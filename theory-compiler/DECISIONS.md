# DECISIONS.md — theory-compiler 轨道设计决策记录

## D1: 解析器技术选型

**决策**: 使用 Python `lark` 库（Earley/LALR 解析器生成器）解析 theory.dsl 和 playbook.dsl。

**理由**:
- lark 支持 EBNF 语法定义，表达力足够覆盖冻结契约的全部句型
- 生成 AST 自然，round-trip 友好
- 纯 Python，无外部二进制依赖
- 保守选择：成熟、文档齐全、无需自己写词法分析

**备选（放弃）**: pyparsing（组合子风格，round-trip 较难）、手写递归下降（工作量大且易出错）

## D2: Lean 4 版本

**决策**: 使用 Lean 4 stable（通过 elan 管理），lake 构建。

**理由**: 标准工具链，与冻结契约中"Lean 的 decide/omega"一致。

## D3: PDDL 语法校验

**决策**: 使用 `pddl` Python 库（pypi: pddl）做语法校验，不调用外部规划器。

**理由**: 工单明确要求"只验证语法合法性"，pddl 库能解析并验证 PDDL 文件结构。

## D4: 素材 B 不变量来源

**决策**: 手工选取经典 1D 孔明棋 5-peg 不可解构型，使用文献已知的 pagoda 权重函数（手算验证后直接填入 DSL 作为字面常量）。

**理由**: 工单明确说明"权重是你自己算出来后填进去的字面常量"，不依赖 engine-rig 的 LP 引擎。选 1D 是因为足够小、可手推、文献有确切答案。

## D5: Python 项目结构

**决策**: 使用标准 `pyproject.toml` + `src/` layout，pytest 做测试。

**理由**: 现代 Python 标准布局，保守选择。

# 汇合 sprint (P-5) — 真 A1

## D-TC-006: 生成器消费 IR，而非 AST 直接进后端

**决策**: 在 parser 与后端之间加一层 `ir.WorldIR` = `TheoryAST` + `ProblemSpec`，
两趟 grounding（值域在 `expand.py`，对象实例在 `ir.py`）都在这里跑完。

**理由**: D-A0-011 报告的缺陷不是"生成器写得不好"，而是生成器**根本没读 AST**。
`gen_lean.generate_lean` 忽略它的 `ast` 参数，直接 BFS 一维孔明棋。修法不是把
world 知识搬进生成器，而是把 world 知识搬出所有生成器：后端只认一套词汇表，
词汇表外的子句抛 `UnsupportedClause`，绝不猜。这是 `fd_adapter` 的规矩——
静默近似一个看不懂的子句，会产出一个与说明书不一致的预测器，下游每一层
都会去认证一个错误的世界。

**代价**: 多一层。换来的是同一份 `gen_python` 同时编译网格世界（A0，三种对象、
传送门、门闩）和线性世界（孔明棋，一种类型四个实例），两者都没有为对方写过一行。

## D-TC-007: Lean 证明有两种形态，由**说明书**挑，不由调用方挑

**决策**: `generate_lean` 依据说明书是否声明 `pagoda(...)` 不变量，产出
`pagoda` 或 `enumerative` 两种发展；`pagoda` 再分 `computational` / `algebraic`
两种证法。

**理由**: 证明策略是说明书的主张的函数，不是调用方的偏好。声明了势函数的世界
应当拿到代数归纳；没声明的世界（A0 有门闩和传送门，没有线性势）应当拿到枚举
证明。让调用方选，等于允许调用方为一个没有势函数的世界要一个势函数证明。

## D-TC-008: 空公理集与线性证明规模不可兼得，原因在 Lean 而不在 pagoda

**实测**（Lean 4.9.0，见 `tests/test_gen_lean.py`）:

| 发展 | `#print axioms` | 证明规模 |
|---|---|---|
| pagoda, `computational` | **空** | `O(2^n)` |
| pagoda, `algebraic` | `propext, Quot.sound` | `O(n)` |
| enumerative | **空** | `O(可达集)` |

代数证明拿不到空公理集，根源不是 pagoda 论证：Lean 4.9 core 里**每一条** `Int`
引理——`Int.add_comm`、`Int.le_trans`、`Int.add_nonpos`——自身都是用 `propext`
证的。任何"讲道理"而非"算出来"的证明都继承它。

**决策**: `computational` 为默认，因为 A1 验收标准写的是依赖假设为空；
`algebraic` 在棋盘大到枚举不动时使用。两者都不发 `native_decide`——它靠跑编译
代码交差，会把 `Lean.ofReduceBool` 记进公理集，而验收看的就是 `#print axioms`。

## D-TC-009: 证书不予采信，重新验算

**决策**: `certificate.load_certificate` 忽略文档自带的 `verified: true`，
从 `weights_integer` 出发重新推导全部三条义务，并且**自己重新枚举move几何**，
再与文档列出的 witness 比对；文档漏列任何一个 move 即报错。

**理由**: 上游 `verify()` 会重算算术，但不检查 witness 表是否完整——删掉几条
witness 的文档照样通过。而漏掉的那一条恰恰可能是势函数上升的那一步。信任那个
标志，等于让一个不成立的权重向量变成 Lean 定理。引擎提议，说明书裁决——裁决
就发生在这里。

## D-TC-010: 说明书的目标宽于证书时，拒绝生成

**决策**: `CertificateGapError`。不静默收窄，不生成一个读起来比实际证明的更强的
`unsolvable`。

**理由**: `lp_potential` 可靠但不完备。5 格棋盘从 `11011` 出发的五个单子目标里，
只有 `01000` 和 `00010` 有线性 pagoda 证书；`10000`/`00100`/`00001` 被 engine-rig
自己的测试钉死为**此方法不可证**。所以说明书的 `count(Peg, alive) = 1` 是一个
本 sprint **未能证明**的命题，这一条写进台账（E-06）而不是绕过去。一个会替引擎
夸大结论的编译器，比一个不会证明的编译器坏得多。

## D-TC-011: E-04 警告，E-03 报错

**决策**: 缺 `semantics:` 是错误；problem 提供了而 manual 未声明的 landmark 是警告。

**理由**: 两者的失败模式不同。缺 `semantics:` 会**静默编译出另一个世界**——这正是
该段落存在的理由。未声明的 landmark 编译出的是同一个世界，代价只是可读性，也就是
E-04 记的那笔账。把后者也做成错误，会拒绝掉每一份在 `landmark` 存在之前写成的
v0.1 说明书，包括 `cold-start-a0/theory/theory.dsl`——那是一份正确的说明书，
现在仍然是。

## D-TC-012: Lean 的 `legal` 是模板，必须对着预测器挣来

**背景**: 独立复核指出 `_derive_moves` 只校验转移的**形状**（去二添一），
不校验**使能条件**。而 Lean 文件里的 `legal s m := s.src && s.over && !s.dst`
是固定文本，没有一个字来自说明书。一个允许跳到已占格的世界会产出同样形状的
转移，然后拿到一份悄悄描述另一个世界的 Lean 文件。

**决策**: `_check_legality`——对预测器能表示的**每一个**占位串、每一个 move，
把预测器的实际行为与 `legal` 的预测逐一比对，不符即拒。

**同时修掉的采样缺口**: 原来只枚举"每个 peg 都活着"的状态，5 格棋盘 32 个占位
串里只检查了 5 个。改为用 `alive=False` 表示少于满员的棋盘后，覆盖 31/32
（第 32 个是五子满盘，本关只有四个实例，表示不出来，正确跳过）。

## D-TC-013: 权重不必在关卡文件里抄一遍

**背景**: 同一次复核指出权重的数据流不是单向的——`theory.dsl` 声明 `weights w`，
`check_against_theory` 就要求 problem JSON 也提供一份，于是引擎的数字要**手抄**
进关卡文件。这正是 A1 想消掉的那道转录工序。

**决策**: 声明了却没提供，降为警告。真正需要数字的后端（`gen_lean`）才坚持
要到，而且证书就能满足它。两处都有时必须一致——过期的副本正是"证明建立在
没人求解过的权重上"的发生方式。

`tests/fixtures/peg5_problem.json` 据此删掉了 `weights` 字段：证书带着数字，
关卡不再复述。

## D-TC-014: candidates_schema 的 v0.2 只做加法，而且要有人来签

**决策**: 新开 `CONTRACTS/candidates_schema_v0.2.md`（草案）与一份**独立**的 v0.2
校验器 `tools/validate_candidates_v02.py`；v0.1 契约文件与 `engine-rig` 那份校验器
一字未动，v0.1 继续是 v0.1 的权威。改动是四类：`engine` 枚举 +2、`kind` 枚举 +2、
`evidence.basis`、`derived_from` 与 `contract` 三个可选字段。

**理由**: M9 的 `deadlock_carver` / `ic3_pdr` 不在六值枚举里，engine-rig 按 D-018
把它们挂在 `fd_adapter` / `lp_potential` 名下出货——那是在冻结契约之内能做的最好
选择，代价是流里 18 行的 `engine` 字段指着两台没跑过的引擎。开枚举是这条压力唯一
的正解。两个新 `kind` 不是为了对称：死锁定理的证明义务是**两条**（模式闭合、
模式-目标互斥），与不变量的三条不同，裁决方按 `kind` 派活会去找三条不存在的义务；
而 `pruning_account` 里根本没有 `actions`，一个遍历 `kind == "plan"` 的消费者在那
一行上拿 `KeyError`。`ic3_pdr` **不发**新 `kind`，因为它的两个产物确实就是
invariant 和 plan——为对称而造词就是本文件在修的那种毛病的镜像。

**为什么是草案而不是定稿**: `engine`/`kind` 的写方是 engine-rig，本轨道只读。
异轨道异步会签：草案先落，PARTNER_SYNC 挂请求，不等待。

## D-TC-015: v0.2 校验器不做 id 唯一性检查

**背景**: 第一稿加了「同一文件内 `id` 不得重复」，理由写的是「append-only，重复
id 是改写过的行顶着旧名字」。一次以 engine-rig 视角做的对抗式复核当场推翻。

**决策**: 删掉，并把理由写进契约，免得下一版再加一次。

**理由**: 三条，任何一条都够。(1) engine-rig 确定性模式下 `id` 是**内容地址**
（`uuid5` over `[engine, kind, payload, evidence]`），重复的 id 恰恰**证明**两行
逐字节相同，而不是改写。(2) append-only 禁止的是删改已写入的行；追加不修改任何行。
(3) `engine-rig/tests/test_integration.py::test_a_second_full_run_only_adds_lines`
把同一次 run 写两遍进同一文件再断言该流合法——那份流在 v0.1 下合法，在 v0.2 下也
必须合法。**一条把既有的、合规的、正在通过的测试判红的「加法」，不是加法。**

同一次复核还抓到第一稿悄悄丢掉了 v0.1 的两条规则（`coverage` 分母为零、空行是
错误），都在一份自称「不改变既有字段含义」的文档里。已恢复，并且加了
`TestAdditive`：两个校验器读同一份语料，凡 v0.1 收的 v0.2 必须收。**「加法」最容易
在实现里悄悄变成「顺手也收紧一点」，所以这条断言要能跑，不能只是写着。**

## D-TC-016: 权重在 IR 里解析一次，不在后端各解析各的

**决策**: `build_ir(ast, problem, certificate=None)`，新增 `_resolve_weights`：
证书填未填的声明；关卡也给了就必须**相等**；一份证书面对两个未填声明时**拒绝**
而不是挑一个。`WorldIR.weight_sources` 记下来源，`gen_markdown` 把数字和出处一起
渲染出来。「关卡副本过期」的检查从 `gen_lean` 搬到这里，因此改抛 `IRError`。

**理由**: D-TC-013 只做了半步——把「关卡必须提供权重」降为警告。剩下半步是数字
**从哪来**：此前只有 `gen_lean` 读证书，另外三个后端只读关卡。后果有两个，都真实
发生过：要么把引擎的向量手抄进入库的关卡文件（A1 想消掉的正是这道工序，而手抄正是
「证明建立在没人重新求解过的权重上」的发生方式），要么 `theory.md` 渲染出一份
**点名了一个它展示不出来的势函数**的说明书。一个源，四种形态看同一份数字，出处
跟着数字走。

**没做的**: 这**不是** E-06。E-06 是 `goal count(Peg, alive) = 1` **证不出来**——
五个单子终局里三个根本没有线性 pagoda 函数。本条清偿的是 E-06 顺带拖着的转录问题，
证明那一半仍然 open，`CertificateGapError` 继续拒绝生成。下一步是 `ic3_pdr` 的证书
导出，而那在 engine-rig 那一侧。

## D-TC-017: 声明了不实现就报错——`gen_pddl` 补上这条守卫

**背景**: 定稿 `dsl_grammar_v0.2` 时按 `semantics:` 提案的收尾段做了一次实测：把
一份说明书改成 `frame reset` + `cascade multi_frame`，过三个生成器。`gen_python`
拒绝（一直有守卫），`gen_lean` 拒绝（它先建预测器，守卫是**继承**来的，自己没有），
`gen_pddl` **照发不误**——它只读 AST，从不建 IR、从不建预测器，所以没有任何东西把
守卫带到它面前。

**决策**: `gen_pddl._check_semantics`，超出支持子集即 `UnsupportedClause`，附负向
测试。

**理由**: 这正是 `semantics:` 段自己要关的那个洞，在低一层重演：说明书把语义事实
写下来了，编译器读了，然后编码了另一个世界。`fd_adapter` 的规矩——支持子集之外是
错误，永远不是静默近似——对编译器同样成立。**声明一件事而没人校验，比不声明更坏，
因为它读起来像已经被检查过了。**

## D-TC-018: 测试必须测所在的那棵树

**决策**: 新增 `theory-compiler/conftest.py`，把本包的 `src/` 插到 `sys.path` 最前。

**理由**: `pyproject.toml` 声明的是可编辑安装，而可编辑安装记的是**绝对路径**。
在第二个检出里（git worktree、clone、别处装过的 CI），`import theory_compiler`
解析到**原来那个目录**，于是整套测试对着工作区里没有的代码跑绿。不是假想：本轮就
这么发生过，一次 149 项全绿之后才发现它对旁边磁盘上的改动一个字都没测。

## D-TC-019: `conflict` 的义务由两条路线清偿，且允许「有条件成立」

**决策**: 新增 `theory_compiler/conflict.py`。义务**按对象**成立——两条守卫相同但
claim 不同对象的规则是级联而不是冲突（A0 的 `press_left`/`door_opens_left` 正是
如此），所以只在 claim 集相交的规则对上要求互斥。两条路线：

1. **守卫分析**（可判定、健全、不完备）：不同动作 / 不同动作参数、谓词与其否定、
   同一格不同颜色、`free(t)` 与非背景色、`free(t)` 与 `t = wall`。此外一律记为
   **未清偿**，绝不记为已证。
2. **穷举扫描**（`certify_conflict`）：拿生成的预测器跑**每一个可表示状态**——不是
   可达状态。可达性是某一个初始格局的性质，`conflict` 是关于 domain 的断言，
   D-TC-012 就是这条教训。

**为什么 `build_ir` 只警告、不报错**: `gen_python` 是**穿过** `build_ir` 造预测器
的，在这里报错等于把穷举路线要用的那台预测器一起否掉。致命判定在上一层
`certify_conflict`，也正是契约原文说的位置（"`certify` must prove it"）。

**允许「有条件成立」，理由**: 扫描可以给出第三种结论——在一个**具名**良构条件下
成立、去掉条件则不成立。这不是打折，因为两半都是机器给的：条件下的干净扫描 +
无条件下的具体反例。它同时是一份缺陷报告，所以必须进台账。

## D-TC-020: E-07——孔明棋说明书没有蕴含它自己声明的 `conflict exclusive`

**发现**: 上条的检查器第一次跑就把七份说明书里的六份判绿、第七份判红。
`jump_right` 是 `forall ?a in Peg forall ?b in Peg` 的模式，守卫只用位置钉住 `?b`
（`?b.pos = ?a.pos + 1`）。接地后 `(?a=Peg_0, ?b=Peg_1)` 与 `(?a=Peg_0, ?b=Peg_3)`
都 claim `Peg_0`，而只要 `Peg_1` 与 `Peg_3` 在同一格上两条就同时触发。

穷举实测：**80,000** 个可表示 (状态,动作) 对里 **600** 次一个对象被 claim 两次；
限制到「没有两枚活棋共格」的 **59,560** 对里 **0** 次。

**决策**: 不改检查器去迁就，不把 `exclusive` 悄悄读弱。记 **E-07**，说明书状态为
**conditional**，条件具名为 `distinct_positions`，见证保留。

**为什么不能修说明书**: 要说出那个条件，守卫里得能对实例做量化（"这一格上没有别的
活着的 `Peg`"），v0.2 的守卫语言没有这个，而契约明文禁止手工扩表达力。不变量语言
也载不动：它到线性算术／计数／奇偶／有限权重为止，「这两个位置不同」一个都不是。

**这条为什么值钱**: 它与 A1 的那个错同形——规则作为 **problem 解**是对的，作为
**domain** 是错的。孔明棋的可达集里两枚棋从不共格，所以这条从来不会在重放里现形；
只有对着全部可表示状态扫，它才出现。**「测不出来」和「不成立」是两件事，而把前者
当成后者，正是这套检查存在的理由。**

## D-TC-021: E-07 用「给说明书一个地方写下它」来清偿，而不是把检查放松

**决策**: `word_table` 的字段加可选修饰符 `unique`（`dsl_grammar_v0.2` 修订记录
第 12 条）。`pos: Int unique` 的意思是「任何两枚**活着的** Peg 永不共格」。孔明棋
说明书据此声明，守卫分析随即把 228 对重叠规则**全部**判绿，条件路线不再被走到。

**为什么不是别的做法**: 三条都想过，都不行。(1) 把 `exclusive` 读弱成「可达态上
成立」——那正是 A1 犯过的错，规则作为 problem 解对、作为 domain 错。(2) 改判
`conflict priority:`——需要对 24 条接地规则给出全序，而这些名字是生成的，写不出来，
而且「谁赢」在这里是假问题：良构态上根本不会两条同时触发。(3) 让检查器**内置**
「同类实例不共格」——不健全：有的世界里两个东西就是可以站在同一格。

`unique` 把它放回**说明书**：这是一条随局变的世界事实（棋子不能叠，走廊里的两个
幽灵可以），语法跨局同一，正好落在 Theoria 1.7 那条边界上。

**`unique` 本身也是义务，不是提示**: `certify_uniqueness` 两条都证——初始态成立，
且 `step` 保持（59,560 条良构转移全扫）。第二条才是要害：一条开局成立、一步之后
就烂掉的性质，会让所有建立在它上面的互斥证明一起作废。**如果只证第一条，这就是
`semantics:` 要关的那个洞在低一层重演。**

**加这个修饰符时抓到两个同形隐患**，都已修：字段正则没有锚定，`pos: Int unique`
被解析成普通的 `pos: Int`，修饰符**静默消失**；漂亮打印器不发 `unique`，于是
parse→print→parse 一圈之后得到一份**不再蕴含自己 `conflict exclusive`** 的说明书，
而且看起来完全正常。现在不认识的字段修饰符是错误，round-trip 测试比字段而不是比
名字。

**条件路线保留。** E-07 对孔明棋清偿，是因为孔明棋现在**说得出**那件事；不是因为
这个问题被判定为不重要。一份需要该条件却不声明的说明书，仍然只拿到具名的有条件
结论加一个反例。

## D-TC-024: 消费死锁证书——接口下移到接地任务，并把说明书装不下 sokoban 记成 E-08

**背景**: C4 要把 `deadlock_carver` 的条件化不可解定理接进生成器。它与前两种证书
形状不同：pagoda 与 ic3 都是「从 `s₀` 能不能到目标」的**全局**命题，这一条是
**条件化**的——不谈 `s₀`，只谈「凡含该模式者皆死」。engine-rig 已发布的 16 条
`conditional_unsolvability` 候选行**全部属于 sokoban**，棋子世界一条没有。

**先做的一件事是勘察，不是动手**: 两个只读 subagent 查 DSL 的表达力边界，结论是
DSL 的**动力学**装得下 sokoban——`free(...)` 就是 `clear`，`toward(o,?d)` 就是
`adj`，push 同时移动箱子与人可以写成两条同守卫、认领对象不相交的规则（契约里
「级联而非冲突」那一条）。装不下的是**目标**：`goal:` 只收一个表达式
（`theory_parser._parse_goal`），`gen_python._goal_body` 只认
`count(Type, f = v) = n` 或单个比较，而 sokoban 的胜利条件是「每个箱子各就各位」，
需要目标合取或者「地标集合」，两者都不存在。附带两处：
`conflict.disjointness_reason` 没有 `free(t)` 对 `X.pos = t` 的判据；
`gen_pddl._extract_pred_pddl` 对不认识的子句**静默丢弃**（D-TC-017 关的那个洞在更
低一层重演）。

**决策**: 不假装说明书能写 sokoban，也不因此把定理放掉。把这条通路的接口下移一层：
死锁证书的世界是**接地 STRIPS 任务**，本轨道自己解析 + 接地一份 PDDL
（`strips.py`，`:strips :typing` 子集，子集外一律报错而不近似），证书只提供**模式**。
说明书装不下 sokoban 这件事记成 **E-08**，写进 STATUS 未清偿。

**为什么转移关系必须自己接地**: 与 ic3 的「没有 `moves` 字段」同一条纪律。闭包只对
某个动作集才谈得上，动作集不能来自断言闭包的同一份文档。**交叉核对是硬的**：本轨道
接地出的地面动作数必须等于证书 `evidence.coverage` 的分母（112），证书点名的每个
被挡动作必须在本轨道的动作集里解析得到且确实删除某个模式原子，本轨道数出的删除动作
一个都不许被漏掉不谈。对不上就抛错——一条在别的任务上证出来的真定理，放到这个任务上
是一条关于错误世界的真定理。

**PDDL 与候选行都是逐字转录的数据，不是 import**: `tests/fixtures/strips/` 两份
PDDL 是**逐字节**拷贝，`PROVENANCE.json` 记着来源与 sha256；两份证书由可执行的
`tools/transcribe_deadlock_certificates.py` 从候选行转录，一项测试每次重跑它并在
漂移时判红。

## D-TC-025: 状态重表示成「一物一格」的元组，良构作为假设进定理而不是被抹掉

**背景**: STRIPS 状态是原子集合，而在任意原子集合上死锁定理是**假的**——没有什么
拦得住一个集合同时含 `at(b1,c12)` 与 `clear(c12)`，从那种态一推就走出了模式。
生产方正是为此要 h² 不动点：从动作集导出哪些原子能共存。

**决策**: 从另一头到达同一处。把状态重新表示成**一物一格的元组**
（`strips_encoding.py`）：player 一格、每个箱子一格，`clear c` 定义成「没有东西站在
`c`」。于是「一格至多放一样东西、一个箱子只在一处」成了**数据的形状**，Lean 不必
再证——与棋子那边把 `St` 定成「每格一个 Bool」是同构的一步。

**这一步要检查，不能假设**: `strips_encoding.verify` 穷举核对 3360 个良构态 ×
112 个地面动作 = 376,320 对：编码的守卫必须与 `pre ⊆ atoms` 逐对一致，编码的效果
必须与 `(atoms \ del) ∪ add` 逐对一致，且每个可达态（3352 个）都必须是良构元组。
这与 `gen_lean._check_legality` 在棋子那条路上做的是同一件事（D-TC-012），
纪律相同，位置相同。

**良构进了定理当假设，因为它是有承重的**: 退化元组（两样东西同格）在原子集合里根本
没有对应物——`clear` 得同时在与不在。实测：把良构丢掉，闭包对
`at(b1,c12) AND at(b2,c13)` 就是**假的**，两个退化态（人站在被推的箱子里）能推出
模式。所以 `wf` 作为假设写进 `dead_closed` / `dead`，而不是被悄悄抹掉；
一项测试盯着那两个反例还在，注释写明「若这天变空了，假设才可以去掉」。

**编码只认一种谓词签名**（`at-player/1`、`at/2`、`clear/1`），别的一律报错而不近似。
猜一个不认识的谓词，得到的就是另一个系统。

## D-TC-026: 只有 `computational` 一种证明形态，分裂预算算出来，超了就拒

**背景**: pagoda 与 ic3 各有 `computational`（空公理集，规模大）与 `algebraic`
（`propext`，规模小）两形态，取舍见 D-TC-008。

**决策**: 这条通路**只有 `computational`**，`algebraic` 显式报错。理由不是偷懒：
代数形态省的是**整数算术**，而这里的分裂是**格**上的，`simp` 除了引进 `propext`
什么也省不下来。给一个更贵又更弱的形态，只会让读者以为有得选。

**分裂宽度是算出来的**: 叶子数 = `格数 ^ 模式未钉住的槽位数 × 地面动作数`。
`at(b1,c12) AND at(b2,c13)` 钉住两个箱子，只剩 player 自由，1792 个叶子，4.2s；
`at(b1,c11)` 只钉一个，player 与 b2 自由，28,672 个叶子，60s——**钉得越多越便宜，
差十六倍**。超 `MAX_LEAN_CASES` 即抛 `DeadlockLeanError`，不发一份编译不动的文件；
这与 `CertificateGapError` 是同一种拒绝。

**`decide` 不吃带自由变量的目标**（Lean 4.9 直接报 "expected type must not contain
free or meta variables"），所以钉住性引理只对模式**读到**的槽位量化，其余槽位填一个
固定格子——填得下正是因为谓词读不到它，两种写法归约到同一个项，调用点靠定义相等
接上。哪些槽位可填由 `_reads` 决定，它一见 `clear` 就回答「全部」。

**超默认心跳预算时在文件头显式抬高，并写明为什么**: 那是墙钟让步，不是证明让步——
每个叶子仍由 `decide` 收尾，公理集仍为空。第一版把 `set_option ... in` 放在文档注释
之后，Lean 直接语法报错；改成文件级。

## D-TC-028: 生成物要被读回来——一次对抗式复核找到的断链

**背景**: 本轮完工后跑了一次对抗式复核（只读，只许证伪）。它没能推翻定理——独立

用变异实验证明了它是真的。

**断链**: `strips_encoding.verify` 检查的是**编码**对**任务**；`recheck` /
`cross_check` 检查的是证书对**编码**。而从这份已检查的编码到**发射出去的 Lean 文本**
之间，还有一步渲染，**没有任何东西在读它**。复核把 `_world` 改了一行，让每条 `push`
的 `applyMove` 分支发 `=> s`（推箱子不动箱子），其余一字不动：`verify` 过、

「箱子永远不动的世界」的漂亮定理。全套非 Lean 测试**一个都没抓到**。唯一偶然抓到它的
是 `level_is_winnable`（那条 11 步通关里恰好有三次推箱），而 `--no-exhibits` 一开，
连它也没了。

**这与 D-A3-007 同形**：绿的、空公理集的、什么也没证的。区别只在于上次是不变式退化成
`true`，这次是转移关系退化成恒等。

**决策**: 加 `gen_lean_deadlock.reread`——**用发射时的文法把发射出去的文本解析回来**，

`Pat`、`Goal`、`s0`。比对是**结构性且精确**的；`wf`/`Pat`/`Goal` 另外在全部 4096 个
可编码态（含退化态，因为发射出的定理正量化在它们上面）上逐态求值比对。
`generate_deadlock_lean` 现在还**拒绝对未经 `verify` 的编码发射**（`verified_stats`
为空即报错），这样「编码对任务」那一环不可能被调用方忘掉。四项变异测试留在
`TestEmissionIsRead` 里，其中第一项就是复核用的那条。

**顺带改掉一句过头的话**: `strips_encoding.verify` 的原文档说它「与
`gen_lean._check_legality` 是同一条纪律：发射出的转移关系不被信任，而是被逐态逐动作
核对」。这对**编码**成立，对**发射**不成立，而 `_check_legality` 恰好是后者的类比
（那边 `legal` 是含义已知的固定模板，拿预测器对它核对确实钉住了发射文本）。已改。

**同一次复核带出的第二条，也是同形的**: 原来的负对照是在**已生成好**的文件里改
`Pat` 的定义体。但 `pat_pins` 的结论与 `closed_pinned` 的钉住字面量里还写着**旧**格子，
所以文件确实变红——**红在这两处不同步上**，而不是红在「新模式可以走出去」上。
更早的一版更糟：替换是对整份源码做的，而同一个格子名在 `legal` 的 112 条分支里出现

**一个因为别的原因变红的负对照，比没有负对照更糟。**

## D-TC-029: `mentions` 取「编译效果」读法，但把那本字典从后端搬到说明书

契约 `CONTRACTS/dsl_grammar_v0.3.md`，被 `a0-spike/THEORIZE_LOG.md` 表达力台账
**X-1** 逼出来。v0.2 用 `mentions` 定义了 `frame persist`，却从未定义 `mentions`；
三种读法互不等价，X-1 用 376 个实测反例把这一点钉死。

**决策**: 取第三种读法（编译效果）的**外延**，但**反转权威方向**。
`writes(r)` = 规则事件在后继态里赋值的对象集合；`o` 被 `r` 提及 iff `o ∈ writes(r)`。
它由 `events:` 声明确定，只有两个来源：`writes { … }` 子句，或 v0.3 公布的默认表。
**两者都没有就报错。** 后端不再是这个集合的**来源**，而是被它**校验**的对象——
`check_backend_agreement` 在 `generate_python` 里逐规则跑。

**为什么不是「R3 照原样」**: X-1 的抱怨不是外延取错了，是
「`frame persist` 只相对于 `gen_exec._compile_effect` 里的一本字典为真，
那本字典不在说明书里，也不在契约里」。答案只能是搬字典，三步缺一不可：
公布它（默认表进契约）、允许说明书覆盖它（`writes` 子句）、**没见过的事件报错**。
第三步是承重的：没有它，前两步只是把猜测挪了个地方。

**这一条是量出来的，不是论出来的。** 在**已经修好签名**的说明书上，
「取第一个参数」这一读法仍然错 376 个转移（`tools/probe_mentions.py`，off-wall 层
39,960 对）。签名修复救的是「签名读法」，救不了「首参读法」；只有定义能救后者。
X-1 的两个请求都是承重的，这就是那个测量。

**`writes` 的成员必须是该事件的参数**——这同时答了 X-1 的第二个请求：
事件若写一个对象，那个对象就得出现在签名里。放宽成自由类型名会让「写了谁」依赖
关卡提供了哪些实例，而 `conflict` 是关于 domain 的断言（D-TC-012）。

**`stayed/1` 写空集**，是默认表里唯一一条不是照抄 `CLAIMED_ARGS` 的。代价照录：
它**收窄**了 `conflict` 义务（A0 上重叠对从 15 降到 1），并且让
「每对象至多一条规则」（契约要求）与「至多一条规则开火」（`gen_exec` 运行时强制、
a0-spike 的探针测量）显式变成两件不同的事。契约只要前者。

**没关掉的一条，写进契约 §9**: `writes` 是中途站。它留下**两份可以互相矛盾的产物**，
再用一条断言去弥合——正是 X-1 所记的那种安排，往上挪了一层。终点是事件**体**
（`event slid(o, p, dir): o.pos := beyond(o, dir); p.pos := ahead(p, dir)`），
写集从体里**导出**，无从漂移。本轮不取，因为它会拒掉本仓库里全部十份说明书的
`events:` 行（对比 `writes` 只拒一份），而为九个遗留事件公布事件体又会把默认表的
隐患原样放大。**v0.3 之后 `frame persist` 有定义了，`step` 仍然没有**：两个后端可以
都满足 `writes {o, p}` 而给出不同的后继。这句话是一次对抗式复核的结论，照录。

## D-TC-030: `free` 在对象自己那一格上——修法、代价，以及代价怎么处理

台账 **X-5**。`_free(state, cell)` 问的是「这一格渲染成背景色吗」，而每个活对象都画在
帧上，于是 `free(Box.pos)` 问的是「箱子那一格里没有箱子吗」，恒假。世界在判断能不能
推之前先测 `is_wall(target)`（`a0-spike/world/sokoban2.py:142-145`），说明书需要
「箱子没站在墙上」这条守卫，写不出来，于是在 52 个态上是错的。

**决策**: `free(c)` 从占用检查里**排除掉所有声明位置在语法上就是 `c` 的对象**。
逐次、按语法：`free(Box.pos)` 排除箱子，`free(ahead(Box, d))` 什么都不排除。
语义排除（「忽略碰巧在那儿的东西」）会让 `free` 对每个被占的格子都为真，把谓词毁掉。

**代价，明说而不是忍着**: `free` 不再对它的参数**指称透明**——`Box.pos` 与
`ahead(Player, d)` 可以指同一格而 `free` 给出不同答案。这不是副作用，修复正是靠它。
三处后果都处理掉，而不是容忍：

* **不交性检查器**。`free(t)` 对 `colored(t, c)` 只有在 `free` 于 `t` 透明时才是证明。
  自排除的出现现在进**独立的键命名空间**，永远不与同一项上的颜色或 `= wall` 对上。
  否则 `free(Cart.pos)` 与 `colored(Cart.pos, 2)`——小车独占该格时两者同真——会被报成
  **已证不交**。本仓库还没有说明书这么写，仍然修：**健全性检查器里的假证明比没有证明更糟。**
* **没有 STRIPS 像**。`gen_pddl` 把 `free` 当**格子的**谓词，逐次排除无法成为格子的性质，
  于是该子句在 PDDL 里恒假、在 Python 里可满足——四形态里的两个会编码出不同的世界。
  后端**拒绝**，这是 v0.2 修订第 10 条的规矩往下挪一层。
* **人类形态**。`gen_markdown` 不得把它渲染成「`Box.pos` is free (unoccupied)」，
  而说的正是箱子站着的那一格。四形态之一允许是散文，不允许是错的。

**它本身修不掉那 52 个**。它让子句**说得出来**，说明书还得去说，并且说完之后规则集
必须仍然是**全的**——把 52 个错答案变成 52 个没答案不叫修复。A0 上的落法：`push2` 加
`free(Box.pos)`，新增 `blocked_box_on_wall` 接住它现在拒掉的那些态，另两条 blocked 规则
也加同一子句。全部 47,040 个可表示对上：0 个不符、0 个无规则开火、从没有两条同时开火。

**顺带清偿的一条**：新增不交性规则「`free(t)` 与 `<inst>.pos = t` 矛盾（该实例恒在帧上）」。
这正是 a0-spike 说明书自己的 `semantics:` 注释所主张的路线一
（*"free(c) 蕴含 c≠Box.pos，这一条就切开了 walk 与 push2"*），而此前无人校验。
有了它，迁移后的说明书**仅凭守卫分析**就清偿 `conflict exclusive`：28 个重叠对，0 个未清偿。
这个对子**只在 `slid` 被读宽时才存在**——按事件名读，`walk` 与 `push2` 不共认领对象，
这一对根本不会被检查。X-1 的「读窄会低估要证的东西」，现在是一条通过的测试。

**一个自己踩的坑，照录**：这条规则第一版用 `if uniq:` 守着，而 `Uniqueness.__bool__`
报的是「有没有字段声明 `unique`」。A0 一个 `unique` 都没有，于是这条规则对**它本来要服务的
那份说明书**被静默关掉，清偿它的代码就在一行之外坐着。是四份说明书兼容验证里的一个
子代理报出「仍有 4 对未清偿」才发现的。改成 `uniq is not None`。

## D-TC-032: 移交包——「四形态」是承诺，不是清单；生成不等于校验

C8 要一个**能交给陌生 agent 的目录**（Theoria 1.11 分层移交，1.8 第三读者）。
`theory_compiler.handover` 造它。三条设计是有争议的，写在这里。

**一包两关，不是一关。** 五个形态里三个是 grounded 的（可执行、Lean、PDDL
problem），只带一关的包会教读者把那一关的家具当成世界律——而这恰是移交题要考的。
带两关，domain/problem 的切口就被**演示**出来：`GLOSSARY.md` 把每个由关卡供给的
名字和它在两关上的值并排印出，标出哪些不同。断言变成证据。

**注释里的越界引用是 citation，不是 blocking。** 两份 A0 说明书的注释一共引用了
十次仓库内的裁决记录（`THEORIZE_LOG` 之类）。包**逐字节照抄**源文件，把这些计入
`SEAL.md`，不删。删了就是在交一份没人发布过的文档。规范文本（规则、律、渲染句）
里的同类引用是 blocking，直接拒绝出包。两者的判别是「匹配点前面这一行有没有 `#`」。

**生成不等于校验，这一条是被读者打出来的。** 第一位新读者把 `manual/DOMAIN.pddl`
判为不可用，而 `MANIFEST.json` 给它记的是 `"status": "generated"`。D-TC-031 已经
记过其中两条（`?dest` 未绑定、`(and (and))` 空效果）；读者还找到第三条：`push-up`
测 `adjacent-above`，而谓词块和 problem 文件写的都是 `adjacent-up`，永不匹配。
**若读者把规划形态当权威，两道最优动作题全错，而分数会记在读者头上。**

所以 `handover.check_pddl` 在把 PDDL 叫作 generated 之前，先用本轨道自己的
`strips.parse_domain` + `strips.ground` 读一遍；读不过就当作**缺口公布**在包的
首页上。它比规划器**拒得更多**（负前条件不在这个子集里），这是有意的取舍：
拒多了，读者少一个形态并且知道；拒少了，读者少一个答案且不知道。
后端本身不在本轮修，D-TC-031 的判断不变。

**副产品：`gen_markdown` 的三处，都是「人类形态说了与说明书相反的话」。**
`GuardPredicate.negated` 没有任何人读——`not free(...)` 渲染成「is free」；
`forall` 变量没有分支，schema 规则印出 `VarRef(name='d')` 的 repr；`jumped` 按
名字（而非名字+元数）分派，于是 `jumped(Cart, portal_exit)` 落进跳棋分支，渲染成
「a peg jumps」——一个没有 peg 的世界里的 peg，且目的地被丢掉。三处已修，
事件表改为按 (名字, 元数) 分派，措辞逐条取自 `gen_python._effect` 编译出的效果。

**事件语义搬进包里，因为说明书里没有。** 说明书声明 `slid(o, p, dir)` 却从不说滑
几格；那个数字住在编译器的事件语汇里。包因此带一页 `PRIMITIVES.md`，逐条写明每个
声明过的事件**做什么**，声明了却没有条目的事件**直接拒绝出包**。DSL 到 v0.3 仍无
语法让说明书说出自己事件的语义——这是表达力台账上的一条，记在这里而不是绕过去。

## D-TC-033: R2-2 是分割算子的洞，不是文法的洞——两处伪装它的编译器缺陷已修

`theoria-arm/GAPS.md` R2-2 把「从不变的格子写不进规则」当作 DSL 表达力缺口报到
本轨道。**量过之后不是。** 同一份说明书，逐字节相同，三个只在**落座哪些实例**上
不同的关卡：给前沿格落一个实例，规则命中，恰好烧对那一格；照臂现在的落座法，
同样的字节一条不发。证据 `runs/20260801T1200Z-R2-2-board-cell-expressivity/
SEATING.json`。所以 `CONTRACTS/dsl_grammar_v0.3.md` 不动，Theoria.md:345 的
「扩一格」条款不触发——台账记的是一条**被驳回**的条目（E-10）。

**真正属于本轨道的是两处缺陷，而它们正是把这件事伪装成文法洞的东西。**

第一处，也是重的那处：`recolored(<landmark>, 1)`。地标是关卡定位的**格子**，
所以「想写一个没有实例的格子」的人第一个就写它。改前它在四形态里的三个**编译
通过**：`edge` 是 `NameRef`，`WriteSets.of_rule` 从不问被写的名字是不是对象；
声明与编译效果都说 `{edge}`，于是 `check_backend_agreement` 也放行；发出的效果
是 `state.edge_color = 1`，而 `State` 是普通 dataclass 且没有这个字段——**赋值
因此成功**，`key()` 不含它，`render` 每次从常量 `BOARD` 重建帧。实测：规则进了
`RULES`，`fired()` 报它命中，`s0.key() == s1.key()`，帧一格没动。

**一条命中且毫无意义、却读起来和能用的规则一模一样。** 这比拒绝严格地更坏：
拒绝会把作者送到修法上，而它把作者送去相信这门语言说不出这句话——R2-2 之所以
报到本轨道，就是这么来的。这是 E-03（沉默的默认）和 X-1（后端偷偷推翻说明书）
的同一失败类，往下一层，发生在 X-1 为防止它而装的那段代码里。

第二处：`gen_markdown` 把 `recolored(leftof(?s), 1)` 渲染成流畅的
「then leftof(?s)'s colour becomes 1」，而 `gen_python` 与 `gen_lean` 对同一份
说明书都直接拒绝。散文形态可以是散文，不可以是**唯一**说这份说明书有意义的形态。
D-TC-032 说「四形态是承诺不是清单」，这是同一句话的又一个实例。

**分三档而不是一档，因为它们不是同一个缺陷戴三顶帽子。** 写地标 = 错误
（说明书自己声明了它是格子，没有任何关卡能救）；写格子项如 `leftof(?p)` = 错误
（位置不是说明书拥有的东西）；写**本关未落座的实例** = 警告。第三档第一版写成
错误，结果删掉了 `a0-cart` 的 `no-button` 关——说明书是 domain，跨关旅行，
`press_left` 写 `Button` 而没有按钮的关卡有权没有按钮，那条规则只是在那里发不了。
它仍然编译成同一条无人读取的赋值，所以照 v0.3 §5 的先例登记为**计数**并钉在
`tests/test_write_targets.py` 里：没人核对的声明，读起来和核对过的一模一样。

**负控制被看见说过「不」**:两处检查同时摘掉,12 条测试红 9 条,活下来的 3 条
恰好是正控制——它们本来就该两边都过。

**没修的,点名**:`gen_pddl` 不走 `build_ir`,因此两处检查都看不到它。它因
`act=key(<int>)` 拒绝整个这类世界(2026-07-31 的修复不在本轮碰),所以目前没有
东西被藏起来;但一份能走到 `gen_pddl` 又写地标的说明书,它仍会照编。

## D-TC-034: 棋盘格不是效果的目标——扩语法这条路可行、可算价，仍然驳回，并把驳回写成契约

**背景**: D-TC-033 把 GAP R2-2 判成分割算子的洞并且判对了，但它按自己的口径
「没发明扩展所以不碰契约」，于是那条边界只以 `ir.py` 的一条 `IRError` 存在。
C15 要的正是这一步：*写下来的拒绝是一条契约，沉默不是*。契约文件是
`CONTRACTS/dsl_grammar_v0.4.md`。

**决策**: 裁决取 (b)——**不扩语法**。§1 把「效果目标必须是对象实例」连同三档
（写地标=错误 / 写格子项=错误 / 写本关未落座的实例=警告）升为规范条文，同时
**明确把守卫排除在这条限制之外**：读任意格子合法，只有写不合法。§2 是驳回本身，
§5 是那条真话该去哪。**没有增删任何产生式**，v0.3 下能编译的说明书在 v0.4 下
照编。

**这一版最该被后人读到的一条：草稿的理由是错的，被推翻了，改了才发。**
草稿论证「(a) 的设计空间是空的——任何能写到从未变过的格子的形式，都退化成由
编译器代替分割算子落座」。一次对抗式复核把它打穿，复核的三条我都自己重跑过：

* **写域等于实例集，在四种形态里都成立——假的。** `gen_pddl` 把颜色流值声明在
  `?c - cell` 上(`gen_pddl.py:260`)，并直接从 `problem.board` 发出颜色事实
  (`:440-443`)——那一层按定义就是从不变的那层。
* **设计空间是空的——假的。** 一个稀疏的、写时才填的棋盘覆盖层被真的搭出来跑了：
  **一个** state 字段（不是每格一个），前沿格烧了，落座的实例一个没加，`key()`
  也变了。证据 `runs/20260802T085557Z-C15-unnameable-cell-verdict/COUNTERDESIGN.txt`。
* **四种形态各自独立作证——夸大了。** `gen_lean` 是 exec 掉 `gen_python` 的输出
  拿到转移关系的(`gen_lean.py:101`)，是依赖方不是第二意见。

**所以驳回改挂在能站住的三条上**：(i) 覆盖层的账不在后端而在语义——v0.3 §1 的
`frame persist` / `conflict` 和目标语言的 `count(<Type>, …)` 全是对对象量化的，
一个覆盖层格子对三者都不可见，要扩就得重开这三条定义；(ii) 全帧责任制
(`Theoria.md:226`，属内环十条约束，`:355` 列为**不动**)要求每个像素要么属棋盘
要么属某对象，被规则写而两边都不属的第三类不被允许，叫它「会变的棋盘」等于
