## Pre-existing PDDL defects (present identically in baseline and current)

### D-1: empty `(and)` effect for every event gen_pddl does not model

`gen_pddl._event_to_pddl` (src/theory_compiler/generators/gen_pddl.py:289) handles
only `moved` and `teleported`. Every other event falls through to
`effects.append("(and)")  # empty effect placeholder` at line 320. So
`jumped(Cart, portal_exit)`, `recolored(Button, 8)` and `vanished(Door)` all compile
to an action that changes nothing, while the Python and Lean forms implement them.
The four co-derived forms therefore encode different worlds.

| manual | actions with `:effect (and (and))` |
|---|---|
| theory | teleport-down press-left door-opens-left  |
| theory_no_button | teleport-down  |
| theory_prime | teleport-down switch-on-up switch-on-down switch-on-left switch-on-right door-opens-up door-opens-down door-opens-left door-opens-right switch-off-up switch-off-down switch-off-left switch-off-right door-shuts-up door-shuts-down door-shuts-left door-shuts-right  |
| theory_prime_seeded | teleport-down switch-on-up switch-on-down switch-on-left switch-on-right door-opens-up door-opens-down door-opens-left door-opens-right switch-off-up switch-off-down switch-off-left switch-off-right door-shuts-up door-shuts-down door-shuts-left door-shuts-right  |

### D-2: unbound `?dest` in push-left / push-right

The a0 manuals guard with `free(leftof(Cart))` / `free(rightof(Cart))`, but
`_extract_pred_pddl` (gen_pddl.py:262) matches only `("above", "below", "left", "right")`
— not `leftof` / `rightof`. Result: no `?dest` parameter is created and neither the
adjacency nor the `free` precondition is emitted, yet `_event_to_pddl`'s `moved` branch
unconditionally emits `(at ?cart ?dest)` and `(not (free ?dest))`. The action is
syntactically malformed (free variable in the effect) and semantically
over-permissive (applicable wherever the cart stands, walls and occupancy ignored).
This is worse than D-1: D-1 under-approximates the effect, D-2 over-approximates
applicability.

| manual | action:unbound-var |
|---|---|
| theory | push-left:?dest push-right:?dest |
| theory_no_button | push-left:?dest push-right:?dest |
| theory_prime | push-left:?dest push-right:?dest |
| theory_prime_seeded | push-left:?dest push-right:?dest push-onto-crate:?dest |

Both defects are byte-identical between baseline and current. Neither is introduced
by v0.3; both are recorded here as evidence, not as regressions.

## Why the X-5 `free(<obj>.pos)` change is inert for this family

No manual in the cold-start-a0 family writes `free(<obj>.pos)` or `free(<Type>)`.
Every `free(...)` occurrence names its cell through a direction function
(`above` / `below` / `leftof` / `rightof`). The current `gen_python` therefore emits
`_free_except` but never calls it (one occurrence per file — the `def` line), and the
current `gen_pddl` never reaches its new `UnsupportedClause` raise. That is exactly
why every guard, effect, PDDL block, Lean table and Markdown rule is unchanged.
