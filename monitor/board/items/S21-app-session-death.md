# S21-app-session-death · App 会话死亡的自动处置

今晚三个常驻研究员（RES-1/2/4）被会话限额打死，六件活（含战役主线 A3）被锁 2 小时无人发现——因为 board.py sweep 按契约只清 W-* 一次性工人，App/常驻会话一律不动（当时的理由是它们的存活从任务表看不出来）。但现在有了更好的判据：**心跳停滞 + urgent 无回应 + 超过两倍循环周期** 三条同时成立即可判定死亡。做三件：(1) sweep 增加 --include-standing 模式，按上述三判据释放常驻会话的认领，并在条目里追加『前任持有者因 X 死亡、可能有半成品在分支上、先查再决定重做还是接续』的提示（我今晚手工做了一次，格式照抄）；(2) 释放动作写进 board.log 与 reflex 事件，让它可见；(3) 补一个负样本：模拟一个心跳新鲜的常驻，断言它的认领**不会**被释放——防止误杀正在长任务里的会话。
