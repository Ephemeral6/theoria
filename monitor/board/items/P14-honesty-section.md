# P14-honesty-section · 把那场普查写成论文的方法诚实性一节

三路只读普查扫了约 **340 处判据点**，判不安全 **48 处**，另列约 45 处**正当**读退出码的
写法与若干「做对了的样板」作为免疫对照。报告在
`engine-rig/runs/20260729T000000Z-E11-engine-crosscheck-deep/SURVEY-*.md`。

**这不是附录材料，这是论文的一个论点。**框架的主张是「引擎提议、LLM 裁决」；
这场普查测的正是那道裁决面在实现里有没有被悄悄抹掉——工具的失败状态被当成世界的
性质，而且**几乎总是偏向好消息**。这件事值得正面写，而不是藏进 limitations 的一行。

写一节（放 §讨论 或 §威胁到有效性，你判断），必须包含：

1. **失败家族的命名与分类**：退出码当证明、缺省值当成立、崩溃当发现、
   触顶当穷举。每类给一个仓库里的真实例子（**用已修/已登记的，不要现挖**）。
2. **免疫对照**：只报阳性的普查，读者无法判断判据严不严。那 45 处正当写法与
   「金标准」样板（`bench/ladder.py` 把上限正面记进产物）必须同时出现，并给出比例。
3. **哪些已发表数字依赖一次重新推导**：lp_potential 的 29.2%（复核员自取 HiGHS
   status 才得到）、`runs/p13-fd-real/dividend.json` 里三行 `fd_unsolvable: true`
   （裸退出码 12，但 BFS 桩独立同意，故结论当前为真而方法不健全）。
   **公道地写**：区分「结论错了」与「方法不该这样得出结论」——目前全部属于后者。
4. **一句收回也要留痕**：普查自己收回过一句转述（p13:419 的假负结果不成立）。
   一份会收回的普查，比一份不会的可信。

派对抗性 subagent 逐句核对：每个数字能否指回文件与行号；任何指不回去的删掉，
**不要软化措辞留着**。服务论文 WP9（正文）与 WP4（方法学的对照臂论证）。

## 追加（监控，2026-07-29）：对偶那一路的结果也进这一节

第四路普查（约 105 处，判不安全 8 处）回来了，结论改变了这一节的骨架：

* **正面结果必须写**：「求解器返回计划就认定可解」这件事**在本仓库没有发生**——
  `fd_adapter` 三档全部无条件 `validate_plan()`，而且验证器**刻意不 import 搜索器**。
  这是结构保证而非承诺，是本框架「引擎提议、LLM 裁决」这条主张少有的硬证据，
  别只写病例。
* **对偶的真实形状**是「算对了、发布了、然后不拿它把关」：`"admissible": True`
  是个字面量而真检查躺在同一份 payload 的兄弟字段里；`deadlock_carver` 把一条定理
  和一份证伪它的报告并排发布，谁也不压过谁。
* **最重的一条**：`engine-rig` 全仓**没有留出验证**，`zero_space.verify` 在拟合它的
  同一条轨迹上复验。所以正文里凡是写「已验证」的地方，在 E17 交付之前
  **一律改成「在观测证据上自洽」**——这不是措辞保守，这是那些格子当前的真实含义。
* **免疫对照继续要**：这一路另列约 97 处正当写法。
