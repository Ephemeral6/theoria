# S32-dual-agent-is-one-agent · 「双代理」这条主张，证据指向单代理

第 1、2 列四个缺口之二，而且它动的是**外壳可信度的核心主张**。

审计（2026-07-29）的证据：`theoria-arm/evidence/model-proxy-401.jsonl` 131 条记录里
**65 条 model_call 全是 401**；`theoria-arm/harness/modelcall.py:11-33` 自己记录了
模型代理被绕过的过程——剥掉 CLI 的 OAuth 头、注入一个不存在的 `ANTHROPIC_API_KEY`、
上游全 401。也就是说**模型代理零真实流量**，而论文按「双代理」在写。

**本件是查证与定性，不是修代码**（`theoria-arm/` 正被 A3 占着）。
产物落在 `verify-lab/`，结论供 RES-2 直接引用。

做四件：

1. **把两个代理各自的实际流量数出来**：环境代理（`proxy/`）处理过多少次真实
   请求、模型代理处理过多少次。**给出分母**——「65 条 401」要对着总数才有意义。
2. **判定这条主张现在能说到什么程度**。三种可能的诚实写法，选一种并给证据：
   (a) 双代理已建成并都在真实流量上验证过；
   (b) 环境代理已验证，模型代理**已建成但未在真实流量上验证**；
   (c) 模型代理的设计存在但当前链路不通。
   **我预期是 (b) 或 (c)，但结论以你查到的为准**——如果证据支持 (a)，
   那说明审计错了，那更值得写下来。
3. **把这条写成论文可以直接用的两三句话**，交给 RES-2，并在 inbox 报一句。
   句子里必须出现分母。
4. **给出「让它变成 (a) 需要什么」的最小清单**——那是下一件工单的输入。

**硬红线**：查证过程不许把任何真实凭据写进任何文件；模型代理那段涉及
`ANTHROPIC_API_KEY` 的记录，**只报形状与计数，不报值**。
零 API 计费、零封存堆接触。服务论文 WP2。
