# V21-leakage-gate-token-level · 泄漏闸门是「通过」，不是「有效」

审计（2026-07-29）逐行确认的结构性缺陷：

* `exam/leakage.py:257` 按 `canonical(value)` **整值分桶**；
* `:267` **丢弃单例桶**。

于是**一个唯一的 `level:` token 就让每个桶变成单例**，`tags: dead` 那一类泄漏
**结构上不可见**——全文没有任何 token 级检查。`exam/STATUS.md` 第 13 条弱点自己写着
三份 P-15 卷子仍未被审。

**这一格的性质要说清楚**：闸门跑了、绿了、被当成证据用了，而它抓不到它声称要抓的那类东西。
这与今晚普查的主模式同形——判据算出来了，但量的不是它自称在量的东西。

做四件：

1. **加 token 级检查**：把答案与题面都切成 token，按 token 共现算泄漏，
   整值分桶保留为第二道而不是唯一一道。
2. **单例桶不许直接丢**：单例意味着「这一项独一无二」，那既可能是无泄漏，
   也可能是**泄漏得太彻底以至于只有它自己**。分开处理并各自报数。
3. **负样本，两条**：造一份带 `tags: dead` 式泄漏的卷子，断言闸门**必须变红**；
   再造一份干净的，断言仍然绿（别把保守修成一律拒绝）。
4. **重审那三份 P-15 卷子**并把结论写进 `exam/STATUS.md`——
   弱点清单里挂着的未审项，是这一格现在最贵的一笔债。

服务论文 WP5 与 WP7。零 API、零封存堆接触。
