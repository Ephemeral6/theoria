# V14-standing-negative-control-probe · 把负控普查变成常设探针：新闸门必须自带能被演示为红的证明

V11 清点了 127 道验收入口，35 道没有任何可执行的负控、13 道退出码撒谎。**清点是一次性的，而缺陷是持续产生的**——今天补完，下周新写的闸门照样没有负控，因为没有任何东西要求它有。

做一件事：**把那份普查变成一个会红的探针**，放在 verify-lab/，任何人都能跑。

设计要点（先想清楚再写，这条最容易做成一个没人跑的玩具）：
1. **判据必须机械可算**。「有没有负控」在普查里是人判断的。要落成代码，得先找一个可判定的代理判据。候选：某个入口的测试文件里，存不存在一个用例**构造坏输入并断言非零退出/断言失败**。这个判据一定有假阳假阴——**先在 V11 那 127 行上标定它**（普查员的人工判断是金标准），把混淆矩阵报出来。**假阳率高到没人愿意看的探针，等于没有探针**（figures/verify.sh 第 7 关的第一版正则就死在这上面，它的第一个发现是 docstring 里的一句话）。
2. **只对新增/变更负责，不要一上来就要求 127 行全绿**。存量 35 个缺口是别人领地的活，探针要能区分「这是已登记的存量缺口」与「这是新长出来的」——照抄 V12 刚做的 KNOWN_MISS.json 形状：手写清单逐条记下存量、写明 owner，任何**偏离**才红。
3. **探针自己要有负控**（不然就是同一个病的第 128 例）：构造一个假的「新增了没有负控的闸门」的树，断言探针必须红；再构造一个「补上了负控」的树，断言必须绿。
4. **不要改任何别人的领地**。探针只读别人的树、只写 verify-lab/。

产出：verify-lab/ 下的探针 + 标定报告（混淆矩阵）+ 存量清单 + 探针自己的负控测试；一份写给监控的建议：这个探针**该不该**进 CI/合并闸，以及**如果假阳率不够低就明说不该进**——一个逼着人加豁免注释的闸门，最后会被整体关掉。

交付前另派对抗性 subagent：专打判据的假阳假阴，让它去构造「明明有负控却被判无」和「明明没有却被判有」的真实例子（仓库里现成的最好）。

零 API、零网络、封存堆零接触，纯 token。留痕 verify-lab/runs/<UTC>-V14-standing-negative-control-probe/。
