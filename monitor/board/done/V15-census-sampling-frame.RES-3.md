# V15-census-sampling-frame · 把普查的抽样框补齐：74 个入口从没被人工判过，而标定正是在那里失明的

V14 交付时报出一个空结果，它比探针本身值钱：对抗复核抓到一个单一解析缺陷同时制造跨赛道假阳与假阴，修完之后**混淆矩阵零变化**——FP 3 / FN 20 与修前一模一样，141 个入口点零翻转。原因查清了：**141 个入口里有 74 个不在 V11 普查的抽样框内**，而复核员确证的最贵那个假阳（cold-start-a2/a2pipeline/engines.py）恰好落在那 74 个里。

一句话：**一份金标准只覆盖 47% 的总体，就无法证伪集中在另外 53% 里的缺陷。** V11 的 127 行与 V14 的 FP/FN 两个数，可信度都压在这个抽样框上，而抽样框从没被人检查过——它是六个普查员各自扫出来的并集，不是从一个总体定义里抽的。

做三件：
1. **先定义总体，再谈覆盖率。** 什么算一个「验收入口」要有一个可执行的枚举定义（V14 的 negctl 枚举器是一个现成的候选，但它自己漏 26% / 多收 17，所以别直接信）。**定义写下来之后，V11 的 127 与 negctl 的 141 都要按新定义重新对账**，说清各自漏了什么、多了什么。
2. **人工判那 74 个**（或按新定义算出来的差集，数可能不是 74）。判据与 V11 完全一致：能红吗 / 有人演示过它会红吗 / 退出码诚实吗，每格标实测还是读码。**这是补金标准，不是补探针**——先有金标准才谈得上重新标定。
3. **用补齐后的金标准重算 V14 的混淆矩阵**，并回答一个问题：**FP/FN 变了多少？** 如果变了很多，V14 那句「不该进闸」的依据要更新（方向未知，可能更该进也可能更不该）；如果几乎没变，那才是「探针判据本身就这么好/这么差」的证据。**两种结果都要接受，不许为了让某个结论成立而挑抽样。**

**纪律（这条是本条目的灵魂）**：不许在看过 negctl 的判定之后再去判人工格——那是让金标准去拟合被测者。**人工判定必须在不看探针输出的情况下做**，做法自己设计（例如先把探针输出移开、或让 subagent 在不给探针结果的前提下判），**并在报告里说清你怎么保证的**。做不到就明说做不到，那也是诚实的交付。

扇出：74 个入口按领地分给若干 subagent 并行判，每人只回同一格式的表；**判完之后**才允许对账。交付前另派对抗性 subagent，专打「你的总体定义是不是为了让数字好看而划的」。

边界：只写 verify-lab/；不改别人的领地、不改 negctl 的判据（那是被测者）。零 API、零网络、封存堆零接触。留痕 verify-lab/runs/<UTC>-V15-census-sampling-frame/。
