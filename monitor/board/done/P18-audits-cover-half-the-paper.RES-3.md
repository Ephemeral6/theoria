# P18-audits-cover-half-the-paper · 两份审计各钉在半篇上，而正文早已长过它们

审计（2026-07-29）核出：引文核查 CITECHECK 钉在 **1319 行 / sha 4208b69c**，
评审 REVIEW 钉在 **75,885 字节**，而当前正文是 **2572 行 / 157,782 字节**。
**两份审计都只覆盖了现在这篇的一半。**

这不是「审计过期」这么轻——它意味着**后一半从来没有被任何人审过**，
而页面与工作板上它是「已审」。同一个形状：一次做过的检查，被当成对当前对象的检查。

做四件：

1. **重跑两份审计，覆盖全文**，并在报告头写明它审的是哪个 sha / 多少行 / 多少字节。
   **把这三项写进产物本身**，下次谁都能一眼看出它是否已经过期。
2. **逐条对比新旧结论**：旧审计的问题修了没有？新的一半引入了什么新问题？
   **旧报告不许覆盖，两份并排留着**——收回与修正本身也是证据。
3. **优先处理五处 kill shot**（`review-d-adversarial.md` 对 v0.3 给的是 Reject）：
   副标题在卖 transfer 与考卷，而 §10.5（`PAPER.md:2324-2325`）自己声明二者
   「未被证据支持、不作主张」；`00_abstract.md:61` 仍写 "Eight results."
   与同一份摘要里的诚实限定并存。**一份自相矛盾的摘要比一份保守的更伤可信度。**
4. **加一道机器闸门**：审计报告里记下的 sha / 行数与当前正文不符时，
   `papers/verify.py` 必须变红。没有这道闸门，同一件事三个月后会再发生一次。
