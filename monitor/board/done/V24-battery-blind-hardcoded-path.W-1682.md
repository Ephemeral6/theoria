# V24-battery-blind-hardcoded-path · 致盲步骤指向一棵随时会被清掉的工作树

清理审计（2026-07-29）里唯一一处**两个扫仓判决相反**的地方，值得单列：
一个判 `.worktrees/v9-battery-gaming-audit` 干净且已合并、可删；
另一个发现 `battery/audit/v9/make_blind.py:16` **硬编码了它的绝对路径**：

```python
SRC = r"C:\Users\...\v9-battery-gaming-audit"
```

那是 V9 博弈审计的**致盲步骤**——即整个抗游戏审计的可信度所系的那一步。
所以这棵工作树现在既是「可删的」又是「不可删的」，取决于谁在看。

做三件：

1. **把 `SRC` 指到一个 git ref**（分支名或提交 sha），不是一个本机绝对路径。
   路径解析失败要**大声报错**，不许静默回落到某个默认目录——
   一个悄悄致盲失败的审计，比没有审计更坏，因为它照样出结论。
2. **重跑一次致盲流程**并确认产物与既有结论一致；不一致就以重跑为准并说明差异。
3. 顺手查 `battery/` 与 `exam/` 下还有没有别的硬编码绝对路径
   （`grep -rn "C:\\\\Users"`）。这台机器的路径进了代码，就等于这份实验只能在
   这台机器上复现——而复现性是本仓的硬要求。

做完之后在 inbox 里说一句「v9 那棵工作树现在可以删了」，S30 的清理才动它。
服务论文 WP5。零 API、零封存堆接触。
