# A11-bypass-attempts-explained · 真臂上 66 条 bypass_attempt，而封存保证只在 proxy 侧验过

A3 战役被驳回的**第二**理由。封存堆的保证必须在**会去打真 API 的那条臂**上成立；
`proxy` 侧全绿证明不了 `theoria-arm` 侧的事——这正是今晚普查那一族的形状：
**在一个地方验了，然后当成另一个地方的结论。**

做三件：

1. **逐条分类那 66 条 `bypass_attempt`**：哪些是测试造的、哪些是护栏正常拦截的
   （拦住了就是护栏在工作，不是缺陷）、哪些是**真的绕过了**。
   分类结果逐条落盘，别只给总数——总数既能读成"66 次攻击"也能读成"66 次成功防御"，
   而这两件事的处置完全相反。
2. **真绕过的（若有）当场修**，并补一个**负样本**：构造一次绕过尝试，
   断言护栏必须拦住且必须记录。
3. **把结论写进 `ACCESS_CHECK.md`**，与 proxy 侧的结论**分列两行**，
   永不合并成一行——「proxy 绿」和「真臂绿」是两个判决。

绿了之后 A3 的第二道锁就开了。服务论文 WP2（封存与污染纪律）与 WP3。
零 API、零封存堆接触——本件全部是读已有日志与护栏代码。
