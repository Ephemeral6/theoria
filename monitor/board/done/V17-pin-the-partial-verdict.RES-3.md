# V17-pin-the-partial-verdict · 把「部分」那一格的判据写死：九个判定员用得最不一致的就是它

V15 交付时自己点了下一步，我同意并下发：**17 个新增 pinned FN 里有 10 个是「部分」**，而「部分」正是九个判定员用得最不一致的那一格。**继续扩样本的边际收益已经低于把这一格的判据写死。**

为什么这条比再扩样本值：V15 的敏感性分析证明了总体定义不是为好看划的（12 个变体、总体 84↔260、pinned 矩阵纹丝不动）。**但那证明的是「线划在哪不影响结论」，没有证明「同一条线上不同的人会判成一样」。** 后者是判定员间信度（inter-rater reliability），本轮从没测过，而它直接决定金标准值多少钱。

三件：
1. **量出现状**：拿 V11 的 127 行 + V15 的 126 行，找出有多个判定员判过的重叠行（V15 的 partials 里应该有），算**判定员间一致率**，「部分」这一格单列。**没有重叠行就明说没有**，那本身是一个发现——意味着整份金标准从来没有过信度证据。**如果是这样，第 2 件就要先造重叠。**
2. **把判据写死**：什么时候算「部分」而不是「是」/「否」。要给**可判定的规则 + 至少三个正例三个反例**（从现有 253 行里挑真实的，不要编）。**规则要能被一个没参与过前两轮的人照着复判。**
3. **重判 + 量改善**：让**没看过原判定**的 subagent 按新判据重判那些「部分」行，报**改判率**与**新的判定员间一致率**。改善不明显就照实说——**一条写下来但没提高一致率的判据，等于没写。**

**盲判纪律（V15 踩过的坑，我的责任，别重蹈）**：判定员的树必须先 git rm 掉 PARTNER_SYNC.md 与 monitor/inbox/，或者从 orphan checkout 起。V15 实测泄漏 29/126、曝光组 present 率 0.55 对 0.34（p=0.055），泄漏面就是我每次交付追加的那些段落。**这一件的 BLINDING 记录要写明你怎么挡的，以及哪些没挡住。**

**不要做的**：不要改 negctl 的判据（它是被测者）；不要为了让一致率好看而把「部分」定义成一个几乎没人会选的窄格——**那是把分歧藏起来不是解决分歧**，对抗复核会专打这一点。

交付前另派对抗性 subagent，专打两条：(a) 新判据是不是把分歧藏进了别的格；(b) 一致率的改善是不是来自重判者看过了新判据因而互相趋同（那是判据的效果，也可能是趋同压力，要能分开说）。

边界：只写 verify-lab/；零 API、零网络、封存堆零接触。留痕 verify-lab/runs/<UTC>-V17-pin-the-partial-verdict/。
