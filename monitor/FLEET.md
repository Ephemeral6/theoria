# 舰队：一页地图

2026-07-29 重整。写这一页的直接原因是用户的一句话——「这个体系有点乱」——
而它乱得有具体形状：**一个身份有两条启动路径，一件事有三个通讯面，
一个「他还活着吗」有三个互相矛盾的判据。** 下面是收敛后的样子。

## 一、谁在干活

| 角色 | 编号 | 赛道 | 怎么启动 |
|---|---|---|---|
| 常驻研究员 | RES-1 | campaign 战役 | **只有无头一条路**：`standing.py` 循环任务自动起 |
| | RES-2 | paper 论文 | 同上 |
| | RES-3 | verify 验证 | 同上 |
| | RES-4 | infra 基建 | 同上 |
| 通用工人 | W-\<n\> | 无赛道 | `dispatch.via_task('W-<n>', 'W-worker.md')`，一次性 |
| 监控 | —— | —— | 就是我；只裁决与供货，不执行 |

**Claude App 里的会话不再是舰队的一部分。** 这是本次重整最重要的一条，理由是实测的：
App 会话对计划任务表**不可见**，于是 2026-07-29 我把一个安静但活着的 App RES-4
判成已死、另起了一个无头 RES-4——**同一个编号两个会话，同一件 S29 被独立做了两遍，
产出两条互相冲突的分支**，而这已是同号并发的第三次。
App 那条路没有提供无头做不到的能力（今天的 99 件交付里，RES-3 与 RES-4 在无头下
交了 46 件），它只提供了一个观测不到的第二入口。

用户当然可以继续在 App 里开 Claude Code 自己用——**只是别再用 RES-1..4 这四个编号**。

## 二、他还活着吗：一个判据

**问工作板。** `board.log` 里一行 `CLAIM` / `DONE` 只可能由一个活着的会话写出来——
它是这个编号对共享状态造成的**后果**，不是它对自己的**自述**。

被降级为参考、不再单独作判据的三个：

* `ops-status/<id>.json` 的 `utc` —— agent 自报的时刻，实测全线漂前；
* 该文件的 **mtime** —— 一次 `git merge` / `reset` 就能把死会话摸新，今天发生过；
* `cycle` —— 单调且伪造不了，但「比我上次记的新」不等于「刚刚才写」。

计划任务表（`schtasks`）在 App 路退休后是**权威**的：无头是唯一入口，
任务在跑就是在跑。上面那三个连同 `.lock` 一起保留为过渡期的第二意见。

## 三、说话：一个通道

**`monitor/bus/`**，`bus.py` 是唯一入口。它有游标（既是送达回执也是已读位置）、
有 `urgent` 哨兵文件做中断、有 `ACK_REQUIRED` 协议。

* `monitor/mailbox/` —— **停止写入**（历史保留）。它与 bus 完全重叠，
  而且分裂了舰队：App 跑的研究员写 mailbox，无头的写 bus，两边看不见对方。
* `monitor/inbox/` —— **保留，方向不同**：agent → 监控的**提案**（一事一文件），
  监控每跳裁决后移进 `inbox/archive/`。它不是对话，是待审数据。

## 四、领活：一块板

`monitor/board/`，`board.py` 是唯一入口。`items/` → `claimed/` → `done/`，
用 `os.rename` 原子认领。四条守卫，每条都有它被写下来的理由：

1. **领地互斥** —— 一块地同时只有一个人写；
2. **赛道预留** —— 通用工人不许抽干某个常驻研究员的队列，**但主人停摆超
   `STALE_MIN` 就解封**（守卫护的是活人的队列，不是死人的）；
3. **花钱守卫** —— `spend: api` 的条目要监控显式写 `generic_ok: yes` 才下放，
   且 `--lane` 自报身份不再能绕过它；
4. **持有上限** —— 常驻研究员同时最多 `HOLD_CAP` 件。

## 五、自动跳动的三个心跳

| 任务 | 周期 | 干什么 |
|---|---|---|
| `TheoriaStanding` | 15 分钟 | 四个常驻研究员该起的起来（`standing.py`） |
| `TheoriaReflex` | 5 分钟 | 清孤儿认领、查配额、补通用工人、跑合并队列 |
| `TheoriaDashboard` | 10 分钟 | 重算 `state.json`，页面在 `:8787` |

**它们挂在系统上，不挂在任何会话上**——包括不挂在我身上。
一个靠我活着的复活机制，会和它要救的东西一起死。

## 六、这套东西的通病，写在最前面给下一个人

2026-07-29 一次 57 个 agent 的对抗性普查留下 28 条缺陷，它们是同一件事的 28 种写法：

> **这个代码库没有第三个值。**「测不到」和「测了，没问题」编码成同一个字面量，
> 而每一处默认值都指向健康答案——计数器默认 0，布尔默认 True，集合默认空，
> 异常处理默认 `pass`。

第二层规律更要紧：**出问题最多的是补丁本身**。修复消除了症状，
同时让问题看上去已被处理。

所以本仓的两条硬规矩：

* **判据来自默认值、空集合或 `except` 分支的地方，换成一个不可能被误读为健康的
  哨兵**（`-1` / `None` / 直接抛）；
* **每一道闸门都要有一个阴性样本**——一个能让它变红的输入。
  20 道闸门里 19 道从没被证明能变红，那 19 道目前只是装饰。
