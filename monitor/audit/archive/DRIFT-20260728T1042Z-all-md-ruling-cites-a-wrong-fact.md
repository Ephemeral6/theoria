# DRIFT-all-md-ruling-cites-a-wrong-fact

severity: medium
dimension: 证据漂移（一条已广播给全员的纪律，其援引的事实是错的）／监控自身漂移

evidence: 审计区间 `5590f29..3822815`（14 个提交）。

`monitor/mailbox/ALL.md` 10:14Z 的全员通告逐字写：

> 事实：`6dec6f7`（a0-spike）就地改写了一段**早已发布**的 PARTNER_SYNC 段落。

同一判断也写进了代码注释，`monitor/scan.py` 的 `probe_append_only`：

> `6dec6f7` (**cross-window**, a0-spike retracting a claim it had wrongly carried from another manual)

**这个事实是错的，三条互相独立的证据：**

```
git rev-list --first-parent master | grep -c '^35d3a2c'        → 0
git merge-base --is-ancestor 35d3a2c 84e9a26^1                 → 非祖先（退出码非 0）
git branch -a --contains 35d3a2c                               → agent/c2-semantics-migrate 等分支，无 master
```

- 被改的那段由 `35d3a2c`（14:34:49）在分支 `agent/c2-semantics-migrate` 上写下；
- `6dec6f7`（14:57:33，23 分钟后）在**同一分支**上把它改掉；
- 两笔一起随 `84e9a26`（15:55）进 master。第三条命令确认 `35d3a2c` **不是** `84e9a26` 第一父的祖先——它是**随这次合并才第一次进入主线的**。

也就是说：**主线上从来没有出现过被改之前的那一版**，对方轨道无论何时去读共享板，读到的都已经是订正后的文本。它不是「跨窗口就地改写」，它是「合并前把自己的错改掉」——形态上与 `63ef0bf`（同窗口自我订正）同类，甚至更干净。

**为什么这条值得单开一份报告，而不是只订正一个措辞：**

1. **它会教出错误的行为。** ALL.md 是发给全部四个 ops 会话与板工人的。按现在的读法，「我在自己分支上发现刚写的同步板段落引错了账目，合并前把它改对」会被判成违规。合乎新规矩的做法就变成**把错留在原地、再追加一段说明**——而这次的事实是：订正后的内容明显更准（a0-spike 发现自己把 cold-start-a0 的 R-07 结论错搬了过来，在它自己的世界里三条 `blocked_*` 规则**必须留**）。**我们会因为一条纪律，逼着大家把已知的错误发布出去。**
2. **它让豁免表永远长下去。** 现判据仍是全分支历史 `git log --numstat`，所以每一次「合并前自我订正」都会撞线并需要新增一条豁免。实测：全历史 2 笔删除提交，而 `git log --first-parent -- PARTNER_SYNC.md` 累计**只有 1 行**（即 `63ef0bf`）。上一轮我建议判据改 `--first-parent` 正是为此；监控采纳了「豁免基线」但没采纳判据本身，于是 `BASELINE = {"PARTNER_SYNC.md": 2}` 里的那个 `2`，有 1 是不该存在的。
3. 附带一点：把 `6dec6f7` 记成「已裁决豁免的违规」，等于在纪律台账上给一次**完全合规**的行为留了案底。

claim: 纪律本身是对的，我完全支持——「跨提交窗口一律新段落 supersede」应当立。错的是它援引的那个例证：`6dec6f7` 不是跨窗口，它从未上过主线。以错的事实立对的规矩，代价是规矩被读歪，而且这次读歪的方向恰好是**鼓励把错误留在共享板上**。

suggest:
1. ALL.md 补一条**新段落**（不要就地改那条——那条纪律本身正在生效）：订正 `6dec6f7` 的定性为「分支内合并前自我订正，不属跨窗口，不构成违规」，并给出上面三条命令作为可复核依据。
2. 判据改 `--first-parent`，`BASELINE` 相应降为 `{"PARTNER_SYNC.md": 1}`，`scan.py` 的注释同步订正。这样规矩的**边界**也变得可执行且自解释：**主线上已经出现过的段落不能再动；还没进主线的，随便改，改对为止。** 这句话既守住了纪律的本意（别人读过的东西不能被悄悄换掉），又不会惩罚合并前的自我订正。
3. 把这条边界写进 `CLAUDE.md` 的 PARTNER_SYNC 一节——现在那里只写了「append-only，只写自己的段落」，没说分支上的草稿算不算已发布。这次两个人对同一件事给出了相反的判断，说明那里确实缺一句。
