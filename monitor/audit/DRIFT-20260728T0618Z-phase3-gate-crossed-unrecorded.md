# DRIFT-phase3-gate-crossed-unrecorded

severity: medium
dimension: 基准漂移（`Theoria.md` 写明的阶段门被跨过，且跨门这件事没有被当作决定记录下来）

evidence:

- 基准文件原文，`Theoria.md:305` 句末：「……切堆清单已提交哈希。**全绿才准烧游戏钱(Phase 3 的门)**；Phase 2 只依赖其中『账本同格式』与『切堆已提交』两项，可与 A1/A2 并行。」
  ——门是**逐字**的，且例外条款只给了 Phase 2，没给 Phase 3。
- 监控自己的盘面同样写着这条门：`monitor/spec.py` 的 `p1` 段 `"gate": "全绿才准烧游戏钱"`，`p3` 段 `"gate": "Phase 1 全绿才准进"`。
- 但 Phase 1 不是全绿：`monitor/state.json` 的 `p1._counts` = `green 6 / partial 8 / risk 2`（16 项里 6 项绿）。
- 而 Phase 3 的条目已经在烧游戏钱：`p3-envelope`（「对照两臂在开发堆各跑 2–3 局，方差包络冻结」，clause 自标 `Phase 3 · 经济`）已实跑 `ar25×haiku×3`，$2.53，被预算闸门 G4 拦停在 1/4 局；`baseline-arms/STATUS.md:12` 记「M5 方差包络战役 ⚠️ 闸门红，停在 1/4 局」。
- 更关键的一步：F-15 的裁决（`monitor/state.json`）是「其余 3 局（g50t/sk48/tn36）**按原协议续跑**」——监控在 Phase 1 未绿的情况下**主动指派了更多 Phase 3 的游戏开销**。
- 全仓检索未见任何把这次跨门登记为例外的记录：`incidents.jsonl` 无对应条目，F-15 通篇讨论的是 ar25 是否劣化，一句没提门。

claim: 门被跨过了，而且是监控自己指派着跨的——但没有任何一处把「我们决定提前跨这道门」当作一个决定写下来。需要说清楚的是：**我不认为该退回去**。基准文件 `Theoria.md:368` 自己要求「每格重复数 ⟨n⟩ **由开发堆方差在冻结前定**」，方差包络因此是 Phase 4 冻结的必需输入，早做有正当理由，$2.53 的代价也谈不上烧钱。问题**只在没写下来**：一条没有边界、没有理由、没有署名的例外，下一次会被援引成任意 Phase 3 开销的先例，而那时候没人能指出它当初的适用范围有多窄。这个仓库已经为「结论说得比证据满」栽过两次（INC-002 初判、P-5 复核订正）；这一次是反过来的同一个病——**做得比记下来的多**。

suggest:
1. 把这次跨门补成一条显式例外并给它边界。建议的口径：**Phase 3 中「为冻结提供输入」的测量类条目（方差包络）可在 Phase 1 未全绿时执行，上限 ⟨预算⟩、限开发堆、逐局入账；Phase 3 的主体（迭代战役 `p3-campaign`）仍严格锁在门后。** 落到 `Theoria.md:305` 那句的括号里，或落成一条 incident/决定——由基准文件的作者裁，不由我，也不宜由监控单方面代行。
2. 顺手把门做成机器可见的：`spec.py` 的 `gate` 字段目前只是一句展示文本，没有任何检查在读它。建议加一个 `probe_gates`——「p1 未全绿时，p3/p4 下有 `status != missing` 的条目」即报 note 并列出是哪几条，让跨门这件事在盘面上一直可见，而不是靠一小时一次的人眼巡检。
3. 与此同时值得记一笔的对照：本轮增量里 `theoria-arm` 的首次在线接触（g50t）**不属于**这次跨门——它对应 `p1-same-shell`，是 Phase 1 验收单里明写要花的钱（「三臂经双代理落同一账本」），花得合规。这条写进报告是为了让例外的边界从一开始就清楚：不是所有在线开销都需要例外，只有 Phase 3 名下的那些需要。
