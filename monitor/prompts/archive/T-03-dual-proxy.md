# T-03 · 双代理：环境代理 + 模型代理（Phase 1 的记录面）

你在 Theoria 仓库。先读 `CLAUDE.md` 与 `Theoria.md` Phase 1「自下而上五层」
(1)(3)(4) 三层的原文 —— 这个工单就是把那三段落成代码。再读
`arc-recon/README.md`（它明确说自己**不是**这个代理）和
`baseline-arms/harness/`（已有的客户端与账本雏形，能复用就复用）。

## 背景

「封闭系统」三条定义 —— 记录完备、可复放、不可绕行 —— 目前一条都没有物理
载体。密封靠自觉；约束 8（无意外则无模型调用）没有任何东西在度量它；
C2「账单形状」是论文的签名证据，而仪表不存在。

## 任务

新建顶层目录 `proxy/`（共同地面，同 arc-recon 的地位）：

1. **环境代理**：本地 HTTP 代理，臂把 ARC base URL 指向它。
   - `ARC_API_KEY` 只在代理内注入（从根 `.env` 读）；臂的进程环境里没有密钥。
   - 请求与响应全量入账（JSONL，一行一次调用；密钥字段 `<redacted>`）。
   - **封存堆护栏在代理层强制**：请求体 game_id 命中封存 21 局立即拒绝 + 记
     incident —— 密封由构造成立，不靠自觉。piles.json 是护栏的数据源。
   - game_id 版本后缀入 run.json 作为环境版本指纹。
2. **模型代理**：同一招再用一次 —— Anthropic API 流量过代理（Claude Code 支持
   base URL 重定向），provider 原始 usage 逐字入账。价目表另存版本化文件，
   成本是换算不是记录。
3. **账本**：两类事件 `env_step`（全帧、动作、关卡边界）与 `model_call`。
   格式三臂共用 —— 这是 Phase 2 电池的输入格式，定了就要冻，先写
   `proxy/LEDGER_FORMAT.md` 再写代码。
4. **密封测试**（Phase 1 验收单原文）：一个测试脚本证明 (a) 臂进程环境无凭据；
   (b) 绕开双代理的出网失败（白名单只放两个代理的端口）。做不到进程级网络
   隔离就把「哪一半是构造保证、哪一半仍靠纪律」如实写进 README。
5. **对账义务**：账本推得的分数必须等于 API scorecard 分数的对账器；
   不等 = incident。写好接口，没有真轨迹前用 A0 轨迹格式做夹具测试。
6. 完成后提交 + `PARTNER_SYNC.md` 追加一段。

## 红线

- 密钥的值不进任何被跟踪文件（源码、测试夹具、文档、提交信息）。
- 本工单**不烧动作配额**：代理的联调用 mock server 做，真 API 只在 T-01 的
  预检里花。
- 不改 `arc-recon/`、两条轨道目录、`CONTRACTS/`。

## 验收

- mock 环境下：一臂经双代理跑一个假局，账本落盘、可复放（按账本动作序列重演，
  帧哈希逐一相等）、密封测试绿。
- 护栏测试：对封存局的请求被代理拒绝并记录。
- `python monitor/scan.py` 后 p1-proxy-env / p1-proxy-model 两行转绿。
