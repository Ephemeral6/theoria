# monitor — 对着 Theoria.md 读工作树

一个只读的进度监视器。它把 `Theoria.md` 当作唯一基准，逐条对表工作树，
产出一页可刷新的 HTML。

```bash
python monitor/scan.py            # 重扫，重写 monitor/index.html
python monitor/scan.py --tests    # 顺带跑两条轨道的 pytest（慢）
```

然后用浏览器打开 `monitor/index.html`。

## 它为什么不属于任何一条轨道

`CLAUDE.md` 划的两条轨道是 `theory-compiler` 和 `engine-rig`，各自只碰自己的目录。
监视器是横切的：它必须读全仓，但**只写 `monitor/`**，不修改任何轨道的文件，
也不写 `PARTNER_SYNC.md`。所以它单独放在顶层，和 `arc-recon` 一样属于共同地面。

## 两类内容，页面上分得开

* **实况**（每次运行重新算）——文件是否落盘、候选流几条、封存堆有没有被碰、
  密钥有没有泄漏、pytest 什么结果。这些在 `scan.py` 的 `PROBES` 里，是代码。
* **判断**（人写的，带出处）——某条 Phase 1 验收项算不算达成、某条约束落实到什么程度。
  这些在 `spec.py` 里，每一行都注明它出自 `Theoria.md` 的哪一句。
  没有出处的行不该出现在那里。

页面上判断带 `clause` 标注，实况带「本次扫描」前缀。

## 每次运行都会重跑的两项硬纪律检查

1. **凭据卫生** —— 全仓扫描 `ARC_API_KEY` 的值，它必须只出现在 gitignore 掉的 `.env`。
2. **封存堆零接触** —— 把 `piles.json` 的封存 21 局与所有账本里出现过的
   请求体 `game_id` 求交集，必须为空。
   （目录列表里出现封存 ID 属于元数据，不算接触，检查器只看请求体。）

任一项变红都是 incident 级事件。

## 状态词表

| 词 | 意思 |
|---|---|
| 达成 | 该条满足，证据在磁盘上 |
| 部分 | 满足一半，note 里说清是哪一半没满足 |
| 有风险 | 有产物，但与基准文件矛盾 |
| 受阻 | 有工作，但要等别的东西先动 |
| 缺失 | 该条没有任何产物 |

## 扫描崩了会怎样（S30）

以前：什么也不会怎样。`build()` 在最后才写 `index.html` 与 `state.json`，所以任何
异常都让两个文件停在上一轮的样子；traceback 进了 gitignore 的 `refresh.log`，
`reflex.py` 连返回码都没绑，把这一轮记成 `quiet`。**「扫描挂了」和「什么都没变」
在页面上长得一模一样**，只是时间戳旧了一点。

现在：

* `scan.py` 崩溃时仍然写出 `state.json`（`scan_ok: false` + 异常类型 + 出事的帧 +
  完整 traceback + **上次成功的时刻**）并把 `index.html` 改写成红色失败页。
  失败页**不显示上一轮的数字，也不显示零**——旧数字配新时间戳，正是要拆掉的东西。
* 页面自己算年龄。`index.html` 里第一次有了 JavaScript：生成时刻被烘进页面，
  浏览器每 15 秒重算一次，超过两个扫描周期（2 × 10 分钟）就自己变红并说
  「扫描可能已经挂了」。**渲染端不该无条件相信后端。**
  三态而非两态：读不出生成时刻是灰的「未知」，不是红，也不是「刚刚」。
* 每次崩溃向 `monitor/crashes.jsonl` 追加一行（**被跟踪**，一条一行）。
  历史崩溃的分类与成因在 [`CRASHES.md`](CRASHES.md)。
* `reflex.py` 检查 scan 的返回码；崩了就写进心跳行，不再记成 `quiet`。

失败出口装在 `main()` 里而不是 `build()` 里，这一条是有意的：`verify.py` 靠
`build()` **抛出**来把闸门判红，一个自己吞掉异常的 `build()` 会让闸门永远绿——
同一个缺陷，只是上移了一层。负样本在
`tests/test_scan_failure_exit.py`，变异体在 `tests/mutants.py`。

## 局限

两条轨道并发工作，这份快照可能在写出的同时就过期了 —— 这不是缺陷，是重跑的理由。
`monitor/state.json` 是同一份数据的机器可读形态，可以拿去做时间序列。
