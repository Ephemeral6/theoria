## 但是：那一列现在的定义不能直接用作地板

`exam/endpoint.py:244-245`：

```python
"certified_share": (round(certified / correct_positive, 6)
                    if correct_positive else None),
```

两个缺陷，都在把它当地板的时候才致命：

**一、`correct_positive == 0` 时返回 `None`。** 表里 `denier` / `abstainer` / `null`
的 `--` 就是它。**`None < 0.5` 不是假，是无定义**——这与 §9.15 刚在特异度上修掉的
是同一个洞（`_rate` 空分母返 `None`，一票否决因此没有全序、可被做成结构上不可触发）。
不要让它在理由维度上重开。

**二、分母是「答对的正类题数」，是可被操纵的量。** 少答对几道正类，分母就变小，
比率反而好看。地板必须建在臂**不能选**的分母上。

**三、它是跨类合并的。** 该函数的注释自陈口径为 class (i)
（「Theoria.md 1.11 class (i)…」），而 `memoriser` 的 `cert` 是 1.000 却在第 (ii) 类上
一张证书都没有（`cov(ii) = 0.000`）——**合并口径分不出「在该类上从未证明过」**。
memoriser 今天被覆盖率地板挡住了，所以看不出来；但一个在第 (i) 类大量出证、
第 (ii) 类答满却零证书的臂，会同时过覆盖率地板和合并口径的理由地板。

## 建议的写法（freeze 的裁量，不是 monitor 的）

把地板定义在**第 (ii) 类的已证率**上，分母钉死为**该类题数**：

```
certified_rate_(ii) = 第 (ii) 类中「判决正确为 unsolvable 且理由是一份被判有效的证书」的题数
                    ÷ 该局第 (ii) 类题数
```

这样：比率**永远有定义**（全答错就是 0，落在地板下——这正是要的结果，不是副作用）；
分母是题目给的，不是臂选的；且它直接量的就是「在这一类上有没有给出唯一算数的理由」。

为什么只在第 (ii) 类：该类 `search_credible = false`，证书是唯一能被计分的理由；
第 (i) 类 `search_credible = true`，「我穷举过了」在那里是正当且被计分的理由，
所以在第 (i) 类上证书份额低不构成过错。

**判决顺序建议写进预注册**：特异度 → 第 (ii) 类覆盖率 → BA → **理由地板最后**。
覆盖率地板收的是「没回答」（去向**不可结论**），理由地板收的是「回答了、
且没给出这一类唯一算数的理由」（去向**不成立**）。顺序颠倒会让「没回答」的臂
被判成不成立，与 §2.3.2 第 2 条直接冲突。

**聚合口径建议取微平均**（把 ⟨m⟩ 局的第 (ii) 类题合并成一个分子一个分母），
理由与特异度地板那条相同：每局第 (ii) 类只有 4 题，逐局比率只能取 5 个值，
「换一种平均法就过线」在一道一票否决的门上是真实可用的事后自由度。
