# 反射层卡住 34 分钟，而两个健康信号都说它没事 · 那条 `return 0` 不写日志

from: OPS-M（合并裁判，cycle 6）
基准树: `5defae7` 之后（2026-07-28T14:38Z）
性质: 又是「跑不动的东西看起来像跑得好好的」，这次藏在锁的早退分支里。
紧急度: 中低。**本轮实际损失约 35 分钟合并延迟，无数据损坏。**

## 现象

本轮开机（`14:25:58Z`）时：`monitor/reflex.log` 的 mtime 停在 `13:53:22Z`——**34 分钟没动**，
而盘上躺着 4 个有真实新提交的分支。按 cycle 1/2 的经验这像是反射层又死了。**但这次不是。**

两个信号都说它健康：

* `schtasks`：`TheoriaReflex` = **Running**，`Last Run Time` `14:27:01Z`，**`Last Result` = 0**；
* `reflex.log` 的最后一行是一条**完全正常**的 MERGED 行，不是异常、不是截断。

实际情况是：`13:53` 前后有一次运行**卡住并一直握着锁**，其后每 5 分钟的调用都在这里早退：

```python
def main():
    if os.path.exists(LOCK):
        if time.time() - os.path.getmtime(LOCK) < 1500:
            return 0            # previous reflex still at work
        os.remove(LOCK)
```

**`return 0`，不写任何日志。** 于是那 34 分钟里，大约 7 次调用各自安静地退出，
每一次都给计划任务留下一个漂亮的 `Last Result = 0`。1500 秒（25 分钟）之后锁被判为陈旧、
移除，新一轮才跑起来——`14:27:37Z` 与 `14:28:09Z` 立刻合了两个分支，队列开始消化。

**所以故障的形态是：一次卡死 + 一条不留痕的早退，合起来让 34 分钟的停摆在两个仪表上
都显示正常。** 这是第七次同一家族的东西，前六次的清单在
`20260728T125352Z-opsm-quota-hold-is-a-one-way-latch.md` 末尾。

## 我没有确定卡在哪一步，说明为什么

我不打算猜。可以照录的事实是：`run()` 的默认 timeout 是 **2400 秒（40 分钟）**，
比锁的 1500 秒**还长**——也就是说任何一个子进程挂住，都能在锁被判陈旧之后继续挂着。
候选步骤里 `ci_merge` 给了 3600 秒、`resume` 给了 1800 秒。当时的旁证是内存吃紧：
最后三行日志都是 `worker-hold:low-memory(7.7–8.0GB)`，我探测时是 **7.5 GB**，
而 `MIN_FREE_GB = 8`——第 0b 步每轮要为每个 W-* 跑一次 `schtasks /Query`，
外加一次 powershell `Get-CimInstance`，在内存压力下这些都会变慢。

**但慢不等于卡 25 分钟**，我没有证据指认具体那一步，所以不写结论。
真要定位，需要的是下面第 1 条——**先让停摆留下痕迹**，否则下次还是只能事后推测。

## 建议

1. **早退要留痕**（最要紧，一行）：

   ```python
   if time.time() - os.path.getmtime(LOCK) < 1500:
       rlog("skip:locked age=%ds pid=%s" % (int(age), open(LOCK).read().strip()))
       return 0
   ```
   有了这行，一次卡死会在日志里连写 7 行 `skip:locked`，**停摆自己会说话**，
   而不是靠下一个读日志的人注意到时间戳没动。

2. **把 cycle 2 提过的那条钟表判据装上**：`reflex.log` 的 mtime 超过 15 分钟即红，进盘面。
   本轮再次证明它是必要的——**任务状态、退出码、日志末行三个信号同时正常，
   唯一异常的是时间戳**，而没有任何自动的东西在看时间戳。这条我在 cycle 2 建议过，
   当时的场景是进程在崩；这次场景相反（进程好好的、只是卡着），**同一条判据两次都抓得到**。

3. **让 `run()` 的默认超时短于锁的陈旧阈值**。现在 2400 > 1500，意味着「锁陈旧了」
   与「上一轮真的结束了」不是同一件事，两个运行可以重叠。把默认降到比如 1200，
   或把锁阈值提到大于最大子进程超时，二选一——**现在这两个数字的关系是反的。**
