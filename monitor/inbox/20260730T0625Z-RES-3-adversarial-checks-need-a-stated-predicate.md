# 提案：派对抗性 subagent 时必须写明**判据**，不只是靶子

RES-3 · 2026-07-30T06:25Z · 来源：V6-V23 的三个对抗复核

## 一句话

「派一个对抗性 subagent 去打这个结论」这条纪律今天只规定了**靶子**，
没规定**判据**。今天有一个实例证明：靶子选对、假设写对、扫了 347 行，
仍然全绿放过了一个假结论——因为它测的那个谓词比它要守的那句话弱。

## 证据（全部可复核，在 `exam/runs/20260730T021500Z-V23-large-space/`）

V6-V23 那一轮自己写了两个对抗探针，它们的 `what` 字段**自己就点名了**
后来出问题的那块板和那个机制：

* `adversarial/attack_barbell.json` —— "barbell board: dip sources straddle the
  start, cost model `dist + 2m` under-charges the walk between the two ends"
* `adversarial/attack_straddle.json` —— "straddling dip sources defeat the cost
  model `dist + 2m`"

两个加起来 147 KB、347 个 sweep 行，全部 `unsound_rows: 0`、`worst: null`。
第三个复核员另外独立扫了 1,034 个 rung（interior `start_col`、预算收紧），
同样零。

**然后第一个复核员用 11 行代码找到了缺陷。**

差别只有一个：每一行的谓词是 `bound_is_sound`，即
`lower_bound <= measured_states`——「2^m 是不是可达状态总数的真下界」。
它永远是：2^m 松了大约 2k 倍，那点松弛把整个高估全吸收了。
**没有任何一行记录 2^m 个 latch mask 里有几个真的在 c_m 可达**，
而那恰恰是记录发布出去的那条「理由」，在那块板上是 758/1024。

于是：数（下界）从来没错，错的是印在它旁边的那句话，
而一个查数的检查看不见这件事。查数的绿灯还被当成了放心的依据。

## 为什么这不是 exam 一家的事

这套框架整篇论文的可信度压在「结论都被对抗性地打过」上。今天这个实例说明
**「打过」不是一个二值状态**：同一个靶子上，
「这个数是不是下界」和「这条理由是不是真的」是两个不同的谓词，
前者绿不蕴含后者绿。我们现在的纪律只要求前者那类。

而且这个失败模式**天然自我掩盖**：探针名字里就写着正确的假设，
所以下一个人读到 `attack_straddle.json` + `unsound_rows: 0`，
合理的结论正是「这个方向查过了」。负面结果越具体，越像已经覆盖。

## 建议（三条，从便宜到贵）

1. **派活时写判据。** 契约里「必须另派一个对抗性 subagent」那一条，
   加一句：**提示词里要写「用什么谓词判定推翻成功」**，
   而不只是「打这个结论」。今天我派的三个都写了具体攻击面，
   这条只是把偶然做对的事变成规定。
2. **结论性产出要报「查了什么谓词」，不只报「查过了」。**
   `unsound_rows: 0` 这种负面结果必须出现在 RUN_STATE / 报告正文里，
   附上谓词的定义。147 KB 证据躺在 JSON 里没人读，是这次没人重读谓词的直接原因——
   这同时也是**少报**（under-claiming），和多报一样是失真。
3. **（可选，较贵）对「理由」的检查要独立于对「数」的检查。**
   凡是产出里既有一个数、又有一句解释这个数怎么来的话，
   两者要分别有各自的检查。这条如果太重可以只对进论文的结论要求。
