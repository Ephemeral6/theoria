## 一、被打掉的那条：`blocked_*` 规则**不是**假规则

初稿说：`transitions_from_segmentation` 默认取 `seg.tracks[0]`，而 `mdl_segmenter`
按栅格序排组件，于是 193 个 gridworld 里 **72 个**挖的是**静止障碍物**，
发布的 `blocked_*` / `effect: none` 共 1209 行"被判假"。

**对抗复核实测推翻了这个定性**，两条：

1. **那 72 个世界里被挖的物体全程零位移（72/72）。** 所以 `effect: none`
   是**关于那块石头的真陈述**——它确实什么也没发生。
2. **P1 的量化范围被读错了。** 原文以 `the ledger is the verifier` 为前提从句，
   量词跑在**账本行**上而不是世界上，展开就是 `applicable == support`——
   实测 **932/932 成立**。**所以 F-1 不构成 P1 违反。**

还有一条方法论上的自我更正，值得记：初稿说"两个独立预言机零分歧"。
**那句是空的**——帧变化数 = 1209 = 判假行数 = mover 移动数，三个数相等，
说明两个预言机**共享同一个解释前提**（effect 是帧级 / mover 级），
在争议点上**不可能**分歧。**两个预言机同意，不等于两个独立证据。**

## 二、留下来的真缺陷，而且我认为它比原指控更该修：**载荷丢了物体绑定**

`engine-rig/engines/cegis_miner/__init__.py` 的 `rule_hypothesis` 载荷**不带 `object_id`**，
而同一条候选流里并排躺着的 `mdl_segmenter` 的 `object_hypothesis` **带**
（`engines/mdl_segmenter/__init__.py:22`，`"object_id": track.track_id`）。**我自己读码确认了这个不对称。**

后果不是"规则是假的"，而是**读者无法知道一条规则在讲哪个物体**。
在那 72 个世界里，规则讲的是石头；LLM 读到 `candidates.jsonl` 时，
它读到的是一条没有主语的规则，而它手上恰好还有一条**带 `object_id`** 的物体假设。
**把无主语的规则安到会动的那个物体上，是这里唯一真正危险的事**，
而它是读者会犯的错，不是引擎犯的错——**因为引擎没给它足够的信息不犯这个错。**

建议：`rule_hypothesis` 补 `object_id`（或等价的物体绑定）。
这是载荷契约的改动，`CONTRACTS/candidates_schema.md` 是冻结契约，
所以走契约变更流程，不是随手加一个字段。

## 三、`F-2` 站住了：**lifted 规则确实违反 P1，而且与怎么读无关**

`lift` 把模板守卫里的方向换成 `?dir` 后**从不重验**。
**149 条 lifted 里 104 条的守卫就是 `["act==?dir"]`。**

初稿的机理句写反了，对抗复核纠正了，**我也读码确认**：
`engines/cegis_miner/atoms.py:109-116` 的 `evaluate` 是
```python
return action == arg
```
一次**普通字符串比较**。所以 `act==?dir` 比的是 `action == "?dir"`——
对任何真实动作都**恒假**，不是恒真。并且 `free(strip(?dir))` 直接抛 `ValueError`。
查遍所有消费者，**没有任何代码绑定 `?dir`**。

**但这反而让结论变成读法无关**，两条路都通向 P1 为假：

* **不绑定** → 触发集为空 → 一条永不触发的规则被当作已挖出的规则发布；
* **若绑定** → 会触发到**不带该 effect** 的行。

再补一条读法无关的度量：**131/149 条 lifted 规则的 `applicable`
不是从它自己发布的 guard 算出来的**。也就是说，载荷里那两个字段互相对不上。

附带（较轻）：`cegis_guard: []` / `iterations: 0` 被当作实测值发布；
27/131 世界发出两条同名 `push`。

## 四、对抗复核另外挖到的，比原指控更该注意：论文路径上有同型缺陷，且**绕过了显而易见的修法**

`theoria-arm/world/adapt.py`（**论文路径**）已经在逐 track 显式传 `track=`——
也就是说，"默认取 `tracks[0]`" 这个修法在那里**已经做过了**。
但它只把发布权给「第一个不报前置条件错的 track」，
而**静止物体永远不报错**，所以照样中招。

**缓解**：该路径实测目前产出 **0 条 `rule_hypothesis`**，
所以**还没有任何 artifact 被污染**。**现在修是便宜的。**

## 五、`props.cegis_miner.check` 在这些世界上返回空，这一条推不翻

162 个世界上四条不变式全绿。**注意这不是"漏报了假规则"**（见第一节，它们不假），
而是：**四条不变式全部遍历 `result.rules`，而 `candidates()` 发的是 `all_rules`；
并且没有任何一条不变式看过 `effect`。**
所以上面第三节那 104 条恒假守卫的 lifted 规则，
**属性电池在结构上就够不到**。这与 V10 量出的"111 个发布字段、64 个从未被审"是同一件事的两个切面。

## 追记（2026-07-29T04:10Z）：第三条独立线，以及一处用词的收紧

**第三条独立线收敛到同一判断。** V13 的实现员在完全不同的路径上——它在写 effect 不变式时
被自己的 **21 条假指控**绊到，查下去发现 `_mine` 挖的是 `seg.tracks[0]`、
在 57 个可挖世界里有 21 个是静止障碍物——**独立得出了与本文第一节相同的结论**：
那些行不是假的，真缺陷是载荷没有主语。**三条互不通气的线（E11 原路、E11 对抗复核、V13 实现）
现在指向同一处**，而第一条的定性已被后两条修正。

**一处用词我收紧。** 本文第一节说"1209 行**发布**规则"。**准确地说：没有任何一行被写到磁盘。**
我复核过——E11 那一路的工作树里没有任何新的 `candidates.jsonl`，
那 1209 行是 `candidates()` 形状的**内存中**产物。
V13 的对抗复核员由此给出了一个比我第一节更强的理由：**"1209 条已发布行"没有指称对象**。

这不改变缺陷本身（载荷缺主语，`Rule.as_json()` 逐字段核对过，确实没有物体标识，
而 `CONTRACTS/candidates_schema.md` 里也没有主语字段），但它改变**严重性**：
**目前没有任何 artifact 被污染**，所以这是"修在前面"而不是"清理在后面"。
和第四节 `theoria-arm/world/adapt.py` 目前产出 0 条 `rule_hypothesis` 是同一个意思——
**现在修是便宜的。**

另附一条 V13 对抗复核员补的、独立于主语问题的证据：`structural_name` **从不过度声明**——
静止物体的规则永远叫 `blocked_*`，从不叫 `push_*`。
所以引擎在命名上是诚实的，缺的只是主语。
