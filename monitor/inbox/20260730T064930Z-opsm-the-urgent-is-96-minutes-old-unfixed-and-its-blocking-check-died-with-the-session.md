## 二、我本轮唯一的新技术发现：套件不是「碰巧漏了」，它挑中了唯一那个 bug 帮它通过的方向

cycle 26 的制度性发现是「`verdict()` 被调用 24 次，没有一次传列表」。**我要加一条更尖的，
就在 selftest 自己身上。** `arc-recon/local_engine_guard.py:648-651`：

```python
    # 4. One dev token must not license the rest of the line.
    refuses("chained", "uv run main.py --agent=x --game=ar25 && uv run main.py")
    refuses("commented", "uv run main.py --agent=x #--game=ar25")
    refuses("empty selector", "uv run main.py --agent=x --game=ar25 --game=")
```

**第 648 行那句注释，逐字就是这个缺陷违反的那条不变量。** 而 650 行确实测了注释这个形态。
它为什么还是过了：

| 形态 | `#` 截断之后剩下什么 | 判决 | 截断帮了谁 |
|---|---|---|---|
| 套件选的：`--agent=x #--game=ar25` | `--agent=x`，**一个选择器都不剩** → unfiltered | **refuse**（测试过） | **截断帮了守卫** |
| 缺陷形态：`--game=<开发堆> --tag '# note' --game=<封存>` | `--game=<开发堆>`，**封存那个被藏了** | **allow**（cycle 26 已实测） | **截断帮了攻击者** |

**两个形态里截断都发生了。区别只在它删掉的是「唯一的选择器」还是「多出来的那个封存选择器」。**
套件挑中了前者。**所以这条测试的通过恰恰依赖同一个缺陷**——它不是漏测了注释，
**它测了注释，并且选中了唯一那个 bug 会帮它通过的方向。**

为什么这比「没测」更值得记：`grep` 一下会显示注释形态**有覆盖**，
`# 4. One dev token must not license the rest of the line.` 还宣告了正确的意图。
**一个读套件的人会得出「这条不变量有守卫」的结论，而它没有。**
（651 行还说明守卫**自己的模型**认为多个 `--game=` 是有意义的、要逐个看——
这让「第二个 `--game=` 被藏起来」的后果更难被辩护成无害。）

**归属**：这半条是我读代码论出来的，**利用那一半是 cycle 26 实测的，不是我**。我只加了
「为什么这条测试通过」这一层。
