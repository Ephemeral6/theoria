## 一、我错在哪（这条我自己写清楚，不等别人替我写）

原裁决里我写：

> 规则 4，封存兜底，被同一个把戏打掉：`echo "#" ; ls environment_files/<sealed-id>` → allow
> ……**这是整条分支里唯一一行绝对不能被绕过的。**

对抗组去跑了**我没跑的那个控制实验**：verdict 字符串不等于利用。用替身载荷（`touch`）、
真守卫、真 `run` 模式：

| 形态 | 守卫判决 | 载荷真的执行了吗 |
|---|---|---|
| A `guard run -- echo "#" ; touch MK_A` | ALLOW（守卫只收到 `echo #`） | **是** |
| B `guard run -- echo '#' ';' touch MK_B` | ALLOW | **否** |
| C `guard run -- sh -c 'echo "#" ; touch MK_C'` | ALLOW | **是** |

* **A 没有判别力**：shell 在守卫被调用**之前**就在 `;` 处切开了，守卫根本没收到 `ls`。
  载荷照跑，**对一个完美守卫、和对 master 现在的零守卫，结果一模一样**。
  这就是「你永远可以干脆不把命令交给守卫」。
* **B 没有判别力**：`run` 走 `subprocess.call(rest)`，**无 shell**，`;`/`#` 都是字面 argv。
  一个没有后果的假 allow。
* **C 是真的、而且是这个守卫特有的**：守卫说 allow **并且**载荷执行。
  而未包装的 `sh -c 'make play-local'` 在我自己那 68 条负样本里是被拒的——
  **所以这不是预检守卫的固有极限，是这一个守卫的缺陷**：一个正确的守卫在这里会拒。

**根因我原来判对了**：`local_engine_guard.py` 的 `segments()` 里
`re.split(r"(?:^|\s)#", plain)[0]` 截到**文本末尾**而不是**行末尾**，
而且 `text.replace('"','')` 跑在它**之前**，所以字面量 `"#"` 变成了注释符。

**但我把根因挂在了一个不可达的例子上。** 我犯的正是我这轮开场立规矩要防的那件事的镜像：
我给五个 subagent 都写了「先在干净 master 上跑对照实验」，而我自己**拿一个单元级的
verdict 当成了一次利用**，从没问「这个输出对应得上任何可达的东西吗」。
**仪器（孤立跑 `classify_command`）没被检验过判别力。这是同一形态的第五次。**
