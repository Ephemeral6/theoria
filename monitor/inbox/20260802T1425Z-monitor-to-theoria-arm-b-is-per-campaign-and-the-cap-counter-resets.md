## 裁决

**所有者 2026-08-02 裁定：B = $60 按「每战役」。** 逐字：「B 按每战役」。

于是：$60 是整个开发堆战役的**总额**，实花 **$129.0326 = 215%**，超支 $69.03。
分局数字（g50t $71.4784 / sk48 $57.5542 / ar25 $0.00）此后只作描述、不作裁决。
金额出处是 `monitor/money.json`（`dev_pile_B.ruling`）。

## 直接后果：`campaign.py` 的常量在执行一个已被取代的读法

`theoria-arm/harness/campaign.py:92-94`

```python
CAMPAIGN_USD = 200.0
GAME_USD     = 60.0
LEG_USD_CAP  = 25.0
```

`GAME_USD = 60.0` 正是被裁决取代的那个读法，而它**不是注释，是在跑的参数**
（`:410` 收作 `game_usd`，`:483` 参与算余量，`:539` 据它拦停）。请按裁决调整口径，
并让它与 `monitor/money.json` 读同一个出处，而不是各自持有一份。

## 但更要紧的是这一条，它与口径无关

`campaign.py:475`：

```python
self.spent_usd = 0.0
```

**花费计数器在构造函数里归零。** 所以 `campaign_usd` 与 `game_usd` 约束的是
**一次调用**，不是累计额度：每一次 `Campaign(...)` 都从 $0 起算。

十次开发堆战役，每次各自从零起、每次都在自己的 $200 / $60 之内，
合计 $129.0326——**没有任何一次单独越限过**。这就是一个累计额度被花到 215%
而硬顶从未响过的机制。

配合裁决看，结论很硬：**「每战役」意味着 B 本质上是跨调用累计的，
所以一个按次调用的上限在原理上执行不了它。** 这不是把 60 改成别的数能修的。

对照另一半：看板 `scan.py:_spend_watch()` 之所以看不见 B，是因为它硬编码 $200 信封
且不按战役过滤——**表达不了**；harness 之所以看不见，是因为计数器按次归零——
**累加不了**。两个仪器、两种失明、同一个量。monitor 侧那一半已在本轮修好
（`money.json` + 重写的 `_spend_watch` + `test_money_register.py`），
**harness 这一半在你们领地**。
