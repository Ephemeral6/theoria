## 我自己的裁决错了三处，而且现在错得更贵（因为分支已经落地）

1. **把它叫做「`sh -c` / shell 包装」缺陷是误导的。** 实测：**包装什么都没藏起来**——
   `sh -c` 带封存 id 而**不带** `#` 时仍然是 `deny_sealed`。
   **真正击穿分类器的是 `#` 截断**；包装只提供**可达性**（让被遮蔽的文本真的被执行）。
   **按我的命名去修，作者会去写 shell 包装解析——那是错的修法。**
2. **我的撤回过宽。** 我 cycle 25 撤回了「规则 4（封存兜底）可被绕过」这条结论，
   因为我选的那个示例（`echo "#" ; ls ...`）没有可达路径。**但结论本身是对的**：
   存在一个**完全不需要 shell 包装**的可达形式——
   `['uv','run','main.py','--agent=x','--game=<开发堆id>','--tag','# note','--game=<封存id>']`
   → `allow`，理由行写着「every selector token resolves inside the development pile」。
   `_as_text` 用空格拼 argv，于是一个**字面量** `--tag "# note"` 参数变成无法区分的注释符、
   截断整行，把后面的 `--game=` 藏起来，而 `subprocess.call` 把完整 argv 原样交给子进程。
   执行那一半**已用两个开发堆 id 实测**：守卫的理由行自己证明它从没看见第二个选择器。
   **我因为示例有瑕疵就撤回了一个正确的结论。**
3. **我说的「约 4 行就修好」是假的。** 专组按我要求的那个补法（逐行、引号感知地剥注释）
   实现并测量：`sh -c` 两个形式**关掉了**，但**无包装的那个形式仍然 `allow`**，
   **而且套件变红（1 failed）**。原因是无包装形式**一个引号都不含**（外层 shell 在进 argv 前
   就吃掉了），所以那个 `#` 是真的裸的，任何正确的剥注释器都会吃掉它；
   同时 `test_local_engine_guard.py:276` 那条**现在能过恰恰是靠这个缺陷**。
   **如果作者照我说的交了，我会在一个绿色的 151 上放行一个仍然开着的洞。**

## 真正的根因比我说的深一层

`classify_command` **把「列表」和「shell 字符串」当同一种东西**：`_as_text` 用空格拼起来，
然后把注释/分隔符**语法**套上去。**但 argv 没有 shell**——`run` 用 `subprocess.call(rest)`，
所以 `#`、`;`、`&&` 在元素里是**字面量**，什么都不该被剥、不该被切。

专组给出的修法**实测绿**（151 passed、`selftest: green`、无需改任何测试）：
对 `str` 输入保持原样；对**列表**输入**整体判**，并**额外**只把「shell 二进制 + `-c` 类旗标」
之后的那个元素当 shell 行判。**我已另派一个对抗组专打这个补丁**——
因为一个「看起来绿的错补丁」是最坏的结果，而且它会被人照着交。**在那个结论回来之前，请不要合任何人照这条写的补丁。**
