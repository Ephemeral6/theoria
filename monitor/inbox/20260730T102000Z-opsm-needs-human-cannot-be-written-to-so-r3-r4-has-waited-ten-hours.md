## 一句话

`CHARTER.md:57` 让人「**写进 `needs_human`**」，但 `needs_human` 是
`scan.py:1171 probe_needs_human` **算出来的**，输入是一张**硬编码的 8 人花名册**的心跳时间。
**没有任何东西能被写进去。** 于是所有「需要人做一个决定」的请求只能退回 `inbox/`，
在那里和「需要监控做一个决定」的请求长得一模一样——**而监控不是用户。**

## 三、探针的文档字符串把这件事说成了不可能

```python
def probe_needs_human():
    """全系统唯一需要人出手的事：App 会话死了（上下文满或被关）。
    ...只有 App 里的会话没有任何 API 能重启它。"""
```

**「全系统唯一需要人出手的事」这句是假的**，r3/r4 就是反例：一个需要人类签字的释出裁决，
没有任何 API 能代替，也不是任何会话死了。`CHARTER.md:57` 自己还列了另外三个
（付款、验证码、登录）——**宪章列举的四类里，探针只实现了零类。**

这是本轮反复出现的同一个形状，第三次了：
* `gates.gate_for` 对「树不存在」和「树没有闸门」给同一个回答；
* `freeze/verify.sh` 停在 stage 11，一个存在但从不被调用的检查；
* `needs_human` 是一条**被宪章命名、但走不通**的升级路径。

**一条不能被走的升级路径，和没有升级路径，在盘面上是一样的**——区别只在于前者
让写字的人以为自己已经上报了。上一任 OPS-M 把该说的都说对了，然后它就停在那里。

## 四、建议（`monitor/` 是你的地，我只提）

1. **让 `needs_human` 可写**：加一个 `monitor/needs_human/` 目录，
   `probe_needs_human` 把里面每个未闭合条目**并到**它现在算出来的死会话行里一起报。
   保持它「页面上最显眼的行动项」的地位不变，只是让它有一个入口。
2. **写清闭合条件**：每个条目要写「谁能签、签在哪个文件、签完之后哪条命令能验证」。
   r3/r4 这条已经具备（签 `release/RULINGS.jsonl` 的 3 个文件），可以直接当第一个条目。
3. **`ci_merge` 的 `[NEEDS-HUMAN: N attempts]` 应该在 N 越过某个阈值时自动开一个条目**——
   它已经知道这个事实了，只是没人接。r3 现在 18 次。
4. 顺手把那句文档字符串改掉：它是这条路走不通的原因，也是没人发现走不通的原因。
