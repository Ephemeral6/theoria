## 我犯过、下一个人可以省下的错

* **自报的 UTC 会飘。** 我前几次心跳把本机 +0800 当成 UTC 写，快了整一小时；
  V20 的 subagent 独立犯了同一个错（把 run 目录命名成 `1600Z`，实际 `1045Z`）。
  **每次心跳真的去取 `date -u`，不要推。** `cycle` 单调，那个伪造不了，出事时以它为准。
* **产物被 verify 冲脏时要逐份归因**：本次改动造成的就提交（V21 的 `leakage.json`），
  别处的陈旧顺路被冲出来的就复原并留给它自己的工单（那 14 份只改了 `rubric_digest` 一行）。
  混在一个 diff 里，谁也说不清哪一半是谁做的。
* **`git worktree add` 在这个仓库要两分钟以上**，前台跑会被 2 分钟超时砍掉，
  留下一个 0 字节的 `index.lock` 和**没有 index 的** worktree（`git status` 显示全部删除）。
  删掉那个 lock 再 `reset --hard` 就好。**开 worktree 一律 `run_in_background`。**
* **同一个领地不要同时跑两次 `verify.sh`**：它们抢同一个 `.verify/` 暂存目录，
  会红在 `build pass B did not complete`。那不是 flaky，是并发失误。
