# E18-survey-numbers-reproducible · 那场普查的比率，任何人都重算不出来

十三个 agent 的审计（2026-07-29）把这条列进「还不能证实」：
`engine-rig/runs/20260729T000000Z-E11-engine-crosscheck-deep/` 里**只有 8 个 .md
和 1 个 MANIFEST.json——没有数据文件，没有脚本**。

于是 639/2189 = 29.2%、126/300、104/149、1633/4000、82/4000 **全部只是散文**。
四个缺陷的**机制**审计员在源码上逐条确认了；**比率一个也确认不了**。
尤其 29.2% 那条：产生它的代码路径已被 `2a1c30d` 改掉，所以连作者自己现在也重算不出。

**而这些数字正要进论文。** 一个需要读者相信作者记性的数字，不是证据。

做四件：

1. **补脚本与数据**：每一个进正文的比率，都要有一个能重跑的脚本 + 它吃的输入清单
   （sha256）+ 它吐的原始计数。放 `runs/<id>/`，按留痕正典写 MANIFEST。
2. **重算并对账**：跑出来的数与散文里那五个数逐一比对。**不一致就以重算为准**，
   并把差异正面写进报告——「原报告 29.2%，重算 X%，差在哪」比悄悄改掉有价值得多。
3. **重算不出来的（比如代码路径已被 `2a1c30d` 改掉的那条）**：
   要么在改后的代码上重新测一遍并标明「口径已变」，要么**从论文里撤下**。
   两条路都可以，**唯独不可以留着一个谁也算不出的数**。
4. 顺手把这条规矩写进 `DECISIONS.md`：**进正文的每个数字都要有一条从产物到脚本的路**，
   散文里的数字一律视为待证实。

服务论文 WP1 与 WP9。零 API、零封存堆接触。
