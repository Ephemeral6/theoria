# A10-shared-ledger-real-arms · 三臂同账本里一条真臂记录都没有

Theoria.md:305 那道钱门里最硬的一条，也是 A3 战役被我驳回的**第一**理由：
`proxy/var/ledger.jsonl` 里只有 `mock_arm` 与 replay，**零条真臂记录**。
而 A3 的全部产出就是论文图 2 的账单形状——没有三臂同账本，那张图跨臂对不上账，
**钱花了也发不出去**。

做四件：

1. **让三条真臂（theoria / bare-CC / ablation）的每一次计费都落进同一份账本**，
   经由 `proxy` 而不是各写各的。已有的臂内账本保留不动，
   转换产物入 `runs/<id>/` 归档（F-16 已裁定 `proxy/LEDGER_FORMAT.md` 为正典）。
2. **对账义务要重新定义，因为它当前不可清偿**：W-1640 查明**分数字段 API 不返回**，
   而对账规则要求逐条比分。裁决：对账口径改为「**成本 × 动作数 × 回合数**三元组
   逐条一致」，分数改由各臂自报并**单独标注为不可交叉核验**——
   把一条做不到的义务留在纸上，等于让这道门永远红着而没人知道为什么。
3. **负样本**：往账本里塞一条金额对不上的记录，断言对账必须变红。
4. 跑一次真的三臂小额对账（mock 或最小真跑皆可，**先算预算**），
   把「修之前 0 条真臂记录、修之后 N 条且对账绿」两份输出归档。

绿了之后 A3 的第一道锁就开了。服务论文 WP2、WP3（图 2）。
**本件不需要花游戏钱**；若需极小额真跑，先过 `proxy/spend_gate.py` 并在 inbox 报数。
