# 两个账号怎么登 —— 你要做的全部事情

其余都做好了：账号池、启动选号、撞限轮换、仪表盘面板、七条阴性样本。
**只有登录我不碰**——输入账号凭据是我明确不做的事。一个账号一次，之后再也不用管。

## 一、登录（两条命令，一个账号一条）

在**普通的 PowerShell 窗口**里跑（不是通过我）。第一个账号：

```bash
$env:CLAUDE_CONFIG_DIR="$HOME\.claude-accounts\a"; claude auth login
```

第二个账号：

```bash
$env:CLAUDE_CONFIG_DIR="$HOME\.claude-accounts\b"; claude auth login
```

两个目录已经建好，并且预置了「已接受 bypass 权限」——**没有这一步，
每个新配置目录的第一次无头启动都会撞上权限墙、以只读模式退出，
而它退出码是 0、日志是空的**（这个失效签名本仓撞过六次才查明，不要再撞一次）。

### 一个坑，会让你以为登了两个账号其实是一个

`claude auth login` 会开浏览器走 OAuth，而浏览器**已经登着你的第一个账号**，
于是第二次很可能直接用同一个账号认证过去，两个目录登成同一个人。防止办法二选一：

* 登第二个之前，在浏览器里先退出 claude.ai；或者
* 用**无痕窗口 / 另一个浏览器配置**完成第二次授权。

## 二、验证（这条你一定要跑）

```bash
python monitor/accounts.py status
```

要看到**两行都是 `login=yes`**：

```
a   max20-a        login=yes     window=open    launches=0    limits=0
b   max20-b        login=yes     window=open    launches=0    limits=0
```

只要有一行是 `no` 或 `unknown`，轮换就不会发生——**而那时撞限仍然是整队停机**，
和现在一样。页面上的「账号池」面板会把这件事说出来，不会绿着糊弄过去。

**顺便确认两个账号真的是两个人**：分别跑

```bash
$env:CLAUDE_CONFIG_DIR="$HOME\.claude-accounts\a"; claude auth status
```

看输出里的账号信息是否不同。两个目录登成同一个账号的话，
池子看起来是满的、实际只有一个窗口，**撞限时两边会同时关**。

## 三、之后会发生什么

* 每个会话在**真正启动的那一刻**选账号（不是建计划任务时选），
  账号写进日志头 `=== runner start <id> model=<m> account=<a> ===`；
* 撞限时归因到**那一个账号**、只关它的窗口，其余会话继续跑，
  `quota.py` 打印 `ROTATED` 而不是 `HOLD`；
* **两个账号都关了才是真 HOLD**，那时熔断器按各自的重开时刻自己出闩；
* 默认分工：研究员与 ops 走 a，通用工人走 b —— 一个账号挂了，
  整条赛道不会跟着停。改这个分工只需改 `accounts.py` 的 `ROLE_HOME`。

## 四、没登录之前不会坏

选不出账号时**回落到机器现有的默认登录**（不设 `CLAUDE_CONFIG_DIR`），
日志头写 `account=default(no-pool)`。所以在你登录之前，舰队照常按今天的方式跑，
只是撞限时仍然会整队停机。这是一个**具名、可见**的回落，不是一个安静的默认值。

## 五、为什么值得

今天单账号的实测停机：03:27–04:30 全队冻结一小时；05:39 四个工人在四秒内一起死；
19:0x 又一次撞限，五个会话同时被打死、窗口关到 23:00。
**第二个账号买到的不是双倍并行**（这台机器空闲内存约 6 GB，一个会话 0.4–0.5 GB，
内存在额度之前先撞顶），**买到的是不停机**——按今天的实际停机时长估，
每天多出 3–5 小时的有效工作时间。
