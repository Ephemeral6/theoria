THE ITERATIONS THAT DID HAPPEN - in the compiler, not the manual

  1. `gen_python_a0`
     rules re-read their guards against the partially-updated state, so `press_left` recoloured the Button and `door_opens_left` then found colour 8 and silently did not fire
     surfaced by: the Door never opened in the generated `step`; caught by inspection, then pinned by `test_simultaneous_rule_semantics`
  2. `gen_pddl_a0`
     the Door's cell got no PDDL subtype, so `press`'s `?d - doorcell` parameter had an empty domain and grounded to nothing
     surfaced by: `fd_adapter` reported UNSAT on an instance that is plainly solvable
  3. `segment_operators`
     `engine-rig` grew a native `split_by_color` switch mid-sprint and the monkeypatched operator stopped matching its signature
     surfaced by: `TypeError` on the variant run

  E-05   wanted: a weight function over cells for a pagoda invariant
         cost  : same as E-04
  E-06   wanted: a proof method for goals no linear pagoda covers

  E-07   wanted: saying that two live instances of one type never share a cell
         cost  : see below
  E-08   wanted: a guard that counts (`count(Token, present = false) >= k`) — the count-lock gate

  E-09   wanted: putting a *named track* in a *place*: "the object I am about to step onto is **that** one" (`faces(T,D)`) — the miner vocabulary, not the grammar
