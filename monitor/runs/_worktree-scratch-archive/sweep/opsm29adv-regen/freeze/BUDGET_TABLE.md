## 引用纪律 —— 先读这条

**每一个数字带 `path:line`。树上找不到出处的数字不许出现在本文**；
该有而没有的，写成 `⛔ 缺，由<谁>在<哪>补`，不许拿一个听起来合理的数填上。
理由与 `freeze/build_manifest.py:1-32` 记的是同一件：手抄的表会烂，
而预算表烂的方向永远是**声称的余量比实际多**——那正是会让战役开跑却跑不完的方向。

因此本文分两层：

* **机器层**（下面 `G1`–`G9`，标记之间）由 `freeze/build_budget_table.py` 从账本生成，
  `--verify` 漂移即非零退出。**不许手改。**
* **判断层**（其余全部散文）手写：B 该是多少、跑哪个情景、占位算不算花了——
  这些是判断，判断恰恰是不许被重新生成的东西。

**一处必须先说明的口径**：本文所有「已花」都不是一个数，是**三个**，

**对一张必须被冻结且可复现的预算表，这意味着三件具体的事：**

1. **余额行不可哈希。** `Theoria.md:368` 要的是「全部哈希」。

**建议的最不坏补救（已实现，提交与否是监控/RES-1 的事）：**

```bash
python freeze/build_budget_table.py --emit-pool-digest   # 写 freeze/POOL_DIGEST.json
```

`build_budget_table.py:pool_digest()` 生成一份**追踪的、按白名单脱敏的**摘要：
只抄本表引用到的聚合量 + 池自身的 sha256 + 末位 seq；
`holder`（主机名/pid）、`reservation_id`、`policy_sha256`、以及**全部 `detail` 载荷**
一概不抄（脱敏是白名单式的，不是「删几个字段」式的）。
于是清单能哈希一份「冻结时余额是这个数、池子是这个 sha256」的凭据。

**这不等于把池子变成可哈希的**，两条限度必须写清：
摘要是**那一刻**的快照，不能证明后续没花钱（后续花钱会让 `--verify` 红，那是设计）；
且摘要是**派生物**，若有人同时改池与摘要，摘要不构成防篡改证据。
它只解决「冻结时的余额在案且可引用」这一件——那件当期是**完全没有**的。

`--verify` 会在四件事上判红：JSON 漂移、Markdown 机器层被手改、
池不在（除非 `--allow-absent-pool`）、以及**逐行引用漂移**

**「池不在即判红」是故意的。** 一份余额不可核的预算表不该悄悄绿；
