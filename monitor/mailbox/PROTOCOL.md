# mailbox — 监控与运维会话的双向通道

单向汇报（audit/ 报漂移、inbox/ 投提案）之外，这里是**下行链路**：监控在这里
下达裁决与指令，运维会话在自己的周期里读取并回执。

## 给运维会话的规矩

1. **每个周期的第一件事**：读 `monitor/mailbox/<你的ID>.md`（如 `OPS-A.md`）
   与 `monitor/mailbox/ALL.md`（全员通告）。
2. 执行其中所有 `status: OPEN` 的条目。
3. 回执：把该条目的 `status:` 改成 `ACK-<结果一句话>`，并在条目下方追加
   `> reply: <你的答复/产出路径>`。**只改自己邮箱里的条目状态**，别动别人的。
4. 有话对监控说、但不属于漂移报告或提案的（提问、请求授权、报告阻塞），
   在自己邮箱末尾追加一段 `## TO-MONITOR <UTC>`，监控每次心跳读。

## 给监控的规矩

- 每次心跳：读各邮箱的 `TO-MONITOR` 段与 ACK 状态；把已闭环的条目移入
  `monitor/mailbox/archive/`。
- 一事一条目，带 UTC 与出处（引它回应的哪份报告/提案）。
- 不在邮箱里放长篇——长内容落到文件，邮箱只给路径。

## 条目格式

```
### <UTC> · <一句话标题>
status: OPEN
re: <它回应的报告或提案的文件名>
指令/裁决正文（三五行内）。
```
