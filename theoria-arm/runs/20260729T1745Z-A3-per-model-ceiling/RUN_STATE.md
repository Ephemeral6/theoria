# A3 · 重新推导「按模型定价的上限表」——它自己的规则没被自己满足

RES-1 cycle 32，2026-07-29。前情：cycle 21 的 `runs/20260729T2015Z-A3-unblock/RUN_STATE.md`
第五节「Me, next」记下 `MODEL_CALL_CEILING_USD` 是一个按 opus 标定、却对所有模型一律套用的常数。
**这一轮开工时先查，发现那件事已经被我的某一世做完了**：`harness/spend.py` 里已经有
`MODEL_CALL_TIMEOUT_S`、`OBSERVED_USD_PER_SECOND`、`MODEL_CALL_CEILINGS_USD`、
日期后缀别名解析、未知模型取表中最大值，以及一条把「预留上限」与「计费金额」拆开的
提案（明确留给监控裁，没有自决）。243 条测试全绿。

所以本轮做的不是重做，是**对抗性复核**：不重读常数，改成从档案里重新推导。
两处都错了，而且是同一个方向——偏低。

## 一、速率取错了最大值

`OBSERVED_USD_PER_SECOND` 的两个数，取的都是**最贵的那一次调用 ÷ 它自己的时长**。
但最贵的调用通常也是最长的，除下来得到的是个中庸的速率；
**最贵的那一秒属于一次更短的调用。**

| 模型 | 表里写的 | 档案里最差的 | 偏低 |
|---|---|---|---|
| `claude-opus-5` | 0.0024676 /s | **0.0028860 /s** | **17.0%** |
| `claude-haiku-4-5` | 0.000606 /s | **0.0006376 /s** | 5.2% |

opus 那个更差的速率来自 `runs/20260728T014402Z-g50t-first-contact-aborted`
（$0.730485 / 253.11 s）——**旧注释在上两段里点了这次调用的名**
（「The aborted run's single call was $0.730485」），却没有把它纳入速率表。
资料在手边，没被用上。

## 二、上限没满足它自己写下的规则

文档里的定则是 `max(timeout × rate, 4 × 最差单次调用)`，向上取整。
对 opus-5 代入它**自己的**（偏低的）数字：

```
1800 × 0.0024676 = 4.44
4 × 1.489011     = 5.96   ← 起约束作用的是这一半
max              = 5.96
表里写的          = 5.00   ← 低 $0.96
```

也就是说：**这条改动是为了消灭「上限有时不够高」而写的，而在本臂唯一真正跑过的
主力模型上，那个毛病原样还在。** 用修正后的速率算，全时长 opus 调用是 $5.19，
仍高于 $5.00。`proxy/cost.py:93` 立的标准（「a ceiling that is sometimes too low
is not a ceiling」）被它自己的表破了。

haiku 那一格反而是对的（$1.25 ≥ $1.15），两种算法下都成立。

## 三、为什么既有的测试全绿

已有 `test_the_ceiling_is_not_below_a_full_timeout_at_the_observed_rate`，
断言 `ceiling >= rate × timeout`。它写得不差，但只盖住了规则的**一半**，而且
**把速率常数当作既定事实读**。于是：

* 规则里起约束作用的那一半（`4 × 最差调用`）没人断言 → $5.00 < $5.96 无人发现；
* 速率常数自己偏低时，它连同由它推出的上限一起变低，断言 `5.00 ≥ 4.44` 照样成立。

**两个错误互相掩护，测试全绿。** 能发现它的方法只有一个：回档案重推，而不是重读常数。

## 四、修法

* 速率改为档案中**最差速率**，并且**向上取整到第七位小数**——
  opus 真值 0.0028860377，写成 0.0028860 会让记录值低于观测值，是同一个毛病的缩小版；
  这一条是新测试当场抓出来的，所以那行现在写的是 0.0028861。
* `claude-opus-5`: **$5.00 → $6.00**（`max(1800×0.0028861, 4×1.489011) = 5.96` 向上取整）。
* 未测量的模型：由 opus-5 按**输出价比**缩放，再乘 **1.25 的吞吐余量**。
  理由不是保守起见，是手上唯一一次跨模型校验说必须这么做：
  haiku 按价比推得 `0.0028861 × (5/25) = 0.000577`，**实测 0.0006376，高 10.5%**——
  便宜档吐词更快，而每秒美元 = 单价 × 吞吐，所以**纯按价比缩放会低估便宜的模型**，
  正好是不安全的那个方向。余量由这一条观测定，不是拍的；n=1，是一个方向已知、
  量级大致已知的修正，不是标定过的常数，记录在案。
* 新增 `test_the_ceiling_table_still_covers_the_archive`：
  **不读常数**，重新扫 `runs/*/desk_log.json` 求每个模型的最差速率与最差单次调用，
  再断言表覆盖规则两半。

## 七、顺带一个还没修的发现

价目表**系统性地低于 CLI 自报的价**，且从不高于：opus 差 0.9–1.8%，haiku 差 4.9–6.0%
（九次调用，逐条见 `measure_desk_rates.txt`）。缺口的成因没查出来——
1h 缓存写入按 2.0× 计已经算进去了，仍然差这些。

**这与上一世记的「4.9–7.9% 短」是同一件事，但分模型看不是一个数**：
haiku 4.9–6.0%，opus 只有 0.9–1.8%。上一世是在十条 haiku 可比调用上量的，所以看到的是前者。

要紧之处：任何**只**读价目表来定上限的做法，都会继承这个缺口。本表没有——
它读的是 CLI 自报的 `cli_cost_usd`。记在这里，因为下一个想「直接用价目表算就好了」的人
需要先知道这件事。价目表本身是 `proxy/` 的地盘，不是本臂能改的。
