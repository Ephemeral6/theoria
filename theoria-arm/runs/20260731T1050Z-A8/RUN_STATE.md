# A8 · 战役记账管线：每关自动产出图 2 原料

`armtools/curves.py` + `harness/campaign.py` 里的一处接线 +
`tests/test_curves.py`（17 条）。

## 一 它做什么

每条 leg 跑完，从**已经算好的** `turn_series` 里抽出三条曲线——
theorize 轮数、七种意外分类计数、逐回合累计成本——**按关卡切开**，
落 `runs/<slug>/curves.json`，外加每关一份 `runs/<slug>/curves/level-NN.json`。

为什么要按关卡切：C3 是迁移，`inner/levels.py` 已经把它的机械含义钉死为
「同一份 `theory.dsl` 对上一个不同的计算 problem」。所以图要撑的那句话是
「第二关比第一关便宜」，而这句话需要三条曲线在边界处**切开**而不是**平均掉**。
一条没切的曲线上，「打完一关之后就不怎么花钱了」和「全程都便宜」长得一模一样。

## 二 它只做归约，不重新推导

每一个数都来自 `armtools.archive.turn_series()`（`model_call` 记录 /
`turns.json` / `surprises.jsonl` 三者的 join）和 `inner/levels.py` 的边界事件。
本文件不为了重算某个量而重读原始账本。

这是规矩不是偏好：`archive.turn_series` 自带一份写下来的、关于这个 join
为什么成立的账（哪个索引桥到哪个、重建有多确信），并且在自查失败时**自己降级**
`join_confidence`。第二份实现就是同一个问题的第二个、且没有标签的答案，
于是 E2 的输入会有两个定义——那正是 `figures/sources.py` 存在要抓的失败，
也是 `campaign.campaign_series` 不重算 front-load index 的同一条理由。
有一条测试把这一点钉住：把 `archive.turn_series` 打坏成抛异常，归约必须照样成功。

## 三 自检：`env_step` 一个都不能漏，对不上即抛

`turn_series` 的每一行带 `http_commands`，即该回合发出的环境命令数。
在本文件所有曲线上求和，必须**严格等于**该 leg 账本里 `env_step` 记录的条数。
真实归档上的实测：

| run | 回合 | 曲线合计的命令 | 账本 `env_step` |
|---|---|---|---|
| `20260728T072604Z-E3-sk48-carried` | 1 | 92 | 92 |
| `20260728T025503Z-g50t-e08-fixed` | 3 | 146 | 146 |
| `20260729T004020Z-leg01` | 52 | 104 | 104 |

**注意这个不变式不是「一回合一个环境步」。** 一个回合会发很多条命令
（RESET、重试、被拒的动作），本臂实测比例高到 146:3。
不变式是曲线**核销掉**每一条命令，不是曲线按命令索引。
如果照字面把自检写成「回合数 == env_step 数」，它在这三份真实归档上全都会抛。

它是严格相等，**两个方向都抛**：少了是丢了回合（那笔钱照样花了，
而丢了回合的曲线只是「看起来短一点」，在图上完全看不出来）；
多了是某个回合被数了两次。单边检查会放过后者。

**外加一条下限：零回合直接拒绝。** 这条是写完自检之后自己攻出来的——
`0 == 0` 满足上面那个等式，于是一条从未走到第一回合的 leg 会写出一份
语法完美、每条序列为空、每个合计为零的 `curves.json`，而**成本曲线里的零
读起来是「这条 leg 很便宜」，不是「这条 leg 没发生」**。
`theoria-arm/verify.py` 开篇点名的正是这个失败，例子也一样：
`figures/verify.sh` 曾经因为两次构建都什么也没产出而打印 "ok"——
两棵空树逐字节相同。拒绝时消息**同时报出两个数**，让读者分得清两种成因：
什么都没跑（两个数都是 0），还是**join 把一份满是命令的账本的每一行都弄丢了**
（账本有命令、序列没有行）。后者是危险的那个，而在加这条下限之前，
它和前者长得一模一样。

抛而不是记：这条与本臂归档路径上其余部分**相反**——
`write_turn_series` 被 `harness/campaign.py` 用 `try` 包着，正是为了让一次归约失败
不至于弄丢一条已经跑过的 leg。这一条不同，因为**有洞的曲线不是降级产物，是错的产物**，
而且错在让战役看起来比实际便宜的那个方向。
自检不过时**一个文件都不写**：缺文件是会被人追问的，短曲线不会。

## 四 接在哪

`Campaign.run_leg` 里，`write_turn_series` 旁边，共用同一个非致命 try：
一条跑过并且付过钱的 leg，值得被记下来，哪怕对它的归约失败了。
失败落在 leg 自己的条目上（`curves_error`），
因为一条既没有曲线又没有理由的 leg，在战役报告里读起来就是「没发生过」。

`tests/test_campaign.py` 里每一条测试都整个替换掉 `run_leg`——这正是
`run_leg` 内部的归档段历来没有覆盖的原因，也是 `_leg_cost` 能带着 bug 出厂的原因
（它读了一个 `ModelDesk.summary()` 从未发出过的 key，于是 $60/$200 天花板压根跳不了）。
所以这里有两条测试驱动**真的** `run_leg`（只替换 `play`）：
一条要求 `curves.json` 落盘、关卡切成两关；
一条造一个有洞的账本，要求 leg 仍然入账、`curves_error` 带上 `CurveGap`、
且**不留下** `curves.json`。

## 五 与 `figures/` 的确定性管线对齐

* 写法与本仓库每一件确定性产物相同：`indent=1, sort_keys=True`、LF、结尾换行。
  同一账本跑两次逐字节相同（有测试）。
* 顶层带一个扁平的 `rows` 和一份声明的 `columns`：
  `figures/` 每张图的审计面是 `figures/csv/<name>.csv`，
  列序要稳定；从 dict 推列序会得到字母序，那会把 `usd_cumulative_in_leg`
  排到 `theorize_rounds` 前面，审计表读起来是反的。
* 七种意外**永远是七条并列序列**，没发生的那种是 0 不是缺键——
  否则「这一类在第一关之后就不再出现了」这句有意思的话，
  和「这一类根本没被画」分不开。
* front-load index **不在这里算**：它是 `battery/metrics/economy.py` 的 E2，
  Phase 4 三个主端点之一。本文件组装输入然后停手。

## 六 一处与条目字面的偏离，明写出来

条目写的是落 `theoria-arm/runs/<关卡>/curves.json`。
本实现落 `runs/<slug>/curves.json` + `runs/<slug>/curves/level-NN.json`。
理由：关卡是 leg **内部**的东西；一关可能被一条中途死掉的 leg 劈成两半；
一次战役里两个游戏都各有第一关。以关卡命名的路径在这三种情况下都会撞车。
run 目录是本臂唯一的 run 身份，所以每关一份文件放在它下面——
「每关有自己的路径」这个需求满足了，命名冲突没有引进来。
