## 0. 三条判据，先写下来

### 0.1 「仍与当前指标定义对应」的判据

一条预测**对应**当前定义，当且仅当：

* **N**（名）预测点名的标识符在 `battery/metrics/` 里找得到，或其改名有据可查；
* **D**（口径）该指标自预测写下之后，其**计算规则**没有变；变过则记 `口径已变`；
* **A**（臂）预测点名的臂，今天仍指同一个构念。

三项全过记 `对应`；任一项不过记 `标注` 并写明哪一项。

### 0.2 「顺序」的判据

用 `git merge-base --is-ancestor <预注册commit> <首次回算commit>` 判定。
退出码 0 且反向非 0 = **顺序严格成立**。查不出先后的，写「无法确定先后，因为 X」，
**不猜**。

顺序另有一层：预注册**当时作者已经看见的值**。这一层 git 证不了，只能靠预注册
自己的封条声明；封条没声明而事后可查的，本表记 `未声明的先验知识`——
**登记，不删除**。

### 0.3 「足够具体到能被证伪」的判据

* **F1** 预测点名的量由一条已注册指标算得出；
* **F2** 存在一个**写得出来的**取值，使这条预测算错；
* **F3** 该量在预测所述的臂上能算出 `ok`——只能得到 `no-data` / `not-applicable`
  的，记 `当前材料不可判定`。

**F3 不过 ≠ 预测被证实。** 不判定就是不判定。

F1∧F2∧F3 = `可证伪`；F1∧F2 而 F3 不过 = `可证伪，当前不可判定`；
F2 不过 = **`不可证伪`**——写不出反例的，本表照实标，**不替它补一个**。
