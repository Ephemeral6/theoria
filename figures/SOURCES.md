# figures/SOURCES.md — what the figures read, what they cannot, and why

Three files describe the inputs, and they have different jobs:

| file | job | maintained by |
|---|---|---|
| `sources.py` | the **registry**: every path, which figures use it, what is taken from it — as a list of `Source` entries *and* a short list of `Rule`s that generate more | hand, and it is the executable form |
| `SOURCES.sha256` | the **hashes**, one line per declared source, `ABSENT…` for the absent ones | generated by `build_all.py`, checked by `verify.sh` gate 4 |
| `check_coverage.py` | the **probe**: does what is on disk actually reach the figures | executable, `verify.sh` gate 8 |
| this file | the **judgement**: what is missing, what that costs each figure, and what the figures are not allowed to read | hand |

## Declared by name, and declared by rule

Most sources are one file with one job and are named individually. Three are
*families that grow* — the theoria arm writes a directory per run, the baseline
writes a roll-up per campaign, the envelope campaign writes a shard per game —
and naming their members by hand meant that data landing on disk did not reach a
figure until somebody edited two files. **Twice, nobody had** (`PLAN.md` §3, §10).

Those three are declared as `Rule`s. A rule is still a declaration: it names the
directory, the filename pattern, the members required inside each entry, and a
**floor**. Every file a rule finds becomes a real `Source` and is hashed into
`SOURCES.sha256` exactly like a hand-written one, so *nothing is read unhashed*.
What moved is only who enumerates the family: the filesystem, rather than a tuple
that ages.

**A `tracked=True` rule discovers only what git tracks**, and that is this file's
third opening rule applying to rules as well as to names. Discovery widens the
blast radius of an untracked file: a stray `pilot_scratch.json` dropped into
`baseline-arms/out/` was invisible when only four filenames were read, and a bare
glob would hash it into `SOURCES.sha256` and feed its rows to a figure — on one
machine and not on a clean checkout. It also keeps the promise the work order
actually asked for, because *committing the data is not a code edit*. When git
cannot answer, discovery falls back to every matching entry and says so through
`sources.TRACKING_UNAVAILABLE`, which `build_all.py` prints: a weaker guarantee
nobody is told about is the failure mode this repository keeps rediscovering.

The floor is the part that makes discovery safe rather than merely convenient. A
glob that finds nothing is indistinguishable from a family that is empty, so each
rule records how many members were on disk when it was written; `verify.sh` gate
0 fails below that count. Members that are *expected to be absent* stay declared
through the rule's `expected` list, because a known-absent input has to remain
legible as absent — a rule that simply found nothing would erase the fact that
the input was ever expected.

And because none of gates 1–7 can see a figure that quietly omits data —
byte-identical builds, matching committed tree and unchanged hashes are all
perfectly compatible with leaving two runs out — `check_coverage.py` walks the
tree independently and asks whether what is on disk reached the picture. It runs
its own negative control first, reconstructing the pre-P8 tree and requiring
itself to fail on it. That control immediately earned its keep: the probe's first
version drew its inventory from the registry it was auditing, and stayed green
over the very defect it was written for.

This file deliberately carries **no table of sources**. It used to. A hand-copied
table of paths is a second source of truth that drifts away from the first, and
drift of exactly that kind produced three of the defects P4 found (see
`PLAN.md` §9). `sources.py` is short and commented; read it.

No **figure** script opens a path that is not declared in `sources.py`, and
`verify.sh` gate 7 enforces it by parsing `fig*.py` with `ast` rather than by
grepping — the regex version's first finding was the phrase "never ``open()``"
inside a docstring. That is not a style rule: an undeclared read is an unhashed
read, and a figure with an unhashed input keeps building green while the input
drifts underneath it.

`sources.py` and `check_coverage.py` are the two files this does not cover, and
both are outside it on purpose. `sources.py` is where the reading happens.
`check_coverage.py` is the auditor: it walks the tree with `os.listdir` and
opens what it finds, because an oracle that reached the tree only through the
registry it audits could prove that registry self-consistent and nothing else.
Gate 7's glob is `fig*.py`, so neither is scanned, and that is the correct
scope rather than an oversight in it.

One non-file source is declared out of band: `git log --follow
cold-start-a0/THEORIZE_LOG.md`, read through `sources.git_log()`. It supplies
the only wall-clock fig06 has. It is **not** hashed, because git history is not
a file; `sources.git_log()` returns `[]` on a shallow or git-less checkout and
fig06 falls back to its ordinal axis and says so on the plate.

## Declared and absent — named on purpose

Absent sources stay in `sources.py` with `optional=True`, so they appear in
`SOURCES.sha256` as `ABSENT…` lines. A source that is missing should be
*legible as missing*, not merely unmentioned.

## What is still missing from figure 2, and what it costs

`Theoria.md` §3.2 specifies figure 2 as a **three-arm** per-turn cost curve. It
ships with two.

* **The theoria arm is present** as of P4 — `theoria-arm/runs/*/cost_curve.json`
  plus each run's `MANIFEST.json`. It did not arrive through the ledger
  interface P-21 built for it: the arm's `ledger.jsonl` is `LEDGER_FORMAT v1.0`,
  a third record dialect whose `model_call` rows carry no top-level cost at all.
  `cost_curve.json` is the artefact the arm publishes for this purpose. As of P8
  it arrives by rule (`theoria_run`, floor 4), so the next run to land is drawn
  at the next build with no edit here or in the figure. It draws a **bill** and
  no **shape**: the live arm is in none of battery v2's five arms, so it has no
  E2/E3/E4 and the plate says which, rather than showing a low score.
* **The Schema arm is still absent from the cost ledger.**
  `baseline-arms/SCHEMA_LOCATE.md` says there may never be one;
  `battery/DECISIONS.md` D-B-004 argues the model ladder is a *weaker* substitute
  rather than an equivalent. Note the asymmetry with figure 3, which **does**
  have a Schema arm: `battery/REPORT_V2.md` ingested one for the battery (8 runs,
  4 development-pile games × 2 upstream collections). Those are upstream
  trajectory collections, not runs this repository paid for, so they carry no
  cost curve. A Schema *capability* column exists; a Schema *bill* does not.

And the caveat that matters more than either: **the two arms that are drawn are
not priced in the same unit.** A `bare_cc` turn buys one model call that picks
one action. A theoria turn buys a desk call that theorises across the whole run —
5 calls covered 7 actions. The vertical gap in panel A is not a like-for-like
markup, and the plate says so on its face rather than in this file.

A two-arm figure labelled as two arms is better than a two-arm figure labelled
as three. A two-arm figure whose two arms are silently in different units would
be worse than either.

## Where a number is contested, both numbers travel

Three inputs disagree with something. None is averaged, and none is quietly
resolved:

* **The theoria arm's dollars.** `cost_curve.json` carries the provider's
  arithmetic (USD 6.317658); the repo's price table recomputes USD 5.795338, a
  −8.3 % gap, of which USD 0.4368 is a known table defect — 1-hour cache writes
  priced at the 5-minute multiplier, because `proxy/cost.py` reads the flat usage
  key and not the nested `cache_creation` object. The provider figure is plotted;
  the disagreement is a note and a line on the plate. It is a finding about
  `proxy/pricing/pricing_v1.json`, not about the run.
* **`cold-start-a0`'s compression accounts.** `THEORIZE_LOG.md`'s O-04 table
  prices Cart +2967 / Button −17 / Door −13 against a pixel baseline;
  `artifacts/concept_accounts.json` and `theory.dsl` say +2125 / −5 / −1 against
  the responsibility-complete baseline, re-priced in commit `7cc02a9`. The log
  was never updated. Figure 6 uses the JSON, names the baseline, and puts both in
  the CSV.
* **`battery/artifacts/arm_contrast.json`.** A v1-era artefact that knows four
  arms where the spectrum scores five. Figure 3 takes its axis from
  `capability_spectrum.provenance.arms` and reports the staleness rather than
  being vetoed by it.
* **The battery's own `support["turns"]` key means two things.**
  `battery/metrics/economy.py` fills it from `len(run.turn_costs())` for E2 and
  E3 — decisions — and from `len(run.calls)` for E4 — billed calls, retries
  included. The two differ exactly when a decision was retried, and on
  `bare_cc-g50t-claude-sonnet-5-ddabe772` they are 20 and 24. Figure 2 labels
  panel D's axis with what E4 actually counts, uses only E2/E3's count for its
  turn-axis check, and reports the disagreement in its notes. Found by P8 while
  widening that check, which briefly made the figure report an axis mismatch that
  did not exist; the two numbers were never the same measurement. Battery
  territory, reported not touched.

## Pile discipline

Every source is either a **self-built world** (`cold-start-a0` and its `prime/`,
`cold-start-a2`, `cold-start-a3`, `a0-spike`) or a **development-pile** game:
`ar25-0c556536`, `g50t-5849a774`, `sk48-d8078629`, `tn36-ef4dde99`. No figure
reads anything belonging to a sealed game.

`capability_spectrum.json` carries the cut it was computed under —
`provenance.cut.piles_sha256` = `3feca53e…41bbc19a`, matching
`arc-recon/data/piles.json` — and figure 3 stamps it.

`cold-start-a2/artifacts/loop_ledger.json`'s own `authority` field records the
INC-004 ruling under which its DC22-isomorphic world was built **without**
reading any upstream DC22 artefact; figure 5 carries that sentence onto the
plate, because a reader who sees "the DC22 case" is entitled to know the seal
held.

## Territory

Figure work writes **only** inside `figures/`. Every data directory is read-only,
and `cold-start-a0/` (including `prime/`) belongs to the theory-compiler track,
so it is read-only in the strongest sense — P4 read it and reported two defects
in it to `monitor/inbox/` rather than touching them.
