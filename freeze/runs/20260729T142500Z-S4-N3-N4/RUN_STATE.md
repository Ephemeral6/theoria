# S4 · N-3 与 N-4 —— RES-1 cycle 25，2026-07-29

机器可读的账在 `MANIFEST.json`；本文是叙述。

## 一件事的两半

`RECONCILE.md` 把 N-3 与 N-4 登记成两条。它们是一条。

**N-4 是一处矛盾**：`CLAIMS_TEXT.md` 的 C1 逐字文本要求「公理集为空」，
而 `STATS_RULES.md` §1.2 已于同日（G1 移植）改为按**白名单**判——
`propext` / `Quot.sound` / `Classical.choice` 放行，`sorryAx` 与
`Lean.ofReduceBool` 永不放行。两份文件都自称是**同一个终点 U3 的逐字文本**。

**N-3 是它的价钱**：白名单放行了三条公理，于是「恒真定理冒充 U3」这条钻法
只剩判据 (c)（非平凡性检查）一道门；而 (c) 至今没有实现。

分开看，N-4 像是「要不要放宽自己的验收标准」，N-3 像是一次待办的升级。
合起来看才是真的形状：**(b) 让出去的那道门，(c) 是接住它的唯一一道**，
所以两者必须同批生效。只做 N-4，这个终点会比修订前更好钻。

## N-4 的裁定与理由

前两轮把 N-4 读成「一次全新的裁定」并因此推迟。这个读法值得订正：
**实质裁定在 G1 移植时就已经做过了**。现在两份文件的分歧不是「该选哪边」，
而是**已做的裁定只落进了两份副本中的一份**。

而分歧的代价不是中立的。按 `STATS_RULES.md` 执行、按 `CLAIMS_TEXT.md` 公布，
**公布出去的那句话本身是假的**——我们并没有按空公理集判。措辞四条硬规第 1 条
（「主张只能出自本文件」）恰恰是为堵这种分歧写的，而它在这里正好失效于
没人会注意的方向。「不动 claim 文本」这条纪律在此保护的不是主张的稳定，
是主张与判据脱钩。

**方向：放宽 `CLAIMS_TEXT.md` 去对齐白名单。** 三条理由，都与我们的成绩无关：

1. **依据是 Lean 4 标准库的事实**，不是我们的表现：凡用到经典推理、命题外延
   或商类型的证明，`#print axioms` 必报那三条。要求空集等于只放行 `decide`/`rfl`
   判得掉的琐碎命题——那不是把门槛提高，那是换了个终点。
2. **时序**：封存战役至今一局未跑（`contamination_log.jsonl` 记封存堆零 API 接触），
   仍在预注册窗口内。
3. **白名单是收敛的**：两条永不放行，冻结后新增任何一条都是 incident。

修订记录写进 `CLAIMS_TEXT.md` 而不只是本文，并附一条论文正文义务：
C1 的裁决段必须写明判据于 2026-07-29 自空集修订为白名单、修订发生在任何封存局
开跑之前、以及 (b)→(c) 的负担转移。**读者默认「放宽了判据」是一个自由度，
除非时序与理由在案。**

## N-3 的裁定

`needs_impl` 与 `开跑前置条件`（§9.11 是先例）的区别不是紧迫程度，
是**不做的话跑出来的数据还有没有意义**。两项都落在后者：

* **§9.14（新登记）** —— U3 达成率**没有任何计算代码**（`build_manifest.py:173-178`
  引 `PREDICTIONS.md:585` 与 V18 的 `ENDPOINTS.md:15`「unfalsifiable」）。
  为一个算不出来的量冻结裁决规则，冻的是一句不可执行的话。
* **§9.2（升级）** —— 判据 (c) 是上面那条钻法唯一的门。而这条钻法不是假想的：
  `cold-start-a3` D-A3-007 记着它**已经自己发生过一次**。

顺带写死一句以前没写死的：**真空定理恰好是判据 (b) 判得最漂亮的一类**，
因为它用的公理最少。所以 (b) 无论定成空集还是白名单，都分辨不出它——
这句话原来在 `CLAIMS_TEXT.md` 里写成「全仓通用的验收判据（空公理集）分辨不出它」，
白名单之后已不再描述现行判据，一并订正。

## 闸

`bash freeze/verify.sh` → exit 0（DRAFT COMPLETE，1 note）。

新增**第 10 阶段**：一条规则，两份副本不许再漂。它查五件事：

1. C1 的两个逐字块不得复现空集措辞（上方的修订记录**可以**引用旧措辞——
   那是散文不是主张，故意不在扫描范围内）；
2. 成立版必须点全白名单五条，**含两条永不放行的**——否则可以靠在公布句里
   悄悄漏掉 `sorryAx` 来放宽；
3. `STATS_RULES.md` §1.2 的白名单**表**必须给出同样的处置，**且放行行只许有那三条**——
   散文承诺「冻结后新增任何一条都是 incident」，这是它可执行的那一半。
   只查「三条在不在」会放过悄悄追加第四条，而那是不动任何人会读的句子就能放宽
   判据 (b) 的最省事的办法；
4. §9.2 与 §9.14 必须仍是开跑前置条件；
5. **阴性对照**：把旧措辞放回 C1，本阶段必须变红。

六种复发形状实测全红：改回空集、公布句漏掉 `sorryAx`、§9.2 降回 `needs_impl`、
白名单表的放行行掉一条、把 `sorryAx` 挪进放行行、往放行行追加第四条公理。

**一处自陈：第 3 项的第一版是绿得没道理的。** 它只查五个名字在 §1.2 里出现与否，
而 §1.2 的散文本来就在逐条论证这五条公理、每个名字都出现好几次——
一个把白名单表格掏空的变异体照样全绿。改成读**表格的处置列**之后才真的在测东西。
记在这里，因为「查名字出现与否」正是一道闸绿得毫无意义时的典型形状。
