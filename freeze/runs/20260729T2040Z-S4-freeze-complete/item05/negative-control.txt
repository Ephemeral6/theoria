# negative control -- does `build_engine_manifest.py --verify` actually catch drift?

Worktree `C:/Users/user/Desktop/theoria/.worktrees/s4-freeze`, branch
`agent/s4-freeze`, HEAD `5822e5e5c4c87e42f834ddca76f3af56eee3e7b6`.
`engine-rig/` clean throughout; nothing outside `freeze/` was written.

The baseline copy is kept beside this file as `ENGINE_MANIFEST.baseline.md` and
the live file is restored from it after every mutation, so a control that dies
half way cannot leave a mutated manifest on the branch.

FOUR checks, one per detector plus one for the CRLF trap, because a verifier with
one detector and four failure modes is a verifier that is green for three:

  A. a hash moves                          -> the row detector must NAME the row
  B. a derived count moves, hashes intact  -> the rendering detector must fire
  C. the pin block is gone                 -> unchecked, must not pass
  D. the whole file is CRLF on disk        -> must stay GREEN (a false red here
     is the exact failure `MANIFEST_DRAFT.md`'s 哈希纪律 warns about: a red gate
     on an identical tree teaches people to regenerate until it is green)

collapse CRLF to LF before the comparison, and every hash it compares came
from git rather than from disk bytes.
