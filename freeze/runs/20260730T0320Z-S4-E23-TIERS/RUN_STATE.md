## 一、「两层一致」兑成 §4.4，**只写一处**

`CLAIMS_TEXT.md` C2 与 C4 的成立版末尾原样留着「两层一致」——
与 S4-E1-HOLES 从 C1 拿掉的**逐字同一个未定义谓词**，判在看到两个数之后。

新写 **§4.4**（`STATS_RULES.md`），六个小节。**它只写一处，两个配对终点共用**，
§2.2.1 与 §3.2 各自指过来、不复述。这一条是有理由的，不是排版偏好：
S4-E1-HOLES 第二轮发现 §1.4.5 与 §1.4.2 把同一条裁决口径写在两处，
**同一组数字于是有两个答案**。一处规则写在两个地方就是两条规则。

### 1.1 为什么不能照抄终点一的合取

终点一是单样本比率：两层各是一个整数与一条过线，合取是唯一读法。
终点二三是配对检验，一层的裁决由**显著性、方向、效应量**三样合成，
而 clean 层的对数可能少到**在结构上不可能显著**。
§4.3 早就算过：符号检验在 Holm 最紧那级（0.0167）需要 **v ≥ 7** 对全部同向。
于是「两层都显著」在小 clean 层上不是一条严格的规则，
**是一条在见到数据之前就把终点判死的规则**——而 §4.1.0 立条的理由正是反对这种事。

### 1.2 两个终点不对称，而这是算出来的

关键是 §4.1.0 的剔除上限**已经给 clean 层的可评对数定了下界**：
「尚未被 §4.1.0 判死」这个前提本身蕴含 ⟨v_clean⟩ 的下界。代进去：

| 终点 | clean 层对数 | 最坏 ⟨v_clean⟩ | 最小可达两侧 p | 最紧 Holm 级可达？ |
|---|---|---|---|---|
| **终点三** | 12 | 8 | **0.0078** | **是，恒可达** |
| 终点二 ⟨m⟩=19 | 12 | 9 | 0.0039 | 是 |
| 终点二 ⟨m⟩=14 | 7 | 5 | 0.0625 | 否（连 0.05 都不可达） |
| 终点二 ⟨m⟩=13 | 6 | 5 | 0.0625 | 否 |
| 终点二 ⟨m⟩=12 | 5 | 4 | 0.125 | 否 |

**所以终点三可以要求两层都显著，终点二在 ⟨m⟩ < 19 时不能。**
这不是两条裁定，是同一条裁定代进两组对数——所以规则写一条，它自己给出不同结果。

### 1.3 裁决表（§4.4.3，六行按序求值）

第 0 行 §4.1.0 剔除上限 → 不可结论；**第 1 行 `2·0.5^⟨v_clean⟩ > α*`（clean 层结构上
不可能达到门槛）→ 不可结论，claim 层照报并降级探索性**；第 2 行 claim 层不显著或方向反
→ 不成立；第 3 行 clean 层显著且反向 → 不成立；第 4 行 clean 层不显著（有功效而未达到）
→ 不成立；第 5 行 两层皆显著同向 → 成立。

**第 1 行是全部要价**：clean 层没功效时**不退回「只看 claim 层」**——那条路就是
「以弱者为准」形同虚设。代价明写：**选 ⟨m⟩ ≤ 14 就是选择让 C4 以不可结论发表**。
这正是 §2.2.1 想买的东西：「事后发现 clean 层不可能显著、于是丢掉 clean 层」
在事后不可用，因为它在开跑前就被算出来钉进预注册了。

**Holm 的 family 仍恒为三个主终点**——第 1 行判不可结论不缩 family。
这一条 C1 已逐字写着，而第 1 行给它开了**第二个调用点**，所以本轮给它加了正向探针。

## 二、⟨k⟩ 的符号冲突比认领单猜的更糟

认领单猜的是 `_clean` 下标含义冲突。**查下来 `_clean` 是一致的**（它一律表示层，
过线与实测由基符号承担），真的冲突在 **⟨k⟩ 本身**，而且是三重：

| 出处 | ⟨k⟩ 指什么 |
|---|---|
| `CLAIMS_TEXT.md` C2/C4 逐字文本 | 可评对数（实测） |
| `Theoria.md:357` / `PENDING_FIVE.md` §4.4 | 开发堆 U3 退出条件局数，k ∈ {1,2,3,4}，needs_human |
| `CLAIMS_TEXT.s4draft.md:68` 的 `FLI_⟨k⟩` | 前载指数百分位（`FRONTLOAD_K = 0.25` 早已钉死） |

`RECONCILE.md:454` 还专门裁定过「待定的 ⟨k⟩ 是开发堆退出条件局数」，
**即已经有一份冻结文档宣称自己占着这个符号**。`PENDING_FIVE.md` §4.4 甚至写了
「注意 k 与 ⟨X⟩ 不是同一个数」——它发现过一次冲突，却没发现更近的那一个。

`Theoria.md` 是冻结上游、它占着这个符号，**所以改名的是可评对数**：
⟨k⟩/⟨k_clean⟩/⟨k_drop⟩ → **⟨v⟩/⟨v_clean⟩/⟨v_drop⟩**。
另补 §4.4.6 把**下标约定**写下来（无下标 = claim 层、`_clean` = clean 层、
`_obs` = 实测、`_min` = 地板、`_drop` = 个数），并由闸门守着。
认领单给的两个选项是「改名」或「明写约定」——**两个都做了**，
因为单改名解决不了「下一个人怎么知道」，单写约定解决不了已经撞了的那个。

**一支没人调用的检查器就是一支红着且没人读的检查器。**

## 四、闸门抓住我自己四处，逐条照录

### 4.1 §4.4.2 的表我手算错了两格

初稿：终点三写 0.0039（应 0.0078）、⟨m⟩=19 写 0.0020（应 0.0039），都少算一位。
`tier_conj.py --verify` 一跑就红。
**两格都不改变第 1 行的结论**——所以它们是最坏的一种错：
不影响裁决，因此不会被任何人在读裁决时发现，而它们仍然是要发表出去的数字。
这也正是这支脚本存在的理由，写进它的模块 docstring 了。

### 4.2 我登记了一句错话，脚本当场打红

§4.4.2 初稿写「本条的裁决不依赖 §4.1.0 那个边界分歧——两式在 12 对上分别给
0.0078 与 0.0039，都 ≤ 0.0167」。**那句话只在我举的那个例子上成立，我把它写成了一般结论。**

`tier_conj.py` 算出真相：**n = 9 时两式给出相反的裁决**——
`> n/3` → ⟨v_clean⟩ = 6、p = 0.03125 **> 0.0167**（第 1 行触发 → 不可结论）；
`⌈n/3⌉` → ⟨v_clean⟩ = 7、p = 0.015625 **≤ 0.0167**（不触发 → 可以走到成立）。

**而 n = 9 是取得到的**：`claim_set.json` 现算 **⟨m⟩ = 16 → ⟨m_clean⟩ = 9**。
它看起来不存在，只因 **§2.2.1 的散文表只列了六个 ⟨m⟩**（5/10/12/13/14/19），
而 ⟨m⟩ 是 needs_human、范围 1..19。**15→8、16→9、17→10、18→11 这四个
在散文里从来没有出现过。**

于是这条从「残余项」升为**开跑前置条件 §9.22**：在 ⟨m⟩ = 16 上
**选哪个边界就等于选 C4 发不发得出来**，而两个边界都写在 §4.1.0 同一节里，
谁都可以在看到 ⟨v_clean⟩ 之后引用对自己更方便的那一个。
本条不替 §4.1.0 拍板选哪一个（两式严格程度不同，那是它的领地），
但把「这个分歧无害」这个借口取消掉。
`VERDICT_FLIPPING_N` 现在是脚本里的一个常数，`--verify` 断言它没漏。

### 4.3 §4.1.0 的两个边界本身（顺带发现）

散文写「剔除对数 **> 全部对数的 1/3**」，给终点二那句写「门槛按 **⌈⟨m_clean⟩/3⌉** 现算」。
**两式只在对数是 3 的倍数时分歧**（3、6、9、12、15、18），其余处处相等——
**所以它躲过了所有以 19 为例的检查**。19 恰好不是 3 的倍数。

### 4.4 我写的否定守卫打红了别人正确的散文

新加的否定守卫第一版直接匹配裸短语「两层一致」与 `family缩成两个`，
**当场把树打红三处，而那三处都是对的**：
「两层一致」在 §1.2（两次）与 C1（一次）的订正框里是**S4-E1-HOLES 留下的历史记录**，
而一条被撤回的规则是预注册的一部分；`family缩成两个` 那两处的原文是
「**不**因某个终点判了不可结论而缩成两个」——**守卫认字不认那个「不」**。

本仓已有的先例是「改我的措辞，不给守卫加引号豁免（豁免本身就是下一个钻法）」。
**但这次要改措辞的是守卫，因为它打红的散文是正确的**：
* 「两层一致」改成匹配它**被当作规则用**的形式（`两层一致(即|则|就|等于|便)`）；
* family 那条**改成正向探针** `*/family`——
  一条分不出「不 X」与「X」的否定正则比一条正向探针更糟，
  因为它会训练人去重写正确的散文。

两条都验过会红：种入「两层一致即成立。」与「配对终点只看 claim 层。」各打红一次。

| 探针／阶段 | 守什么 | 阴性对照 |
|---|---|---|
| `E2/conj` | C4 与 §2 都指向 §4.4.3 | `§4.4.3 → §4.4.9` 变红 ✓ |
| `E3/conj` | C2 与 §3 都指向 §4.4.3 | 同一变异，另一探针 ✓ |

| 阶段 `[17]` | §4.4 的三样算术 | 把 4.1 那个算错的 0.0039 装回散文表 → 变红 ✓ |

`E2/conj` 与 `E3/conj` **共用一个变异**，这是设计使然：两个配对终点指的是**同一个**
§4.4.3（一条规则一个家），所以不存在只碰到一个指针的变异。
写成两条而不是一条，是因为一条只能证明其中一个探针是活的。

另新增 scope `S4`（§4 的正文范围）——两层合成的裁定住在 §4，
既有的 `S1`/`S2`/`S3` 都框不住它。

**§9.21 值得单独说一句。** 它与 §9.18（`api_unusable` 臂可自制而 d 收它）、
§9.20（g 可被臂拧而它是「不成立」的唯一否决键）**同形，是第三例**。
三例同形说明它不是三次疏忽，而是一条系统性的东西：
**凡「没能测到」能软化一个不利裁决的地方，都必须先问那个「没能」是不是臂说了算的。**
这句话现在逐字写在 §4.4.4 与 §9.21 里。
