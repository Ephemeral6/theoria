## 4 · A1 — a machine-checked impossibility whose weights crossed a data boundary

### 4.1 What A1 was for

A1 is the framework's own acceptance item, and `Theoria.md` states it as a test of
plumbing rather than of insight:

> **A1 孔明棋**：孔明棋规格 → DSL → **LP 按钮式解出 pagoda 权重** → Lean 验封闭
> 引理，依赖假设为空。判死赌的是管线接通，不是 LLM 灵感；找不回，直接判死。
>
> — `Theoria.md`, Phase 1, 三件离线验收

("peg solitaire spec → DSL → the LP solves the pagoda weights at the push of a
button → Lean verifies the closure lemma with an empty dependency set. What the
kill-condition bets on is that the pipeline connects, not on LLM inspiration; if
it does not come back, kill it outright.")

An impossibility claim is the interesting case for a reason set out in
`Theoria.md` §1.5: it cannot be checked by exhaustion, because the paths are
exponentially many. The old method is to find a quantity that holds at the start,
that no legal move can break, and that winning would require breaking — "三个小
检查代替无穷穷举，检查量与状态空间大小无关" (three small checks in place of an
infinite enumeration, with a checking cost independent of the size of the state
space). Writing it in Lean replaces human checking of the three conditions with
machine checking of them, and forbids the proof from quietly leaning on an
undeclared assumption.

### 4.2 The chain, with the data boundary named

`theory-compiler/STATUS.md` records the accepted chain:

```
engine-rig/interop/certificates/pagoda_5_11011_to_00010.json
        ↓  (数据文件为界，不 import 对方代码)
theory_compiler.certificate   —— 不信 verified 标志，全部义务重新验算
        ↓
theory.dsl  invariant pagoda_potential pagoda(w) <= 0 [source: lp_potential]
        ↓
theory.lean  def w : Pos → Int | .p0 => -1 | .p1 => 1 | ...
        ↓
lean →  'inv_init' / 'inv_closed' / 'inv_all' / 'unsolvable'
        does not depend on any axioms
```

The two tracks do not import each other's code. A JSON data file is the entire
interface, and the consuming side does not trust the producing side's verdict:
the certificate carries `"verified": true`, and
`theory-compiler/src/theory_compiler/certificate.py` ignores it, re-deriving the
move geometry itself and recomputing all three obligations from
`weights_integer` alone (D-TC-009, `theory-compiler/DECISIONS.md`). A certificate
that merely omits a witness is rejected rather than covered for, because the
producer's own `verify()` re-does the arithmetic but never checks that the
witness list is complete, and the omitted move is exactly the one whose potential
might rise.

The weight vector that crossed the boundary is `[-1, 1, 0, 1, -1]`, solved by
`engine-rig/engines/lp_potential` and shipped in
`engine-rig/interop/certificates/pagoda_5_11011_to_00010.json` with six
`inv_closed` witnesses (deltas `0, 0, -2, -2, 0, 0`), `inv_init` value `0`, and a
`goal_break` witness giving `00010` potential `1`. The M8 rehearsal's weights were
`[1, 2, 3, 2, 1]`, hand-computed and typed in as literal constants (D4,
`theory-compiler/DECISIONS.md`); that is the transcription step A1 was meant to
delete, and the vector is different because a solver, not a person, chose it.
No `sorry`, no `native_decide`, and 83/83 tests pass, eight of which invoke `lean`
on the generated artefacts and read `#print axioms`.

### 4.3 The negative control

An empty axiom list is only evidence if it is a check that can fail. An
independent adversarial review — read-only, permitted to falsify but not to
confirm — ran that control. Changing `w .p1` from `1` to `7` made `lean` report
`decide proved ... is false`; all four theorems became
`depends on axioms: [sorryAx]`, and the exit code was 1
(`theory-compiler/STATUS.md`, 独立复核). The same review confirmed that
`gen_lean.py` contains no hard-coded weight vector and that the move set is
derived independently from the predictor, so the cross-check is not circular.

### 4.4 What A1 did not settle: E-06, an open problem

The manual's `goal count(Peg, alive) = 1` was **not** proved, and the pipeline
says so. From `11011` on the 5-cell board there are five singleton end states.
`lp_potential` yields a linear pagoda certificate for `01000` and `00010` only;
`10000`, `00100` and `00001` are pinned by engine-rig's own
`engine-rig/tests/test_interop.py` as *not provable by the linear pagoda method*
— `assert unprovable == [0, 2, 4]`, infeasible at every bound tried while the
control instances still get certificates. This is not a missing export. The
configuration is genuinely unsolvable — BFS gives reachable set
`{00111, 11100, 01001, 10010}`, minimum 2 pegs — but the invariant language
(linear arithmetic, counting, parity, finite weights) cannot carry the
conclusion. It is the documented incompleteness of the method, asserted by a test
so that a future "fix" has to argue for itself (D-014, `engine-rig/DECISIONS.md`).

The compiler's response is `CertificateGapError`: it **refuses to generate**, and
names the uncovered end states (D-TC-010, `theory-compiler/DECISIONS.md`). It does
not silently narrow the theorem into one that reads stronger than what was proved.
This is the headline of the section rather than its caveat. A pipeline that
declines to state what it cannot certify is the behaviour the framework is
arguing for; `theory-compiler/STATUS.md` books it as ledger entry E-06 and calls
it "本 sprint 唯一的开放问题" (this sprint's only open problem).

### 4.5 Limitations

Recorded verbatim in substance from `theory-compiler/STATUS.md`: **"空公理集"与
"证明规模线性"不同时为真** — an empty axiom set and a linear-sized proof are not
simultaneously available. The `computational` development gives an empty axiom
list at `O(2^n)`; the `algebraic` one is `O(n)` but carries `propext` and
`Quot.sound`, because in Lean 4.9 core every `Int` lemma it reasons through is
itself proved with `propext` (D-TC-008). On the 33-hole English board the former
is 2^33 and does not run. Both are honest — neither ever emits `sorryAx` or
`ofReduceBool` — but the trade-off is real. Further: the whole verification ran
on **one** 5-cell fixture, so the pipeline's generality is not supported by this
evidence. Two gaps the review found were fixed rather than argued away: the
enabling conditions of moves were never checked against the predictor and the
placeholder enumeration sampled only 5 of 32 states (D-TC-012, now 31/32), and
the solved weights still had to be hand-copied into the level file (D-TC-013, now
supplied by the certificate alone).

Finally, the 已清偿的债务 (settled-debt) table in `theory-compiler/STATUS.md`
closes the loop opened in §3.6: E-01 through E-05 from A0's expressivity ledger
are all discharged in `CONTRACTS/dsl_grammar_v0.2.md`, with the `semantics:`
frame-axiom clause now mandatory, and A0's manual parsed under v0.2 一字未改
(without a single character changed).
