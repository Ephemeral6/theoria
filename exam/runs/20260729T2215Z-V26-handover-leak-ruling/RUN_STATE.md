## 四、对抗复核推翻了本条的修正（cycle 83–84，最重要的一节）

派去打「修好的卷子干净了」这条结论的 subagent **找到了一条比被修的那条更锋利的判据，
而且量出我的修正把它变得更锋利**：

> 「B 画在板面最外圈 → 答 `none`」

两块死板的 box **落在字面上同一格 `(0,5)`**——`stile` 与 `cairn` 各自的
`start_box` 都是 `(0,5)`——而我补的两个状态 box 都在内部。于是这条切分
**从修前的 8/8、p_fire 0.035714，变成修后的 10/10、0.022222**：
按闸门自己的统计量，比本条要修的那条更锋利。已自行复现，不采信报告。

**差点当成第六条泄漏登记。它不是**，判决靠的是这张表：

| level | target | target 在外圈 | 外圈格数 | 其中存在可解 |
|---|---|---|---|---|
| `warren` | (4,2) | 否 | 26 | **0** |
| `kiln` | (3,5) | 否 | 22 | **0** |
| `stile` | (4,4) | 否 | 21 | **0** |
| `cairn` | (2,1) | 否 | 17 | **0** |
| `flume` | **(7,5)** | **是** | 25 | **2** |

外圈上的箱子只能沿那条边推，所以 target 不在外圈时它永远到不了。
这条规则的真假**随 target 的位置走**：在四个 target 不在外圈的板上成立，
偏偏在唯一 target 在外圈的板上失效。**那是对这个世界的推导，不是元数据预测答案**——
也正是 `leakage.METADATA_FIELDS` 刻意不含 `state`/`board` 的道理。

钉法是 `test_a_box_on_the_outer_ring_is_dead_for_a_reason_and_not_by_accident`，
钉的是**条件不变量**而不是纯度：任何贡献了「外圈 box」题目的 level，
它自己的 target 必须不在外圈；`flume` 当这条定律的**正对照**。
危险的未来改动不是「规则变得不纯」（不纯等于通道坏掉，那是好事），
而是「规则仍然纯、但不再可推导」——那才是泄漏，测试禁的是后者。
**第一版这条测试写松了**：它只断言了定律本身，我把 stile 的 target 挪到外圈做变异，
它照样 PASS。改成条件不变量之后才真的挡住那种改动。

**残留缺陷，真实且没修**：这份卷子**分不出**「读者查了 target 再推」与
「读者条件反射认定边上的箱子都死」——四个 target 恰好都不在外圈，两种读者都拿 10/10。
要关掉它需要一个**可解的外圈 box** 题目，而 **`stile` 与 `cairn` 上一个都没有**
（两块板每个 (player, box) 对都搜过，零个）。只有 `flume` 有，
而加 `flume` 题会破掉关闭第 4 条通道的 level 均匀性。
**所以这两条不变量在这五块板上无法同时加强**——这是板集的结构约束，写下来省得下一个人再搜一遍。
登记交出，不硬凑。

## 五、复核在本条自己的产出里找到两个缺陷，都已修

1. **认证这次修正的那条测试里有一句空断言。**
   `assert report.get("metadata_hits", 0) == 0`——`check_paper` **根本没有**
   `metadata_hits` 这个键（元数据命中它是 `raise`，能走到那一行就说明没命中）。
   于是这句断言对**任何**卷子都过，包括带着这条测试存在理由的那条泄漏的卷子。
   **这就是 V19–V25 追的那族缺陷，出现在其中一条的修正内部。**
   已换成断言「检查真的跑了、而且有可能说话」：`solvable` 被推出来了、
   `tags` 被扫了、`solvable` 至少一个分组 `can_fire_at_all`。
2. **修正给一份已经因饱和失效的卷子加了两道最容易的题。** 两个新状态都是
   `plan_len` 11、只需一次推，而其余可解题是 14–25 步、2–5 次推；模块 docstring 那句
   「These have 14 to 25」因此变成假的。但 11 **是这两块板的上限**（穷举搜过，
   6 行小板到不了 14），所以这个代价是被迫的、不是偷懒。docstring 已改成把代价说出来，
   并写明后续要加难题就加在 `warren`/`flume`/`kiln` 上、每个 level 两道。

**另有一条修正的副作用要直说**：这个题族的「绿」现在比从前值钱少了。
分组里不再有单持有者 `level:` token，池化私有标记切分**无可池化、在此族失效**；
同时 `solvable` 标签集的族错误率升到 **0.106281**（高于 `ALPHA` 0.05），
所以即使有 token 开火也会被标 `weak_evidence`。
通道关了、找到它的探测器也安静了——**这正是要靠性质测试
（`test_level_multiplicity_is_uniform`）而不是靠闸门绿的理由。**

## 六、尺度错误：判据是「族内唯一」而不是「整卷唯一」

复核同时指出 V25 的措辞错了一个尺度，已复现确认：`level:` 标记同样挂在
七道 `step_semantics` 题上，所以 r2 卷子的**整卷**计数是
`stile 1, cairn 2, flume 3, kiln 4, warren 5`——
**整卷版规则只在 `stile` 上开火、把 `cairn` 判成可解，是 7/8 不是 8/8**，
而 `cairn` 正是 `PREREGISTRATION.json` 预先指名「最锋利」的那块。
闸门本身从来没这个毛病（它按 `kind` 分组，一直算的就是族内版），错的只有散文；
而错的方向恰好会让读者去验错的规则、看到 7/8、于是断定这里没事。
已改三处：`exam/leakage.py` 的注释、`exam/STATUS.md` 的 V25 段、
以及本条自己 `_OPTIMAL_CASES` docstring 的第一版。
