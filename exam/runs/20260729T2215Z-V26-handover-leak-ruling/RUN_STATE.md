## 四、对抗复核推翻了本条的修正（cycle 83–84，最重要的一节）

派去打「修好的卷子干净了」这条结论的 subagent **找到了一条比被修的那条更锋利的判据，
而且量出我的修正把它变得更锋利**：

> 「B 画在板面最外圈 → 答 `none`」

两块死板的 box **落在字面上同一格 `(0,5)`**——`stile` 与 `cairn` 各自的
`start_box` 都是 `(0,5)`——而我补的两个状态 box 都在内部。于是这条切分
**从修前的 8/8、p_fire 0.035714，变成修后的 10/10、0.022222**：
按闸门自己的统计量，比本条要修的那条更锋利。已自行复现，不采信报告。

**差点当成第六条泄漏登记。它不是**，判决靠的是这张表：

| level | target | target 在外圈 | 外圈格数 | 其中存在可解 |
|---|---|---|---|---|
| `warren` | (4,2) | 否 | 26 | **0** |
| `kiln` | (3,5) | 否 | 22 | **0** |
| `stile` | (4,4) | 否 | 21 | **0** |
| `cairn` | (2,1) | 否 | 17 | **0** |
| `flume` | **(7,5)** | **是** | 25 | **2** |

外圈上的箱子只能沿那条边推，所以 target 不在外圈时它永远到不了。
这条规则的真假**随 target 的位置走**：在四个 target 不在外圈的板上成立，
偏偏在唯一 target 在外圈的板上失效。**那是对这个世界的推导，不是元数据预测答案**——
也正是 `leakage.METADATA_FIELDS` 刻意不含 `state`/`board` 的道理。

钉法是 `test_a_box_on_the_outer_ring_is_dead_for_a_reason_and_not_by_accident`，
钉的是**条件不变量**而不是纯度：任何贡献了「外圈 box」题目的 level，
它自己的 target 必须不在外圈；`flume` 当这条定律的**正对照**。
危险的未来改动不是「规则变得不纯」（不纯等于通道坏掉，那是好事），
而是「规则仍然纯、但不再可推导」——那才是泄漏，测试禁的是后者。
**第一版这条测试写松了**：它只断言了定律本身，我把 stile 的 target 挪到外圈做变异，
它照样 PASS。改成条件不变量之后才真的挡住那种改动。

**残留缺陷，真实且没修**：这份卷子**分不出**「读者查了 target 再推」与
「读者条件反射认定边上的箱子都死」——四个 target 恰好都不在外圈，两种读者都拿 10/10。
要关掉它需要一个**可解的外圈 box** 题目，而 **`stile` 与 `cairn` 上一个都没有**
（两块板每个 (player, box) 对都搜过，零个）。只有 `flume` 有，
而加 `flume` 题会破掉关闭第 4 条通道的 level 均匀性。
**所以这两条不变量在这五块板上无法同时加强**——这是板集的结构约束，写下来省得下一个人再搜一遍。
登记交出，不硬凑。

## 这一轮真正的教训

**修好一处「不可能失败的检查」，不会修好紧挨着它的那几处；
而且「我刚修好一处」的满足感正是让人停止再看的东西。**
本条的三条缺陷（B1/B4 各自，和 B3 那条被写下来阻止别人复查的假不可能）

两轮找到的东西没有重叠，这本身就是「交付前必须再打一次」的证据。
