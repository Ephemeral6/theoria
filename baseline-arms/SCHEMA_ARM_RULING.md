## 2. 本轮的新证据：那一列里唯一自称「实测」的格子，测不出来

`~10⁸(实测 2.04–3.41 亿)` 是整列里唯一一个声称有测量的数。
grep 全仓库，**这个区间的出处不存在**——`AUDIT.md` §1.2 早在开工时就把整行
登记为「占位符，没有任何数据、代码或账本」，但登记的是 `⟨复现值⟩` 那一格，
「实测 2.04–3.41 亿」被一路带过去了。

`harness/schema_column.py` 是第一次真去数它。方法与两个陷阱：

* **口径一（去重）**：Claude Code 会话日志里，每条 assistant 消息的 `usage` 在
  顶层记一次，又在 `usage.iterations[*]` 里重记一次。按 `message.id` 去重，
  只取顶层 `usage`。
* **口径二（朴素树遍历）**：把所有出现 `cache_read_input_tokens` 的 dict 全加起来。
  **这是错的口径**，之所以照算，是因为要回答「有没有**任何**口径能得出
  2.04–3.41 亿」，而答案是没有。
* 双计不是常数倍：run 间比值从 3.5× 到 4.6×，**所以不存在一个「改正系数」**
  （`tests/test_schema_column.py::test_dedup_matters_and_is_not_a_constant_factor`）。

## 3. 三条路，逐条定价

### 路 (a)：建复现臂

**第一道墙不是钱，是代码。** 「跑一遍上游 harness」的前提是有 harness，
而 `SCHEMA_LOCATE.md` §2.2 直接查 GitHub org API 确认它不存在。
这一道不是「贵」，是**不可能**。

**第二道墙是纪律。** 凭轨迹重实现一个 Schema-like agent，
工单纪律逐字禁止（「不允许凭训练记忆重新实现一个类似的东西冒充复现」），
且它有一个更硬的技术后果：要知道该实现什么，就得读上游的 `world_model.py`
与 `notes.md`——**而那些文件在 21 局封存游戏上也有，读了就等于把确认集烧掉**
（`piles.json` rule 2；INC-BA-001 已经因为**检索**这批发布物污染了 9 局）。
所以路 (a) 的重实现分支不是「贵一点的诚实」，是**把 Phase 3 的确认基础换掉**。

**第三道墙是钱，本轮第一次真算。** 就算前两道都被人工解开，
按 `proxy/pricing/pricing_v1.json`（`effective 2026-07-28`，
cache_read ×0.1、cache_creation ×1.25）对已测的 4 局 claude 侧计价：

| run | 模型 | 计价 |
|---|---|---|
| sk48 | `claude-fable-5` | $137.70 |
| tn36 | `claude-fable-5` | $124.30 |
| ar25 | `claude-opus-4-8` | $101.81 |
| g50t | `claude-opus-4-8` | $286.00 |
| **4 局合计** | | **$649.80**（均 $162.45/局） |

外推 25 局、**只一套采集**：**$4,061**。池中余额 **$143.50**——**差 28 倍**。
（这是下界：不含重试。本轨道实测每次成功动作平均约 5 次 HTTP，
jar-on 之后 1.97，`harness/unit_prices.py`。）

动作预算反而**不是**瓶颈：claude 侧 4 局 1,466 个 `action_taken`，

成为瓶颈」相反，值得记一笔。

**判：路 (a) 关闭。** 不是「以后再说」，是三道墙里有两道人工也解不开。

### 路 (b)：上游 artifacts 作已记录的非复现对照

**做得到，且已经在做**——`battery` 的 `schema_repro` 臂、论文 §7.2 的表。
它的**不足只有一处，但很重要**：这个方案没有回答
「那这一列还叫不叫『复现口径』」。留着列名，等于让每一次引用都要
临时否认自己的列名，而 §1.3 已经显示这个否认漏了两处
（臂名、`CLAIMS_TEXT.md:23`）。

### 路 (c)：删列，并重述 C1/C2/C5

**做得到，代价明确**：删掉的不只是一个空格子，还有那条
Phase 2 工序 1 指定的能力梯度——`Theoria.md` 要求每条候选指标必须在
「已知能力梯度（CC vs Schema）」上拉开差距，而 v2 唯一跑过的正是它，
`P3 是全电池唯一一条既在主表又在指定梯度上被验证过的指标`。
把这条一起删掉，是拿诚实换掉一个真实结果。

## 4. 裁决

> **删列，保行，改名，随处标注覆盖面。**

四条，逐条可执行：

**D-BA-023 (i) — 主表撤销「Schema（复现口径）」列。**
理由：那一列的列名承诺一个复现值，而复现在**代码不存在**的意义上不可能，
不是暂缺。占位符 `⟨复现值⟩` 撤销，不是留空——留空维持了「有一天会填」的预期，
而本裁决的内容正是「不会」。

**D-BA-023 (ii) — 同一批材料以 `schema_upstream` 保留为参照行，不进主表的臂列。**
它是**别人的账本**，跑在别人的外壳上；它不是本框架的第三条臂，
所以它不该站在「零分工 → 半分工 → 全分工」那条消融梯度里——
那条梯度的三格必须是同壳的。参照行另置，带自己的覆盖面栏。

**D-BA-023 (iii) — 臂名 `schema_repro` → `schema_upstream`（battery territory，走 inbox）。**
`repro` 这三个字母是 D-B-019 那次混淆的**残留物**，而残留物会再次被读。

**D-BA-023 (iv) — 缓存读格子：删「实测 2.04–3.41 亿」，代之以本轮可复算的读数与其口径。**
量级 `~10⁸` 留，括号里的区间删。替换文本见 §5。

**为什么不是纯 (b) 或纯 (c)：** 纯 (b) 保住了结果但保住了那个词；
纯 (c) 去掉了那个词但一起丢掉了工序 1 唯一的真实梯度。
被删的是**列**（一个身份主张：「这是我们复现出来的 Schema」），
被留的是**行**（一个材料主张：「这是上游在 4 局上的账本」）。
这两件事此前共用一个格子，这就是全部的病。

## 7. 残余缺口（诚实登记）

1. **本裁决改不了任何一个受影响的文件。** `Theoria.md` / `freeze/` / `papers/`
   都不属本轨道，§5 是提案。**在它落地之前，主表仍写着「实测 2.04–3.41 亿」**，
   而本轨道现在知道那个数没有出处。守卫只覆盖 `baseline-arms/*.md`——
   跨territory 的执行由人决定，不由本轨道代劳。
2. **缓存读只在 4/25 局、1/2 套采集上测过。** 25 局的量级是**外推**，
   本文不主张它。codex 那套采集的 4 个 run 完全没有 token 字段，
   所以「上游单局缓存读」这句话在它上面**没有真值**，不是 0。
3. **`98.98%` 未被本轨道核过。** 它是上游自报、25 局、我们只有 4 局，
   而其中 21 局按纪律永不可核。它只能作为**引用**存在，
   本裁决不改变这一点，也不给它加可信度。
4. **朴素/去重之外可能还有第三种口径。** 本文只能断言「我试的两种都不产生
   2.04–3.41 亿」，不能断言「不存在任何口径产生它」。
   若有人知道那个口径，`TABLE_CLAIM` 是一个常量，改它再跑即可。
5. **`score_trajectories.py` 仍未取**（`SCHEMA_PATH_A.md` §2.2），
   所以「冻结打分器原样接入」这条 Phase 1 铁律在 Schema 一侧仍未落实。
   本裁决不改变那个决定——取它应是一次单独的、有依据的决定。
6. **动作预算的方向与 Phase 1 预判相反**（钱先于动作成为墙，§3 路 a）。
