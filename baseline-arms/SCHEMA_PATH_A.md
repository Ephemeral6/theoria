## 3. 守卫：它长什么样，以及它第一次就失败了

`harness/fetch_schema_traces.py`，设计理由见 `DECISIONS.md` D-014。三条：

1. **正向白名单，默认拒绝**——不是「除非点名封存局否则下载」。
   反向名单遇到没预料到的路径形状会**开放失败**，而开放失败不可撤销。
2. **过滤只在文件清单（纯文件名）上做**，先于任何一次内容请求。
3. **下载器不解码、不打印、不总结任何下载物**。字节从 socket 到磁盘到 sha256，
   往上只回清单。

### 3.1 第一次执行：`allow = 0`，一个字节都没下

上游路径只写 **4 字符前缀**（`..._max_ar25_100.0`），从不写完整 pile id，
而当时 allow 分支只测完整 id——165 个本该下载的文件全被判成 `deny_unknown`。

**这正是想要的失败方向。** 执行下载的子代理照令停下并报告，
没有自行放宽白名单。修法是让 allow 与 sealed 共用同一个边界锚定的前缀正则
（`names_game()`），且 sealed 仍**先**判。

配套补上 `tests/test_whitelist.py`（19 例全过），覆盖三类真正会出事的情况：

* 全部 **21 个封存 id × 3 种路径模板**，前缀式与完整式都必须 `deny_sealed`；
* **前缀落在哈希中间**（`blobs/9ar25f0e/…`）必须**不**放行——边界锚定就是为它写的；
* **一条路径同时点名两堆**（`summary_ar25_ls20.json`）必须判 `deny_sealed`；
* 两堆的 4 字符前缀互不相同（前缀匹配只在这个前提下安全，所以它也是一条测试）。

### 3.2 执行纪律

下载由独立子代理执行，明令：不得用浏览器 / WebFetch / WebSearch 打开该数据集
（**检索过程本身就是 INC-BA-001 的事故源**），不得读取任何下载物的内容——
连开发堆的也不读，主上下文只接收清单与哈希。
**下载不等于阅读**：只要没有任何模型读过那些字节，封存纪律就还在。

## 5. 这批材料入库的形态

载荷 **不进 git**，`MANIFEST.json` **进 git**（`DECISIONS.md` D-013）。
两个理由同向：上游**未声明许可证**，而 `Theoria.md` Phase 4 的释出清单会公开全部
tracked 文件——把一份没有许可证的第三方数据 commit 进来，等于替它决定了可再分发性；
而账本真正需要的是「我们用的是哪一份材料」，那是 revision sha 加逐文件 sha256。

重建方式：

```bash
cd baseline-arms && python -m harness.fetch_schema_traces
```

比对 `MANIFEST.json` 的 `payload_sha256` 即可确认拿到的是同一份。

说清楚这个区别很重要：路 A 拿到的是**上游的账本**，不是**我们的复现**。

而这正需要同样 4 局上两条臂的轨迹：CC 侧由本轨道的战役产出，Schema 侧由本轮产出。
**这两半现在都有了。**

它不足以、也永远不足以填 `⟨复现值⟩`——那一格要的是「我们跑出来的分数」，
而我们跑不了。用上游的 98.98% 冒充复现值，比空着更糟。
