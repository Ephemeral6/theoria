## 措辞里刻意收紧的两处（不收紧就是把错误反向再犯一次）

**一 · `level_baseline_actions` 不是下界。** `theoria-arm/inner/scoreboard.py`
写得很清楚：它是参考解法走过的动作数，「**不是**下界，超过它正是整件事的目
的，所以这里没有任何一句话说某关不可达」。因此可写的是「没有给到足以期待通
关的预算」，**不可**写成「通关在结构上不可能」。工单原文的「设计保证的结果」
一句要降级为推断。核对器把那一档命名为 `budget_below_level_1_baseline`，不叫
impossible。

**二 · 「没有任何一条 run 被允许走到基线」只对已归档的 43 条成立。** ar25 有
一张卡走到 **67**（基线 32），tn36 有卡走到 **32**（正好等于基线），g50t 最好
一张 **73** 对 78——很近，仍然没到。

原因**不是**「卡跨 reset 累计动作」（初稿这么写，是错的：这六条观测的
`resets` 全部为 **0**，什么都没跨）。原因是 2026-07-27 m4 试点期有 **16 条**
run 花掉超过 30 个动作，而它们**一条都没归档**——在 budget 层看不见，在卡层
看得见。所以：
* 「g50t 上没有任何一条基线 run 走到过 78」——**真**；
* 「没有任何一条基线 run 被允许超过 30 个动作」——**假**（16 条 m4 试点期的
  run 超过 30，最高 73，它们只活在 ledger 与 probe log 里，没有 `run.json`）。
核对器两层都打印，措辞不能在这上面含糊。

## 欠项三：一条给足动作的基线对照，明码标价（本件不执行）

工单按 opus 单条 $3.441054 / 30 动作 = $0.1147/动作，估 78 动作约 $8.95。
该单价复算无误，且**恰是 opus 五条 run 的中位数**（不是挑出来的），但五条的
极差是 1.74×，且另有两条 opus run 花了钱买到 **0** 个成功动作，中位数看不见
它们。所以本件把价格改报为区间与合计口径（`harness.audit_claim_14` 第四节
自动算，不写死）：

**按 (局 × 档) 逐格算，不是按档池化算。** 初稿的表按档算价、却按「局 × 档」
标行，于是同一档的每一局都拿到同一个数，还给一个「该档在该局上零成功动作」
的格子报了价。逐格重算（`harness.audit_claim_14` 第四节自动出，不写死）：

| 局 × 档 | 到基线所需动作 | 该格 $/动作 | 一条的价 |
|---|---|---|---|
| ar25 × haiku | 32 | 0.0503 (4 run/59 动作) | **$1.61** |
| tn36 × haiku | 32 | 0.0476 (7 run/111 动作) | **$1.52** |
| sk48 × haiku | 61 | 0.0484 (4 run/96 动作) | **$2.95** |
| g50t × haiku | 78 | 0.0384 (5 run/134 动作) | $3.00 |
| ar25 × opus | 32 | 0.1858 (1 run/7 动作) | $5.94 |
| sk48 × opus | 61 | 0.1292 (2 run/40 动作) | $7.88 |
| g50t × opus | 78 | 0.1121 (2 run/44 动作) | **$8.74** |
| g50t × sonnet | 78 | 0.1293 | $10.08 |
| sk48 × sonnet | 61 | 0.1930 | $11.77 |
| tn36 × opus | 32 | — | **不可得**：2 条 run 花了 $1.8815，买到 **0** 个成功动作 |
| ar25 × sonnet | 32 | — | 不可得：1 条 run 花 $0.0823，0 个成功动作 |

工单的 $8.95 是「opus 档中位数 × 78」；逐格算 g50t × opus 是 **$8.74**。两者
都不离谱，但要报就报逐格的那个。

## 关于「买哪一格」——初稿的推荐是错的，此处撤回

初稿推荐 `sk48 × haiku ≈ $2.75`，理由是「ar25/tn36 上卡已走到过基线且仍 0 分，
那两局的实验已部分做过」。**这个理由不成立**，四处：

1. 那六条走到基线的卡**全部是 haiku**。初稿一边说「这两局已有答案」，一边又
   推荐「那就买 opus 档的 32 动作」——而 opus 在这两局上根本没跑过足预算的
   run。「已经做过」和「换个档再做」不能同时当理由。
2. tn36 的两条是 `actions == 32 == 基线，正好相等`。从「花掉的动作数等于参考
   解法的动作数」推出「答案是没赢」，正是本文件第一条禁止的那个错误——
   `scoreboard.py:432`：它**不是下界**。
3. 推荐本身重犯同一个错：把 sk48 的预算定成 **61 = 基线**，等于要求模型一步
   不多地追平参考解法。若问题是「给足动作能不能赢」，61 按本文件自己的逻辑
   就**不算给足**。
4. m4 试点期那些 run 是另一代 harness（2026-07-27，早于 D-015，无 `run.json`）。
   本文件的每一个分母都把它们排除在外（「43 已归档」），却又拿它们当决定性
   证据。两者只能取一个。

**改成这样**：最便宜的一格是 **tn36 × haiku ≈ $1.52**（基线 32，该格 7 条 run
共 111 个成功动作，单价最扎实）。但预算必须**高于**基线而不是等于——取
2× 基线（64 动作）约 **$3.05**，才是「给足动作」的诚实读法。若要 opus 档，
tn36 上不可得（零成功动作），退而取 **ar25 × opus，2× 基线 64 动作 ≈ $11.89**。

无论买哪一格，**$1.52–$11.89 这个量级仍比 A26 的 $120 便宜一到两个数量级**，
这一条结论不受上面任何一处订正影响。
