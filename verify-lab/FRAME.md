# 抽样框 —— 先定义总体，再谈覆盖率

V14 交付了一个空结果：对抗复核抓到一个解析缺陷，同时制造跨赛道假阳与假阴，
修完之后**混淆矩阵一格没动** —— FP 3 / FN 20 与修前一模一样。

原因不在探针，在分母。V14 的矩阵算在 V11 普查的 103 行上，而探针跑在 141 个入口上；
**141 里有 74 个 V11 从没判过**，而复核员确证的那个假阳恰好落在那 74 个里。

> 一份金标准只覆盖总体的一半，就无法证伪集中在另一半里的缺陷。

更根本的问题是：**没有人定义过总体。** V11 的 127 是六个普查员各自扫出来的**并集**；
V14 的 141 是一条启发式的输出，而那条启发式自己的报告写着漏 26%、多收 ≥17。
两个互相重叠的方便样本，没有抽样框。

`verify-lab/frame/frame.py` 是那个抽样框。

```bash
python verify-lab/frame/frame.py            # 计数
python verify-lab/frame/frame.py --list     # 只出路径，不出任何判定
python verify-lab/frame/reconcile.py        # V11 的 127 与 negctl 的 141 按新定义对账
python verify-lab/frame/matrix.py           # 重算混淆矩阵
```

## 1. 定义

**验收入口**是本仓库中满足下面两条的一个单元：

1. **是被发布的** —— 被 git 跟踪，属于仓库交出去的东西，而不是谁磁盘上的草稿；
2. **是一个验收单元** —— 人或者某个 harness 能调用它，或者它的拒绝能到达这样一次调用。

**就这两条。特别地，它不要求这个单元有能力失败。**

### 为什么「能不能红」不是成员资格

因为那是三问里的第一问。一个只收「能红」的总体，永远数不出一个「不能红」——
而「否」正是 V11 给出过 15 次的答案：`release/checklist.py`、`release/reproduce.py`、
`cold-start-a3/run_all.py`、`theoria-arm/harness/run.py`，全是名义上的闸门，
判决到不了退出码。那些行是 V11 被引用最多的发现。

V14 的枚举器要求非零退出路径（`probe.py: has_main_block and can_exit_nonzero`）。
于是**整整一类死闸对它结构性不可见**：它报得出「新闸没有负控」，报不出
「某个闸不再能失败了」。那和那 74 个入口是同一个缺陷，只是高一层。
在这里重复它，会让这个抽样框没有能力审计它被写出来要审计的东西。

所以 `can_refuse` 在这里是**一列**，算出来、发布出来，从不做筛子。

### 三个分层

| 分层 | 是什么 | 数量 |
|---|---|---|
| **A 可调用** | tracked、非测试的 `.py` 且有 `if __name__ == "__main__"`；或 tracked、非测试的 `.sh` | 190（183 py + 7 sh） |
| **B 终止性拒绝库** | 不在 A 里，抛一个仓库自己定义的 `Exception` 子类，被至少一个 A 层文件 import，且该异常在它自己以外的任何非测试文件里**无人 catch** | 34 |
| **C 测试套件** | 每个直接含 `test_*.py` 的目录算一个 | 17 |
| | **合计** | **241** |

（本文档的计数取自把 `frame.py` / `reconcile.py` / `matrix.py` 自己也纳入之前的那一版；
纳入之后是 243。抽样框把自己数进去是对的 —— 一个豁免自己规则的探针，正是它在找的病。）

**分层 B 为什么必须存在。** 它装的正是 V11 最锋利的那几个发现所在的类：
`proxy/guard.py`、`exam/leakage.py`、`battery/guard.py` 靠抛异常拒绝，压根没有 `__main__`，
而 V14 的枚举器对这一整类是瞎的。一个省掉分层 B 的抽样框，就是**为了让枚举器显得已标定
而划出来的抽样框** —— 也就是这个条目存在要抓的那种造假。

**分层 C 为什么必须存在。** V11 数过它们：127 行里有 12 行是 `python -m pytest` 或
`pytest <dir>`，不指向任何文件。按本仓库自己的说法它们就是验收入口 ——
`arc-recon/verify.sh`、`monitor/verify.sh`、`exam/verify.py` 都把某个套件当一步来跑并读它的退出码。
丢掉它们，就是悄悄扔掉正在被审计的那份金标准的 12 行。

### 三个标记：标注，不是排除

每一次排除都是缺陷能躲开审计的地方，而 V15 的全部发现就是
**一个没人检查过的排除，正是缺陷所在的地方**。所以这里只标注：

| 标记 | 含义 | 数量 |
|---|---|---|
| `frozen` | 在 `runs/<id>/` provenance 目录下的一次性脚本。是真入口（`a0-spike/runs/.../make_manifest.py --verify` 在 V11 普查里，是一道真的字节闸），但不该累积义务：一个每建一个 run 目录就变红的常驻探针会被关掉。**报告，不设闸。** | 15 |
| `generated` | 编译产物。它会抛是从生成器继承来的；闸是生成器。 | 0 |
| `unparseable` | 被跟踪、但**解析不了**。**收进来，不是跳过。** | 1 |

`unparseable` 这一格现在只有一个成员，而它值得单独说：

> **`release/checklist.py` 自提交 `fa59795` 起就在字符串字面量里带着一个裸换行，
> `import` 它会抛 `SyntaxError`。V11 的普查记录着实测它 `7 present, 3 withheld, 0 absent`、
> `exit 0`。**

`negctl/criterion.py` 与 `probe.py` 都在一个裸 `except` 里吞掉这个解析失败，于是这个文件
悄悄离开了它们的总体。这就是一个抽样框长出没人看得见的洞的方式，所以它在这里是一列。
（`release/` 不是本条目的领地，只报不修。）

### 这个抽样框仍然看不见什么 —— 先说清楚

* **函数粒度。** 单元是文件。`worldgen/build.py` 里一个闸有负控、另一个没有，只数一次。
  这是 V14 `_a_file_level_present_is_not_a_promise` 那条限制的原样继承，没有修。
* **import 按文件名主干解析。** 分层 B 的「被某个 A 层文件 import」是按模块 stem 匹配的，
  在一个有四个 `verify.py` 的仓库里会过度连接。这是**故意选的宽松方向**：
  V15 在修的错误是一次排除，所以分层 B 宁可多收。
* **算判决但从不拒绝的模块。** `theoria-arm/armtools/archive.py` 算四项义务、
  每一项都写进 MANIFEST，不抛、不返回非零。它进分层 A 纯粹因为它碰巧有个 `__main__`。
  同样形状但**没有** `__main__` 的模块，对这里的每一层都不可见 ——
  而 V11 是靠人读出来的。目前没有任何机械规则接得住它。
* **可达性是语法层面的。** 一条永远不成立的条件后面的 `return 1` 照样算 `can_refuse`。

## 2. 对账：V11 的 127 与 negctl 的 141

```
抽样框                        241 个单元
V11 普查                      127 行 →  107 个单元（44.4%）
  其中不指向任何单元的行         12
negctl 的钉子                 141 条路径 → 140 在框内（58.1%），1 在框外
差集（框 减 V11）              134（分层 A 101，分层 B 27，分层 C 6）
在 V11 里但 negctl 没钉        37
negctl 钉了但 V11 没判         70
```

### V11 漏了什么

**134 个单元（56%）。** 按领地：monitor 14、baseline-arms 13、theory-compiler 13、
cold-start-a0/a2/a3 各 12、engine-rig 11、exam 6、figures 6、ablation-arm 5、
papers 5、worldgen 5、arc-recon 4、proxy 3、fuzzlab 2、theoria-arm 2、a0-spike 1。

这不是随机的缺口。它有形状：

* **整片新territory没进普查** —— `monitor/` 的 14 个入口一个都没被 V11 判过，
  而 `monitor/` 是给别人的闸门评级的那套东西。
* **每条流水线的中间步骤都缺** —— V11 判了 `cold-start-a2/run_all.py`，
  没判它调用的 12 个 `a2pipeline/*.py`。而退出码的诚实性恰恰是逐步骤的。
* **图脚本只判了聚合器** —— V11 判了 `figures/build_all.py` 与 `verify.sh`，
  没判 fig02–fig07 本身。

### V11 多收了什么（12 行不指向任何框内单元）

不是错误，是**粒度**：`battery/metrics/*`（一个 glob）、
`battery/audit/{gaming,validation,...}.py`（一个花括号展开）、
「battery 的一条命令总闸」（**不存在的东西**，V11 正确地把它记成缺席）、
`release/bundle.py --check`（同样不存在）、
`proxy/scoring/`（一个目录）、`proxy/redact.py` + `proxy/ledger.py`/`canon.py`
（一行判两个文件）、`fuzzlab/tests/test_*.py::<函数>`（三行判到函数粒度）、
`theory-compiler/conftest.py` 与 `exam/grading/selftest.py`（被 `is_test_file` 排除）。

**一条不能忽略的：V11 判了「不存在的闸」，抽样框判不了。** 一个只能枚举磁盘上有的东西的
抽样框，永远数不出「本该有一个闸，而它不在」。V11 的两行正是那个形状，
而那是人能给出、机器给不出的一类发现。

### negctl 漏了什么、多收了什么

* **漏 101 个** —— 框内 241 个单元它枚举 140 个。三类：
  分层 B（27 个终止性拒绝库，它压根不看）、分层 C（17 个测试套件，它压根不看）、
  以及**没有非零退出路径的 A 层文件**（`can_refuse=False` 的 42 个中的大部分）——
  最后这一类是它的枚举器按定义排除的，也就是「死闸」这一整类对它不可见。
* **多收 1 个** —— `monitor/tests/mutants.py`，一个测试文件。
  它就是 V14 论据 4 里点名的那个：一整套变异测试台，被枚举成闸门，
  又被钉成「缺负控」，正好反了。

## 3. 补齐的金标准

`verify-lab/SUPPLEMENT_TABLE.md`：差集里 **126 个**入口的人工判定，
判据与 V11 逐字相同，九个判定员并行，**全部盲于探针**（做法与破口见
`runs/20260729T120000Z-V15-census-sampling-frame/BLINDING.md`）。

差集是 134，判了 126，差在：
* 6 个分层 C 单元 —— 测试套件。negctl 一个都不打分，判了也不会动矩阵一格；
  这是**声明的缺口，不是沉默的缺口**。
* 2 个 `verify-lab/negctl/probe.py` 与 `criterion.py` —— 判它们就要读它们，
  而读它们正是盲判禁止的事。

计数：

```
补齐入口总数：126
能红：      是 79 / 部分 44 / 否 3
有负控：    是 34 / 部分 15 / 否 77
退出码诚实：是 32 / 部分 13 / 否 36 / 不适用 45
实测支撑的行：0 / 126
```

**「有负控 = 否」占 61%**，比 V11 的 28%（35/127）高一倍多。
这不奇怪，也正是抽样框存在的理由：V11 的六个普查员各自先扫到的，
是自己领地里最显眼、最像闸门、也最可能有人写过测试的那些。
**便利样本系统性地偏向已被覆盖的一侧。**
