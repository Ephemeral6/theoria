# 判定员间信度 —— 这份金标准从来没有过信度证据，现在有了，而它不好看

V15 交付时点了下一步：17 个新增 pinned 假阴里有 **10 个是 `部分`**，而 `部分` 正是
判定员用得最不一致的那一格。V15 的敏感性分析证明了总体定义不是为好看划的
（12 个变体、总体 84↔260、pinned 矩阵逐格不变）。**但那证明的是「线划在哪不影响结论」，
没有证明「同一条线上不同的人会判成一样」。**

这一条量后者。

```bash

python verify-lab/irr/overlap.py     # 有没有两个判定员判过同一行

python verify-lab/irr/refold.py      # 重判后 pinned 矩阵动多少
python verify-lab/irr/shapes.py      # 同形状不同格的几对，人工配的
```

判据本身：`verify-lab/PARTIAL_CRITERION.md`。
盲判怎么挡的、哪些没挡住：`runs/20260729T180000Z-V17-pin-the-partial-verdict/BLINDING.md`。
**先读那一轮的 `ADVERSARIAL.md`。**

## 1. 重叠行：零

`overlap.py` 把 V11 的 127 行与 V15 的 126 行按判定员索引开
（V11 的判定员就是它总表里的 `领地` 列，20/19/14/10/32/32 = 127；V15 的是 `批次` 列 b1–b9）。

```
corpus            253 rows, 15 judges, 233 distinct .py/.sh paths
inter-judge overlap  0 paths
intra-judge repeat   12 paths
```

**十五个判定员，两百五十三行，没有任何一条路径被两个判定员判过。**
这不是解析器的毛病，是设计：V11 按领地切分，V15 取抽样框的**补集**。
两轮都是为「不重叠」造的。

那 12 条 intra-judge 重复是**同一个判定员**在同一份分表里判了同一个文件两次，
而且是**故意**的粒度差异 —— `worldgen/build.py --check` 判 `是`、
`worldgen/build.py::check_determinism` 判 `否`。V14/V15 的矩阵按行计分正是为了留住这种冲突
（`matrix.py::gold_v11` 的 docstring 写了：塌成一个文件一格，公布的 FP 3 会变成 0，
「那 3 个就是那些冲突」）。所以它们不是信度证据。

> **结论：这份金标准在今天之前从来没有过任何信度证据。**
> V11、V14、V15 三轮的每一个数字，都建立在「判定员之间会判成一样」这个从未测过的假设上。

所以第 2 件之前必须先造重叠。造了。

## 2. 怎么造的

22 行，分三层（`sample.py`），六个判定员，两条臂：

| 臂 | 判定员 | 拿到的 |
|---|---|---|
| `old` | O1 O2 O3 | **V11 的第二问逐字原文**，外加一句「`部分` 没有进一步定义，自己划线」 |
| `new` | N1 N2 N3 | `PARTIAL_CRITERION.md` 全文 |

两条臂都另外回答**第一问「能红」**。判据对第一问只字未提 ——
**它是安慰剂列**。如果新判据组连它也更一致，多出来的一致就不是判据，是六个体读了同一份
文件的趋同。

样本分层是这一条不能省的部分：只重判 `部分` 行会答错问题 ——
一条只准往外搬、从不往里搬的判据，必然提高一致率，因为空格上的一致是白送的。
所以 14 行 `部分` 之外，另有 4 行 V15 判 `是`、4 行判 `否` 作对照。

盲判：`git ls-files` 逐条复制，按前缀删掉 290 个文件
（`verify-lab/` 64、`monitor/board/` 76、`monitor/inbox/` 62、`PARTNER_SYNC.md` …），
2287 个进树。导出后重测：22 条被判路径里 **4 条**仍出现在一份谈负控的文件里，
**0 条**出现在带本实验室判定词汇的文件里。V15 的实测是 29/126、其中带判定词汇的若干。
细节与三件挡不住的事在 `BLINDING.md`。

派单前提交了 `PREREGISTRATION.md`（commit `4a47472`）：判据作者自己对 22 行的干读，
钉在时间线上，不给任何判定员看。

## 3. 现状：`部分` 这一格测出来是不可靠的

`old` 臂是纯粹的重测信度 —— 三个新判定员，V15 自己的判据逐字，V15 自己的行。

| | n | 一致率 po | Fleiss κ | 全票一致 |
|---|---|---|---|---|
| `old` 有负控，全部 22 行 | 22 | 0.848 | **0.764** | 17/22 |
| `old` 有负控，**`部分` 层 14 行** | 14 | 0.810 | **0.689** | 10/14 |
| `old` 能红（安慰剂） | 22 | **1.000** | **1.000** | 22/22 |

**安慰剂列满分，第二问 κ 0.764。** 同一批人、同一棵树、同一天：
「这个文件能不能红」三个人从不分歧，「有没有人演示过它红」三个人分歧了 5 行。
不一致不是判定员的水平问题，是那一问的判据不够。

更硬的一个数：**`old` 臂的多数票只在 6/14 行上重现了 V15 公布的 `部分`（43%）。**
全部 22 行上是 13/22（59%），而 8 行对照层里对上了 7 行。
**V15 的 `是` 和 `否` 基本重现得了，`部分` 重现不了。**

这就是工单要的那个答案：`部分` 是九个判定员用得最不一致的一格，量出来了。

## 4. 写死判据之后：一致率**没有显著提高**

| | `old` κ | `new` κ | Δκ | 95% CI（20000 次逐行 bootstrap） |
|---|---|---|---|---|
| 有负控，全部 22 行 | 0.764 | 0.882 | **+0.118** | **[−0.109, +0.330]** |
| 有负控，`部分` 层 14 行 | 0.689 | 0.770 | **+0.078** | **[−0.533, +0.415]** |
| 能红（安慰剂） | 1.000 | 0.872 | −0.124 | [−0.306, +0.000] |

原始一致率确实涨了（`部分` 层 po 0.810 → 0.905，全票一致 10/14 → 12/14）。
**但经过机会校正、按行 bootstrap，两个区间都大幅跨零。**
在这一格上，`P(Δκ ≤ 0) = 0.348`。

> **照实说：这条判据没有把判定员间信度显著提高。**
> 工单写着「一条写下来但没提高一致率的判据，等于没写」——
> 按这个标准，本轮**没有**证明这条判据值得写下来。n = 14 行、每臂三个判定员，
> 本来也不够分辨 0.08 的 κ 差；这是设计的功率不足，不是结果的噪声。

**安慰剂列的方向倒是清楚的：它跌了。** 新判据组在判据只字未提的那一列上比对照组
**更不一致**（1.000 → 0.939，CI 上界 0.000）。所以「一致率的改善来自趋同压力」这条指控，
在能测到的范围内**不成立** —— 读了同一份文件的三个人，在文件没管的问题上并没有更像。
反过来读也成立：判据把注意力从第一问上引开了，这是它的代价，不是它的收益。

## 6. 判据自己的账，比它判的东西还不齐

判据不把分歧藏起来的唯一凭据，是**理由码**：离开 `部分` 的行带着
`D0`（没有拒绝路径）/`D1`（没执行）/`D2`（没断言）/`D3`（打的是别处），
于是任何人都能在任一处重新折叠，不必重判。

**实测这本账比它记的判决更不一致：**

```
判决一致率        po = 0.939   全票 20/22
理由码一致率      po = 0.773   全票 15/22
```

七行分歧，其中四行是同一个病：`D0` 与 `D1`/`D2`/`D3` 同时成立时判据没说谁优先。

```
SPLIT monitor/ci_merge.py                       D1/D0/D1
SPLIT monitor/reflex.py                         D1/D0/D1
SPLIT monitor/scan.py                           D3/D0/D2
SPLIT papers/…/fig2_coverage_accuracy.py        D1/D0/D1
SPLIT ablation-arm/exhibits/e2_a2.py            D2/D2/D3
SPLIT cold-start-a2/a2pipeline/exhibit.py       D3/D3/C
SPLIT engine-rig/recheck/verify_all.py          D2/D2/C
```

三个判定员各自在自己的 `## 判据打不中的地方` 里独立抓到了同一处，
并且给出了它的代价：N1 说，按 `D0` 的字面，`ci_merge.py` 与 `reflex.py`
会一起进 gold-negative，而**它们的「负控」分别是源码 grep 和 AST 断言 ——
恰恰是这份普查最该记下的东西**，塞进 `D0` 就抹掉了。

判据还被抓到**自相矛盾**：N2 指出判据 §3.3 把 `transfer.py` 判 `部分`
靠的是一句同样属于「转手」的赋值，而三个判定员对 `certify_a3.py` 的
`否(D3)` 用的正是「转手不算」——**3.3 与那一行不能同时对**。
这一处按对抗复核的结论处理，记在 §8。

## 7. 它对 V15 那个数字的影响

把 22 行重判结果代回金标准（其余 231 行不动），`refold.py`：

```
strict pinned  before  n=145  TP 35  FN 36  FP 1   TN 73   FNR 0.507
strict pinned  after   n=145  TP 34  FN 28  FP 2   TN 81   FNR 0.452
harsh  pinned  before  n=145  TP 26  FN 18  FP 10  TN 91   FNR 0.409
harsh  pinned  after   n=145  TP 25  FN 18  FP 11  TN 91   FNR 0.419
```

**22 行（253 行的 8.7%）改判，就把 V15 的头条从 0.507 挪到 0.452。**
V15 自己的对抗复核把那份补齐的净贡献算作约 11pp；
**其中约 5.5pp 押在 `部分` 这一格怎么读上。**

`harsh` 几乎不动（`部分` 本来就按「没有」折），这是符合预期的，也是这个数可信的旁证。

**这不是新头条。** 22 行、三个判定员、一条判据，改的是一个方向对被测者有利的方向
（假阴变少），而信度改善又不显著。**在此基础上重新公布任何 FNR 都是不诚实的。**

## 8. 这一轮没做到的

* **判据没有被证明有效。** §4 的区间跨零。要分辨 0.08 的 κ 差，
  按同样的方差量级需要的行数是本轮的好几倍。这是功率问题，下一条要么扩样本要么放弃。
* **理由码这本账不可用**（§6），而它是「没把分歧藏进别的格」的唯一凭据。
  判据必须先规定 `D0` 的优先级、补上 `C` 对「一行直转的 main」的裁决、
  并解决 §3.3 与转手层的矛盾，否则这本账记不准。
* **判定员是同一个模型的六个实例。** 相互独立，但不是六个人。跨模型信度没测。
* **只读约束是指令级的**，没有沙箱强制（`BLINDING.md` §3.1）。
* **`部分` 只重判了 14 行中的 14 行，`是`/`否` 各只重判了 4 行。**
  对照层太小，「判据有没有把分歧挤进 `否`」这个问题，本轮只能定性回答。
