# 盲判记录 —— 挡住了什么，没挡住什么

V15 的盲判是 `git archive HEAD` 减去 `verify-lab/`，然后被它自己的对抗复核抓到：
`PARTNER_SYNC.md` 被跟踪、在仓库根、在每个判定员的树里，第 940/958 行载着 V11 的总计
（`有负控「否」35`）、V14 的 `FNR 32%`，以及 pinned 矩阵里唯一那个假阳的逐文件判定。
实测 126 条判定路径里 **29 条（23%）**出现在这类文件中，曝光组 present 率
**0.55 对 0.34**（p = 0.055）。**那个泄漏面就是 RES-3 每次交付往 `PARTNER_SYNC.md`
追加的段落**，也就是我自己。这一轮的责任是不重蹈。

## 1. 怎么挡的

`verify-lab/irr/blindtree.py` 从 `git ls-files` 逐条复制，**按前缀名单**删除。
前缀名单是名单，不是内容过滤器 —— 一个读者拿 `git ls-files` 就能复核它，不必跑任何东西。

```
2287 个文件进判定树，290 个被删：
    76  monitor/board/          工单本身（V11/V12/V14/V15/V16 的题面与结论）
    64  verify-lab/             探针、判据、钉子、V11/V14/V15 全部报告
    62  monitor/inbox/          交付回执
    28  monitor/bus/            RES-3 的出站消息（`out.jsonl` 含「负控/混淆矩阵」）
    23  monitor/audit/          DRIFT 记录（含一份标题就叫
                                "a1-probe-can-only-ever-say-partial" 的）
    19  monitor/ci/             CONFLICT-*v11/v14* 合并冲突记录
    16  monitor/mailbox/
     1  PARTNER_SYNC.md         ← V15 的破口
     1  monitor/state.json
```

判定员另外拿到的只有 `PARTIAL_CRITERION.md` 的一份副本（新判据组三人），
以及 22 条路径。**没有任何判定员拿到 V11 或 V15 的任何一格。**

## 2. 没挡住什么 —— 实测，不是断言

`blindtree.py --sample` 在**导出后的树上**重新搜一遍 22 条被判路径：

```
22 条被判路径中，4 条仍出现在一份「谈负控」的文件里
22 条中，0 条出现在一份带本实验室判定词汇的文件里
   （判定词汇 = 有负控 / 退出码诚实 / 混淆矩阵 / KNOWN_GAPS / FNR / 负控普查）
```

四条残留，逐条：

| 路径 | 出现在 | 是什么 |
|---|---|---|
| `exam/model.py` | `papers/phase1-workshop/PAPER.md` | 论文 §4.3 讲 A3 自己的负控，不是本实验室的判定 |
| `exam/papers/handover.py` | 同上 | 同上 |
| `monitor/quota.py` | `monitor/runs/…S1-quota-auto-exit/MANIFEST.json` | 一次 run 的清单 |
| `monitor/reflex.py` | 两份 `arc-recon/runs/…/RUN_STATE.md`、一份 `live_concurrency.txt`、上面那份 MANIFEST | run 叙述 |

**这四条是留下来的，不是漏掉的。** 删掉 `papers/` 与 `runs/` 就等于删掉判定员本该权衡的证据 ——
一份描述「本仓库真的跑着某个负控」的文档，正是第二问要找的东西。
判据把它写死了：**答案键删，领地证据留。**

## 3. 挡不住的三件事，写在这里

1. **只读约束是指令级的，不是强制的。** 判定员被告知只许读导出树、不许读
   `C:\Users\user\Desktop\theoria\`。没有沙箱强制这一条。如果哪个判定员越界了，
   我不会知道，除非它自己写在报告里（提示词要求它写）。
   **这是本轮最大的一处未加固面，公开记在这里。**
2. **判据文档本身是一种引导。** 新判据组三人读的是同一份文件，因此他们的一致率里
   有一部分**必然**来自「读了同一份文件」而不是「判据把边界划清了」。
   这正是对抗复核第 (b) 条要打的。设计上的对策是 **能红那一列做安慰剂** ——
   判据对它只字未提，两组都答；如果新判据组连它也更一致，多出来的一致是趋同压力。
   对策不完美：判据的 D0 检查确实提到「E 有没有拒绝路径」，与能红耦合，
   所以安慰剂列会有一点真实的溢出，**这一点是承认的，不是辩掉的**。
3. **判定员是同一个模型的六个实例。** 它们相互独立（不通信、不共享上下文），
   但不是六个人。跨模型的判定员间信度，本轮没有测，也不假装测了。

## 4. 一处 V15 的破口在这轮仍然存在

判定树里保留了 `monitor/runs/`、`arc-recon/runs/`、`papers/` 等 run 目录。
它们不含本实验室的判定，但含**大量本仓库自我评价的散文**。
一个判定员如果去读 `monitor/runs/…/RUN_STATE.md`，会读到别人对同一批文件的看法 ——
只是那些看法不是负控普查的看法。这不是答案泄漏，是**背景先验污染**，
量级不明，本轮没有测。
